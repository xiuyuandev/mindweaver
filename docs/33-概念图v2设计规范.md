## 0. 一句话

把概念图从「思维导图的另一种布局」升格成**一等公民**：独立的数据形状、独立的主题、
独立的工具栏与属性面板，交互对标 CmapTools —— 在概念图里画图，不该需要先想清楚
「这在思维导图模型里是哪一种节点」。

## 1. 范围

**做**：
1. 三个实证 bug（§2）
2. 概念图专属数据形状（§3）
3. 概念图专属主题（§4）
4. 概念图专属悬浮工具栏（§5）
5. 概念图专属检查器/属性面板（§6）

**不做**（本轮）：
- 不引入 CmapTools 的「资源库 / 图层 / 公式」
- 不做在线协作、不改 `.zmind` 的容器格式（ZIP + JSON）本身
- 不动思维导图的任何行为（包括它自己的工具栏与检查器）

## 2. 三个实证 bug（本轮先修，各有判据）

### B1 · 概念之间不能建立联系

**现状**（`docs/30` §5.4.2）：入口有 5 条——拖锚点到已有概念、拖锚点到空白、
`Ctrl+L`/右键「连接」（选 2 颗直连 / 选 1 颗进连线态）、右键「新建概念并连线」、
大纲 `Tab`。模型层 `AddRelationship` 对概念图**允许多条平行命题**、只拒自环
（`mw-core/src/document.rs:1478-1505`）。

**用户实测「连不上」的两条真实路径**：

| # | 路径 | 为什么连不上 | 判据 |
| --- | --- | --- | --- |
| B1a | 建完线立刻取消/失焦 | `finish_new_link` 立起空短语框，`blank_new = true`；**短语留空就把整条线撤掉**（`docs/30` §5.9「未填不给连线落盘」）。用户感觉「连了又没了」 | 建线后**不写短语就留着**：线落地、短语显示为「未命名」占位，事后可补；只有 `Esc` 显式取消才撤 |
| B1b | 拖锚点命中太窄 | 锚点是概念盒边缘上的小点，`anchors_win_over_the_node` 只保证「命中锚点时锚点优先」，没保证**够得着** | 锚点热区 ≥ 12 css px（现有 `LINK_SNAP_CSS=12` 同档）；悬停概念时才出锚点，露出即可拖 |

**验收**：
- `blank_phrase_allows_the_line_to_stay`（单测）：`AddRelationship{label:None}` 后
  线在、短语显示占位；`Esc` 才撤。
- `anchor_hit_area_is_at_least_12_css_px`（单测）：锚点命中盒 ≥ 12 css px。
- 金样 `cm-link-create-nophrase`：建线后不写短语，线与两颗概念都在。

### B2 · 连接短语的文字编辑漂移

**根因**（`scene.rs:1875-1891` + `concept_layout.rs:57-105` + `canvas_methods_3.rs:1027-1034`）：

1. 短语位置 = 曲线中点 + 切线偏移，偏移由**每帧实测的短语字宽**算
   （`proposition_label_offsets(label_widths, tangent)`）。字一变，整条带重排——
   **改一条短语，同组的其它短语跟着挪**。
2. ≥3 车道时间距按「投影半宽」累加，字宽直接进公式（`concept_layout.rs:63-84`）。
3. 编辑框 rect 在打开那一刻 `world_to_screen(label_at)` 一次性算死，
   **编辑中缩放/平移不跟随**。
4. 编辑框字体（`LIST_META`）≠ 渲染字体（13px），提交后重测宽度 → 跳一下。

**修法**：
- **R1（core）**：车道偏移改成**只由车道序号 + 切线方向决定**，短语字宽只影响
  胶囊自身的左右外扩，不影响中心。字宽不再进间距公式 → 打字时短语**不挪**。
  间距下限由 [`PROPOSITION_LABEL_CLEARANCE`] 与**组内最宽那条**的投影半宽决定
  （一次重排只在「最宽那条变了」时发生，且改的是自己，肉眼无感）。
- **R2（shell）**：编辑框每帧跟着 `world_to_screen(label_at)` 走，缩放/平移都跟随。
- **R3（shell）**：编辑框字体与渲染字体同源（13px）。

**验收**：
- `lane_offsets_do_not_move_when_one_label_is_retyped`（单测，R1）：只改一条短语的
  字宽，其余车道偏移逐位不变。
- `edit_box_follows_pan_and_zoom`（金样，R2）：编辑中平移/缩放，框与短语重合。

### B3 · 概念能叠在同一位置

**根因**：落点/拖放**不做避让**，只在重叠时闪 0.25s 红框（`canvas.rs:1387-1389`）。
`concept_layout::arrange` 会分开，但那是手动触发的。

**修法**：拖放/新建落点做**最小位移避让**（`concept_layout::resolve_overlap`）：
以落点为中心向外找最小位移，让新盒与既有的每个概念盒都不相交（留
`CONCEPT_MIN_GAP` 净空）。重叠已是既成事实时（粘贴、导入），只在「整理布局」时
才动它们——**不动用户已经摆好的东西**。

**方向键微调不避让**（2026-11-02 判定）：那是一次 1px / 8px 的**精确移动**，
加避让会变成「按一下跳一下」，手感立刻坏掉。重叠反馈靠既有的红边闪一下。

**验收**：
- `dropping_on_an_occupied_spot_slides_to_the_nearest_free_one`（单测）。
- `resolve_overlap_never_moves_the_fixed_boxes`（单测）：已有盒一个像素不动。
- `resolve_overlap_is_deterministic`（单测）：同输入同输出。

## 3. 概念图专属数据形状

**现状**（`docs/32` 已实现）：概念 = `Node{parent_id:None, pos, pinned}`，
命题 = 源节点的 `relationships[]`，靠 `id` 区分；文档类型 = `meta.layout.kind`
字符串 `"conceptMap"`。`.zmind` 不升版本、不新增必填字段。

**用户判断「数据存储方式不应该不一样」——方向是对的，但**：真正的问题不是「要不要
分开存」，而是**概念图在树模型里是硬塞进去的**：概念要靠 `parent_id=None` 这种
「不是什么」来定义，命题挂在节点上而不是图上，检查器/大纲/导出都要先判断「是不是
概念图」再分岔。这就是处处分岔的根源。

**v2 方向**（在 `.zmind` 里新增**可选**的顶层 `conceptMap` 块，缺省回落到现有形状，
**不升 `FORMAT_VERSION`**）：

```jsonc
{
  "meta": { "layout": { "kind": "conceptMap" } },
  "conceptMap": {              // 可选；缺省时读旧形状（向下兼容）
    "concepts": [ { "id", "text", "x", "y", "pinned", "style" } ],
    "propositions": [ { "id", "from", "to", "label", "color", "head", "dashed", "width", "note" } ],
    "focusQuestion": "...",
    "groups": [ { "id", "name", "members": [...] } ]
  }
}
```

- 命题**升到图层**，不再寄生在源节点的 `relationships[]` 里 → 检查器/导出/搜索
  不用再「从每个节点捞边」。
- 概念有自己的 `style`（形状/填色/描边/字号），与思维导图主题彻底解耦（§4）。
- 往返：旧文件读进来自动**转换**成新形状；保存时若 `conceptMap` 块存在就写新形状。
  转换必须**逐字节可逆**（同 D15 的口径：`split` / `compose` 双向测试）。

**验收**：
- `concept_map_roundtrips_through_the_v2_block`（mw-format）：旧形状 → 新形状 → 旧形状
  逐字节相同。
- `old_files_without_the_block_still_load`（mw-format）：缺块时行为不变。

## 4. 概念图专属主题

**现状**：共用思维导图主题，末尾 `apply_concept_defaults` 叠一层默认（椭圆、面板底、
14/20）。概念一改颜色就跟节点分支色混在一起。

**v2**：概念图有自己的主题族（4 套，与思维导图主题**不同名、不同色板**）：

| 主题 | 语义 | 概念盒 | 关系线 | 命题 |
| --- | --- | --- | --- | --- |
| `cm-paper` | 白纸（默认） | 椭圆，白底 1px 灰描边 | 1px `#9AA0A6` | 13px，胶囊白底 |
| `cm-slate` | 深色 | 圆角矩形，`#2B2F36` 底 | 1.5px `#6B7280` | 浅字，胶囊 `#2B2F36` |
| `cm-mint` | 柔和 | 椭圆，`#EAF6F0` 底，`#3E8E6E` 描边 | 1.5px `#3E8E6E` | `#2A6B52` |
| `cm-clay` | 暖色 | 圆角矩形，`#F7EFE8` 底，`#B0714E` 描边 | 1.5px `#B0714E` | `#8A5537` |

- 色板、形状、字号**全在概念图主题里定义**，不读思维导图主题的任何常量。
- 主题切换只改视觉，不进 `.zmind`（与现主题同口径）。
- 命题短语的胶囊、箭头、虚线都在概念图主题里给值。

**验收**：
- `concept_themes_do_not_share_tokens_with_mindmap_themes`（单测）：两套主题的
  色板交集为空。
- 金样 `cm-theme-paper` / `cm-theme-clay` 各一张。

## 5. 概念图专属悬浮工具栏

**现状**：无专属工具条（`docs/30` §5.9 明令禁止第二套工具条）。但用户要的是
**概念图这一层**的工具，跟思维导图那条不是一回事——这条 §5.9 禁的是「同一张画布
两条工具条」，不是禁「概念图有自己的工具」。

**v2**：概念图里出现一条**贴着画布左上的悬浮工具条**（与思维导图的工具条**互斥**：
画布是概念图时只显示概念图这条）。6 个动作，与 CmapTools 的常用工具对齐：

| 图标 | 动作 | 快捷键 | 落什么命令 |
| --- | --- | --- | --- |
| 概念 | 新建概念 | `Tab` | `AddLinkedConcept`（不带边） |
| 连线 | 连接两个概念 | `Ctrl+L` | `AddRelationship` |
| 文字 | 改命题短语 | `F2` | `SetRelationshipLabel` |
| 整理 | 整理布局 | `Ctrl+Shift+L` | `ArrangeConceptMap` |
| 钉住 | 钉住位置 | `Ctrl+P` | `SetConceptPinned` |
| 聚焦 | 聚焦问题 | `Ctrl+Q` | `SetFocusQuestion` |

- 28px 高、圆角 8、`POPOVER` 投影（与现有 `ui_kit::menu_frame` 同档）。
- 悬停 120ms 出提示（含快捷键）；禁用态（没选中概念时的「连接」）灰显但仍可点，点了给提示。

**验收**：
- 金样 `cm-toolbar`（默认态）、`cm-toolbar-disabled`（没选中概念，「连接」灰显）。
- `toolbar_layout_is_28px_with_eight_radius`（单测，几何）。

## 6. 概念图专属检查器 / 属性面板

**现状**：检查器是思维导图那套，概念图靠「概念排布」与「命题」两组塞进去
（CM-17 / CM-19）。

**v2**：概念图里检查器整块换成**专属面板**，三段：

1. **概念**（选中 1 颗）：文字、形状（椭圆/圆角矩形/矩形）、填色、描边、
   文字色、字号、**钉住位置**、坐标（只读）、所属分组。
2. **命题**（选中 1 条）：短语、箭头（四档）、颜色、线宽、虚线、备注、
   「源 → 目标」（可点跳转到两端概念）。
3. **图**（没选中）：聚焦问题、主题、整理布局、分组管理、概念/命题计数。

- 面板宽 288（同现有检查器），分组默认展开，改完立刻生效（500ms 合并撤销，同 SE-08）。
- 与思维导图检查器**不共用分组键**（`concept/layout` 之类只在概念图里出现）。

**验收**：
- 金样 `cm-inspector-v2` / `cm-inspector-v2-prop` / `cm-inspector-v2-empty`。
- `concept_inspector_groups_are_concept_only`（单测）：概念图面板不出现
  「含子树」这类树语义分组。

## 8. 被本文件取代的条目

| 原文 | 原口径 | 本文件 |
| --- | --- | --- |
| `docs/30` §5.9「禁止引入第二套工具条」 | 同一画布不许两条工具条 | 概念图与思维导图**各自只有一条**，互斥显示 |
| `docs/30` §5.9「未填不给连线落盘」 | 短语留空就把线撤掉 | **B1a**：线先落，短语留「未命名」占位，Esc 才撤 |
| `docs/32`「命题挂在源节点 `relationships[]`」 | 概念 = `Node`、命题 = 节点字段 | **§3**：`conceptMap` 可选块，命题升到图层（向下兼容） |
| C21「三车道以上按每条自己的字宽分别排」 | `proposition_label_offsets` 逐条累加投影半宽 | **B2 R1**：等距对称带，步长只认**组内最宽那条**；改一条短语不再挪动同组其它短语。C21 的不重叠验收仍然成立（净空 ≥ 24），被换掉的只是「按条排」那套排法 |

其余 `docs/30` §5 与 `docs/32` 仍然有效。
