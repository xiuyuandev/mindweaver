# 26 · X100 完成定义与验收规范

> 适用：X01–X100 的每一轮，以及 Stage B2 的 CER-01–CER-34。本文替代“有按钮就算完成”“测试绿就算完成”“截图存在就算完成”。
> 内容表面的专用判词见 §4.1；执行口径与四道人工门见 [`29-内容体验重构工作包.md`](29-内容体验重构工作包.md)。

## 1. 完成状态

每一项能力只能处于以下状态：

| 状态 | 条件 |
| --- | --- |
| 未开始 | 没有实现或没有有效证据 |
| 进行中 | 有实现但仍有明确缺口；不得写成完成 |
| 已实现 | 主流程可达，仍有视觉、边界或证据缺口 |
| 已验证 | 行为、视觉、回归、工程四类证据齐全并通过阶段门 |
| 阻塞 | 存在 P0/P1 问题；必须写明复现和恢复路径 |
| 延后 | 明确不在当前范围；必须写入差距矩阵 |

“已验证”是唯一可以勾选阶段任务的完成状态。一个轮次可以因为依赖未满足而进入阻塞，
但不得用“模型失败”“等确认”代替证据说明。

## 2. 四类证据

### 行为证据

- 纯逻辑使用单元测试、属性测试或命令往返测试。
- 真实交互使用 `MW_GOLDEN_INPUT`，输入和最终截图必须来自同一构建。
- 打开 `MW_TRACE` 后，trace 必须记录脚本开始、关键动作和脚本完成。
- 悬停、拖拽、菜单键盘、IME、滚动和跨 DPI 不允许只靠“代码看起来正确”。

### 视觉证据

- 每个有界面的状态必须绑定一张 Xmind 参考图和一张本项目图。
- 两图记录窗口逻辑尺寸、DPI、主题、缩放和参考版本。
- Xmind 专有资产不进入 golden；比较重点是层级、密度、几何、交互状态和可读性。
- 静态 golden 只证明稳定，不证明好看；必须同时给出人工视觉判词。
- 动态状态使用脚本停在稳定帧后截图，不允许截到中间动画。

### 回归证据

- 相关 golden 至少双跑，容差和目标必须明确。
- 有文档修改的轮次必须验证一次撤销和重做。
- 有选择/焦点变化的轮次必须验证键盘路径和焦点归属。
- 有格式变化的轮次必须验证旧文件读取、新文件保存和往返。

### 工程证据

- `cargo fmt --all -- --check`。
- 相关测试与阶段末全量串行测试。
- `cargo clippy -p ... --all-targets`，新增告警必须为 0。
- release 构建成功；涉及性能时记录二进制时间、大小和样本条件。

## 3. 每轮证据包

目录固定为 `shots/x100/<round-id>/`，例如 `shots/x100/X07/`：

```text
shots/x100/X07/
  report.md
  manifest.json
  reference/            # 本轮参考；没有新增时可为空并在 manifest 说明
  actual/               # 本轮实际截图
  traces/               # MW_TRACE、命令日志、性能输出
  golden/               # 基线或双跑结果摘要
```

`manifest.json` 至少包含：

```json
{
  "round": "X07",
  "status": "verified",
  "referenceVersion": "26.5.1107.202609082009",
  "date": "2026-10-22",
  "build": { "commit": null, "binarySha256": null },
  "scenarios": [
    {
      "id": "hover-hold",
      "reference": [],
      "actual": [],
      "trace": [],
      "result": "pass",
      "notes": ""
    }
  ],
  "tests": [],
  "knownGaps": []
}
```

没有 git 提交时 `commit` 写 `null`，二进制哈希和源码时间必须存在。

**Stage B2 例外**：内容体验重构的工作包目录为 `shots/x100/CER-XX/`，字段与上面相同，另需 `before/`、`after/`、`scripts/`，以及 `report.md` 里的人工判词小节。完整模板见 [`29-内容体验重构工作包.md`](29-内容体验重构工作包.md) §10。

## 4. 视觉判定

X100 不要求复制品牌，但对核心界面采用以下可测门槛：

- 关键控件的逻辑尺寸、位置和内距与参考值偏差不超过 2 logical px。
- 面板宽度变化时，固定的控件尺寸不随 DPI 缩放变成不可见或难以点击。
- 100%–200% DPI 下文字没有裁切、重叠、糊成一片或命中区错位。
- 正文对比度至少 4.5:1；辅助文字和图形门槛按 WCAG 对应级别检查。
- 同一交互状态只能有一套视觉语义：主选、次选、焦点、悬停、编辑和非法拖放不能互相冒充。
- 菜单、检查器、搜索和节点工具条同一时刻只有一个指针/键盘主人。

参考值必须写入场景说明；没有参考值时不能宣称“像 Xmind”，只能记录为设计判断。

### 4.1 内容表面附加判词（Stage B2 起）

全屏大纲、卡片笔记页、卡片库三类内容表面，除 §4 的通用门槛外，还必须满足 [`28-内容体验重构规范.md`](28-内容体验重构规范.md) §9 的八项人工判词：

1. **10 秒测试**：不点任何按钮，只读出结构/正文/库的分区。
2. **无盒测试**：选中、编辑、标签、行分组不再靠描边框表达。
3. **颜色测试**：强调色不参与正文大面积填充；标签不着色成墙。
4. **宽度测试**：28 规定的版心（大纲 800/760、卡片 720/640、库预览 680/600）在 1366 与 2560 双档成立。
5. **层级测试**：字号/留白/位置三者至少两项表达层级，不靠装饰。
6. **5 分钟任务**：新建→编辑→加层级→搜索→回到原处全程键盘可达。
7. **模板测试**：同一版式套四主题不塌、不裁切、不失去对比度。
8. **中文/IME 测试**：行内编辑、候选窗跟随、禁则换行、拼音检索通过。

判定口径：

- 机器门（测试 + golden 双跑 + clippy + fmt）通过只算 `已实现` 的必要条件。
- 人工判词逐项写 `pass / fail / not-run`；存在 `fail` 或 `not-run` 时该工作包不得标 `已验证`。
- 28 的视觉规格与本文冲突时，内容表面以 28 为准；外壳与画布仍以 06/16 为准。

## 5. 行为判定

- 一次用户动作只能产生一次可见命令；批量操作只形成一条撤销记录。
- 新增/删除/移动后，选择、焦点、滚动和相机至少保持一项可预测锚点。
- 快捷键在 IME 组合态不得抢占确认键；编辑态与搜索框的键路由必须明确。
- 所有可鼠标完成的节点编辑必须有一条键盘路径；所有关键菜单必须有 Esc/方向键/Enter。
- 取消拖拽、关闭菜单、退出编辑和撤销后不得留下悬空状态。

## 6. 固定回归矩阵

至少覆盖：

| 维度 | 必测值 |
| --- | --- |
| 窗口 | 1080×720、1440×900、1620×1080；640×460 窄窗 |
| DPI | 1.00、1.25、1.50、2.00 |
| 主题 | snow、ink、mist、sand |
| 文档 | tiny-cn、complex-style、perf-20k、坏文件、旧格式 |
| 输入 | 英语键盘、微软拼音、复制粘贴文本、IME 组合 |
| 状态 | 默认、悬停、单选、多选、编辑、拖拽、菜单、搜索、空、错误 |

阶段门可以按风险和轮次缩小矩阵，但不能永久跳过 P0 状态。

## 7. 阻塞与重试

每轮最多对同一命令或构建问题做 3 次有变化的重试；每次重试必须改变操作、补充日志或缩小范围。

连续失败后：

1. 把命令、退出码、关键日志和已尝试方案写入 `report.md`。
2. 判断是否可以选择不依赖该问题的下一项。
3. 可以绕行时继续推进，并保留阻塞状态。
4. 不可绕行时结束本轮，不得伪造通过或在原地空转。

## 8. 阶段门

每 10 轮执行一次人工验收。交付内容必须包括：

- 10 轮状态表与证据包完整性检查。
- 全量测试、fmt、clippy、release 和 golden 摘要。
- 本轮相对 Xmind 的三项最大改善与三项最大残余差距。
- P0/P1 清单；存在未解释 P0 时不得进入下一阶段。
- 用户确认后的下一阶段边界；未确认时只能修复当前阶段，不扩面。

**Stage B2 门（G-B2-1…4）**按 [`29`](29-内容体验重构工作包.md) §4 执行，额外要求：

- 每门覆盖对应批次全部工作包，逐包给出 `未开始/进行中/已实现/已验证/阻塞/延后`。
- 每门至少包含一次真实键盘脚本回放和一次中文/IME 复核。
- 视觉证据必须同轮同构建，记录旧基线 SHA-256、漂移量、包围盒与最大通道差；未受影响基线必须逐字节不变。
- 人工判词未签时，阶段门结论只能是 `机器门 PASS; 人工门未通过`，不得进入下一批。
- X20 人工门失败（2026-10-25）是 B2 立项依据；Stage C 在 B2 全部门通过前保持冻结。
