## 2026-11-01 · M32 · 折叠圆点双击「展开到下一级」（打磨轮 66）

**触发**：账本 §3 第 13 条——`docs/02` §3 的 P2 功能「展开层级」在代码里只有全展开/全折叠，
双击圆点与单击同义。风险小、入口唯一，一轮做完。开工现场核对发现纯函数与判定逻辑已在
上一段会话落地（`mw-core/src/drill.rs` 7 条、`mw-ui/src/drill_click.rs` 6 条、壳层
`toggle_drill` 接线、`mm-toggle-drill` / `-deep` 两场已注册且基线已拍），缺的是门、证据与账。

### 改了什么

1. **语义**：折叠节点双击 = 展开自己 + 只露一层（其直接子级中「有孩子且已折叠」的那几个
   重新折叠回去）；已展开节点双击 = 只展开直接子级里有孩子的、叶子不写 `collapsed`。
   两次双击 = 两条撤销。
2. **双击判定**（`mw-ui`，纯逻辑）：同一节点 + `0 ≤ dt ≤ 0.5s` + 落点 ≤ 4 css px +
   两次单击之间没有新的撤销深度；任何其他命中（节点、连线、空白）或提交动作清空记忆。
   时间取 `ui.input(|i| i.time)`（egui 帧计数虚拟时钟），不用 `Instant`，金样按帧确定。
3. **单击让位**：判定发生在 `toggle` 落地之后，第一击照常进撤销栈；壳层用
   `undo_depth` 相等做安全阀， depth 变了就不钻，宁可退回单击语义。
4. **本轮代码**：无新增功能改动，只补报告 §9 收口、`manifest.json`、两份 gate summary、
   `docs/02` §3 行、`docs/06` 折叠圆点行、账本 M32 行、`docs/STATUS.md`、`AGENTS.md`。

## 2026-11-01 · M9b · 整图折叠与聚焦视图下的圆点（打磨轮 67）

**触发**：账本 §3 第 16 项——M9 的四张基线拍的都是默认展开态的**单颗**圆点，
`Ctrl+/` 整图折叠与 `Alt+Enter` 聚焦这两种整体状态下的圆点集合从没核对过。纯证据轮。

### 查到了什么

1. **画面结论**：圆点只画在**有父级且有下级**的节点上。整图折叠后场景剩 5 个节点，
   圆点恰好 3 颗（纯 Rust 原生 / 中文排版 / 交互与性能），根与叶子都不画；
   聚焦「纯 Rust 原生」后 4 个节点、圆点恰好 1 颗（`winit + windows-rs`，屏幕 (536,551)），
   聚焦根不画、视图外无残点、面包屑不重叠。
2. **一处证据的 bug**：`canvas_methods_2.rs` 的 `scene_toggle` 轨迹清单只按 `has_children` 判，
   把**根主题**也列了进去，而绘制与命中（`mw-render/src/hit.rs` 的 `if let Some(parent) = n.parent…`）
   要求有父级。对着画面数圆点才发现：轨迹 4 条、画面 3 颗。这类不一致和第 37 轮
   「三张基线点在空白处」同一种病——**轨迹比画面可信的时候，就会把人带到错的地方**。
   改法：dump 判据对齐 `HitMap`，没有父级就 `continue`；改动在 `if crate::trace::is_enabled()` 块内，
   不设 `MW_TRACE` 时零路径，不可能动像素（这也是本轮唯一的代码改动）。
3. **第一版聚焦场景是无效证据**：只 `MW_FOCUS_DEMO=中文排版` 时三颗子级全是叶子，
   画面一颗圆点都没有——只能证「没有残点」，证不了「边界圆点还在」。
   改借第 66 轮的 `MW_DRILL_DEMO` 给「winit + windows-rs」挂一颗孙子，边界上才有可拍的点。
