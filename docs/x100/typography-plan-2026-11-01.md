# 全局字体与排版打磨 · 体检与实施方案（2026-11-01）

> 状态：**已执行（2026-11-01，TYPO-01）**。§1 是改造前审计快照，§3 的目标值已落地；
> 与本文不一致的实测值（`text_faint` = 0.68、标签改「色点 + `ch.text`」、未加 `fonts::medium/emph` 包装）
> 见 §8 执行记录，证据在 `shots/x100/TYPO-01/`。

## 0. 一句话结论

产品「看着累」不是某一页的字号问题，而是四件事叠在一起：

1. **小字当家**：外壳 73 处 11px、96 处 12px，卡片/大纲元信息大量 11–12px，100% DPI 下低于 Windows 原生 UI 的舒适下限；
2. **灰得看不清**：浅色 `faint` 实测只有 **2.10–2.37:1**，却被用来承载笔记库元信息、菜单快捷键、帮助注释、开始页提示；内容表面 `text_faint` 也只有 **3.56–3.70:1**；
3. **字重是假的**：egui 的 `RichText::strong()` **只改颜色、不改字重**（`widget_text.rs` 把 `strong` 只用于取 `strong_text_color`）；真正的中等字重靠检查器里 0.4px 双描边伪装，内容表面的 500 实际渲染成 400；
4. **三套字阶各写各的**：外壳 11/12/13/14/16/25，内容 11.5/12/12.5/13/13.5/14.5/16/18/22/28/30，开始页又有一张 9 档表，检查器再有 7 个本地字号。0.5px 的档位彼此打架，层级靠猜。

方案的核心不是「整体调大 1px」，而是：**统一成一套可断言的整数节奏 + 真字重 + 全部文字颜色过 AA + 按中文行高重排页面几何**。

### 1.3 字重假象

- `egui 0.37` 的 `RichText::strong()` 在 `widget_text.rs::into_text_and_format` 里把 `strong` 只交给 `get_text_color`，**字体仍是常规面**。仓库里有 19 处 `.strong()`，包括笔记库 21px 页标题、24px 预览标题、设置页 20/22px 数值、开始页小节标题——它们现在都只是「颜色深一点的常规字」。
- `content_kit::font_for` 把 500 映射到常规族；检查器 `inspector.rs` 用 `c + Vec2::new(0.4, 0.0)` 双描边伪造 500。
- 系统实际有 `seguisb.ttf`（Segoe UI Semibold，真正的 600 拉丁面）；中文只有雅黑 Regular / Bold 两面，没有 500/600 面。所以「中文 500」不可能真做出来，只能在 400 与 700 之间选一个并写清楚。

### 1.4 行高与字距

- 内容正文 16/28（1.75）是舒服的，但大纲单行 16/26、换行却重设为 24，行距和行框步进不一致（`outline.rs::row_text_job` 与 `row_layout_height`）。
- 外壳大量 12/16（1.33）、13/18（1.38）级别的行高，中文上下几乎贴住。
- 卡片页注释写「行高 26」，代码实际 `BODY_LINE = 28`，文档与实现已经漂移。
- 画布中英之间加了 `0.1em` 光学间隙（`text.rs::CJK_LATIN_GAP_EM`），egui 侧没有对应处理；混排时两套表面的中英节奏不同。
- 画布层深 28/20/15/14，摘要 13、命题短语 12；小字在 100% DPI 下偏细。

### 1.5 字体栈

- 画布 DirectWrite 候选顺序是 `Microsoft YaHei UI` → `Microsoft YaHei` → `Noto Sans SC` → `Segoe UI`（`mw-render/src/dwrite.rs::FONT_CANDIDATES`）；中英混排里拉丁和数字也走雅黑。
- egui 只注册雅黑常规 + 雅黑粗体（`mw-shell/src/fonts.rs`），没有 Segoe UI，也没有真正的 semibold 族。
- 结果：Windows 原生应用最擅长的「Segoe UI 拉丁 + 雅黑中文」组合没有用上；数字、英文、快捷键标签都显得偏宽偏软。

### 1.6 页面清单（都要过一遍）

开始页、画布（含节点/摘要/命题/关系线/聚焦问题带）、大纲、卡片页、笔记库、搜索条、检查器、菜单、命令面板、快捷键面板、帮助、对话框、设置、主题工作室、统计/诊断、标题栏、标签页、状态栏、导出（PNG/SVG/PDF 共用 Scene）。

## 2. 目标与非目标

### 目标

1. 所有页面文字在 100% DPI 下达到「Windows 原生可读密度」：正文 14，说明 12–13，不再有 11px 承载信息。
2. 所有正文/说明/元信息文字对比度 ≥ 4.5:1（四套主题、page/panel/panel2 三种底）。
3. 字重成为真层级：400 常规、500/600 用 Segoe UI Semibold（拉丁）+ 雅黑粗体（中文，标注偏差），删除 `.strong()` 与 0.4px 双描。
4. 三套字阶收敛为整数档；开始页、检查器、卡片页不再各写一张私有表。
5. 中文行高统一：正文 ≥1.7，说明 ≥1.45，标题 1.4–1.6；大纲换行与单行同一把尺子。
6. 页面几何随字号同步 +2–4px，窄窗（检查器 240、搜索 560、库 900、开始页 960）不裁字、不挤压。

### 非目标

- 不新增依赖/crate/构建工具；不打包新字体文件（只用系统字体，缺失时回退雅黑）。
- 不动 `.zmind`、`Node`、`NoteCard` 字段，不做迁移。
- 不换主题色板、不改图标/插画、不改动效节奏。
- 不做全站 `letter-spacing`；中文永不加字距，拉丁正文保持 0。
- 不引入 ClearType/子像素渲染改造；现有灰度字形图集与 wgpu 管线保持不变，除非证据表明必须动。
- 不改文案内容，只改排版与分隔符。

## 3. 设计决定

### D1 字体栈：Segoe UI 拉丁 + 雅黑中文

egui 侧（`crates/mw-shell/src/fonts.rs`）：

| 族名 | 组成 | 用途 |
| --- | --- | --- |
| `zhisi-segoe` | `segoeui.ttf` → `SegUIVar.ttf`（回退） | 拉丁常规 |
| `zhisi-segoe-semibold` | `seguisb.ttf` | 拉丁 500/600 真面 |
| `zhisi-yahei` | `msyh.ttc` index 1 | 中文常规 + 全局兜底 |
| `zhisi-yahei-bold` | `msyhbd.ttc` index 1 | 中文强调 |
| `Proportional` | `[zhisi-segoe, zhisi-yahei, Ubuntu-Light, NotoEmoji, emoji-icon]` | 400 正文 |
| `zhisi-semibold` | `[zhisi-segoe-semibold, zhisi-yahei, emoji…]` | 500：拉丁真 semibold，中文保持常规 |
| `zhisi-bold`（沿用常量名） | `[zhisi-segoe-semibold, zhisi-yahei-bold, emoji…]` | 600：拉丁 semibold，中文粗体 |

回退规则：Segoe 文件缺失时，两个强调族自动退化为「雅黑常规 / 雅黑粗体」，功能不受影响。字体仍用只读内存映射，新增两个小文件（约 1.5MB 量级）不改变 P13 的内存口径。

画布 DirectWrite（`crates/mw-render/src/dwrite.rs`）：

- `FONT_CANDIDATES` 改为 `["Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans SC"]`；
- 语言仍是 `zh-Hans`，中文由 DirectWrite 的脚本回退落到雅黑；`WEIGHT_BOLD = 600` 让拉丁拿到 Segoe Semibold、中文拿到雅黑 Bold；
- **决策门**：拍「中，English。123（测试）」混排样张，检查全角标点是否仍走中文字形、基线是否一致。若标点或行高明显劣化，退回「雅黑优先」，只保留 egui 侧的 Segoe 拉丁——这一步以截图为准，不凭感觉。

> 为什么 egui 敢把 Segoe 放第一：egui 按字形逐个回退，中文字形在 Segoe 里不存在，自然落到雅黑；拉丁/数字拿 Segoe。风险是部分全角标点可能被 Segoe 抢先命中，所以必须有 §5 的混排样张。

### D3 字重：删掉假 500 与 `.strong()`

- 新增 `fonts::regular(size)` / `fonts::medium(size)` / `fonts::emph(size)` 三个入口，分别返回 `Proportional` / `zhisi-semibold` / `zhisi-bold`。
- `content_kit::font_for`：400 → regular；500 → medium；600 → emph。
- 检查器删除 0.4px 双描；分组标题、对象标题等需要强调的走 `medium/emph`。
- 全仓 19 处 `.strong()` 全部替换为显式字体 + 显式颜色（保留原来想表达的「深色强调」）；`TextStyle::Heading` 也改成 `fonts::emph(HEADING)`。
- 加一条源码扫描测试：`crates/mw-shell/src` 下禁止 `.strong()` 与裸 `.size(1x.x)`，防止回潮；允许的极少数例外写进测试的 allowlist 并注明原因。
- 中文偏差写进 `fonts.rs` 头注释与 `docs/28`：**中文没有 500/600 面，500 用常规、600 用粗体**；拉丁按 400/600 两面真渲染。

> 一个必须改的产品口径：`LIST_TITLE`、`TAG` 从 500 改成 600。否则中文列表标题仍是常规，层级回到「全靠颜色」。

### D4 行高

- 内容正文 16/28 不动；标题按 §D2 表。
- 大纲：单行与换行都 26；`row_text_job` 的 `line_height` 从 24 改为 26；`row_layout_height` 的每多一行从 +24 改为 +26。
- 大纲根行 44 → **46**（16/26 标题 + 13/19 备注 = 45，再留 1）；有备注的普通行从 `row_h + 20` → `row_h + 22`。
- 外壳行高由控件几何显式负责：菜单/命令 30 → **32**，快捷键 28 → **30**，搜索行 44 → **46**，搜索页脚 28 → **30**；检查器 28/30/40/44 不动，因为 13/19 与 12/18 仍装得下。
- 卡片页顶部栏 40 → **44**（30/42 标题与 13/19 元信息需要呼吸）；库页头 48 不动。

### D5 字距与分隔符

- 中文：**0 字距**，永远不加 `letter-spacing`。
- 拉丁正文：0；只有全大写短标签（如 `Esc`、`Ctrl`）允许 +0.2px 级别的轻微 tracking，用 `TextFormat.extra_letter_spacing`，不进入全局样式。
- 画布中英光学间隙 `0.1em` 保留；egui 侧不强行模拟（逐字插入空格会破坏复制/选区），改用「统一分隔符」让视觉节奏一致：
  - `·` 两侧各一个普通空格；
  - 斜杠菜单里 `label    hint` 的多空格改为固定列宽（右对齐 hint），不靠空格对齐；
  - 键帽 `Ctrl` `Shift` `I` 用 4px 间距 + 键帽内边距，不靠空格串。
- 数字列（统计、计数、字数）用等宽数字；egui 不暴露 OpenType feature，改为右对齐 + 固定列宽，视觉上不跳。

#### 内容透明度

| 角色 | 旧 | 新 |
| --- | ---: | ---: |
| 亮色 `text_secondary` | 0.70 | **0.70** |
| 亮色 `text_faint` | 0.56 | **0.68**（原计划 0.65；雾青/暖砂的 page/panel 只有 4.28–4.45，抬到 0.68 才全员 ≥4.5） |
| 暗色 `text_secondary` | 0.72 | **0.72** |
| 暗色 `text_faint` | 0.58 | **0.68**（与亮色同步） |

亮色 faint 合成后最差 4.60:1；暗色必须不小于亮色，同时仍有「比 secondary 淡」的层级。

#### 标签文字

新增 `note_view::tag_ink(tag)`：取 `tag_color(tag)` 的 45–50% 明度，作为**文字色**；`tag_color` 只再用于圆点、浅底、描边。八支颜色在白/纸/面板底上均 ≥6:1（实测 6.12–9.30）。笔记库 chip 建议同时改成「6px 色点 + tag_ink 文字 + 8% 色底」，与 `docs/28` 的标签口径一致，并去掉「彩色字墙」。

#### 其余

- `Chrome::warn`、强调色、链接色不动；链接已经有自动压暗逻辑。
- 图标颜色不算文字，仍按 3:1 非文本门槛；但 `icon_off` 与 `faint` 的新值要一起复核。
