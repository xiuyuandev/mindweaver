# 12 · 历史注记：WebView 路线（已废弃）

> 状态：**历史，禁止按本文开发** · 收敛日期：2026-10-19
>
> 本文原先是一份 17KB 的「WebView 内重做画布」方案。2026-10-16 的 **ADR-010** 已否决该路线；2026-10-19 仓库清理时删除了正文，只保留这份结论，避免旧方案误导接手者。

---

## 为什么废弃

1. **「原生」是产品负责人的硬约束**：不允许 WebView / HTML / CSS / JS / Electron / Tauri 出现在产品运行路径里。
2. 旧版实测被评价为「没有任何原生体验」「像玩具」；问题不只是性能，而是壳层、字体、输入法、菜单、动效的整套质感。
3. 继续在 WebView 里修补，会把最关键的渲染/输入/壳层问题留在错误的抽象层上。

## 现在在哪

- 纯 Rust 原生栈：eframe/egui 0.37 + wgpu 30 + DirectWrite + windows-rs 0.62。
- 架构见 `04-系统架构与模块划分.md`，技术选型见 `03-技术选型与开发环境.md`。
- 旧 WebView 方案的诊断（D1–D10）与部分规格，已被吸收进 `13 §1`、`06` 的现行设计；**不要再去恢复旧代码或 `ui/` 目录**。

## 旧目录去哪了

- `ui/`（Svelte/TypeScript 原型）与 `_archive/mw-app`（Tauri 壳）已在 2026-10-19 清理中删除。
- 仓库不再包含 Node/前端工程；构建只需要 Rust。

## 唯一保留的历史结论

> WebView 不是性能原罪，但它无法满足本项目对「原生质感 + 中文输入 + 壳层一致性」的要求。路线已定，不再回头。
