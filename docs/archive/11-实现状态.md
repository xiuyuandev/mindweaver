### 2.3 H3 面板焦点恢复 + H4 色板键盘可达（本轮新增，诚实状态）

#### 2.3.1 H3：面板开合后焦点不丢

- 新增 `crates/mw-shell/src/panels/focus.rs`：
  - `PanelId`（Outline / Inspector）作为记忆分桶；
  - `FocusKey`（`base` + 可选 `tail`）给控件稳定身份，id 派生为 `Id::unique(("mw-focus", base, tail))`，与控件在 UI 树里的序号、换行位置无关；
  - `FocusMemory`：`note` 记录本帧真实存在的键，`set_open` 识别「由关到开」的那一帧，`restore` 把记忆里的键请求回来。
- **修掉一个真缺陷**：`restore` 原先在面板绘制之前调用，用上一帧的 `known` 判断目标是否存在；目标本帧已被文档变化删除时会请求一个不存在的 id，被 egui 的「死人开关」帧末清零。现在 `set_open` 仍在绘制前，`restore` 移到两个面板绘制之后，此时 `known` 已是本帧真实键。
- 锚点：大纲 `anchor()` 是虚拟键（故意不在 `known`，验证「不请求焦点也不回首项」）；检查器 `anchor()` = `FocusKey::indexed(ROW_BRANCH, 0)`（分支线首格）。
- 5 条单测：`reopening_a_panel_returns_focus_to_the_same_control`、`a_removed_control_falls_back_to_its_nearest_sibling`、`a_lost_target_never_resets_focus_to_the_first_item`、`a_missing_target_settles_on_the_panel_anchor`、`adding_other_controls_leaves_the_remembered_key_alone`。
- **未做**：`MW_TRACE` 真实输入轨迹、`shots/qa/` 截图。

#### 2.3.2 H4：三排色板键盘可达

- `inspector.rs` 的 `swatches` 改为 `SwatchRow { current, fallback, tip }` + `row: &FocusKey`；每格用 `FocusKey::indexed` + `ui.interact` + `Sense::click()`。
- 左右方向键在同排色点间移动焦点；Space/Enter 由 `Sense::click()` 自带语义激活，因此**不另开激活路径**——鼠标与键盘必然产出同一条 `Command`，撤销粒度不分叉。
- 自绘焦点环 `r = 9.8`，压在选中环外缘 9.0 之外，二者不会互相冒充。
- 三排色板（填充 / 分支线 / 文字）、形状、B/I、页签、布局均接入 `FocusKey`；`MW_TRACE` 有语义名。
- 2 条组件测试：`clicking_and_space_return_the_same_swatch`、`a_swatch_change_is_one_undo_away_from_the_original_color`。
- 外观：**golden `--tol 0` 0 差异**，基线未重拍（焦点环只在有焦点时绘制）。
- **未做**：真实键盘全链路探针（选节点 → 开检查器 → 进色板 → 改色 → Ctrl+Z）与截图。

## 4.5 v8 画布排版与锥形分支线（2026-10-19）

**依据**：本机 XMind 26.5.1107 的安装包里有官方主题库（`resources/app.asar → static/styles/themes/*.json`，44 套、7 种模板）。默认主题 `M01 Snowbrush` 的令牌是：

| 角色 | 令牌 |
| --- | --- |
| 中心主题 | `fo:font-size: 28pt`、`font-weight: 600`、`line-width: 4`、无描边 |
| 一级主题 | 20pt、500、`line-width: 3`、左对齐 |
| 二级及更深 | 14pt、500、`roundedRect` |
| 分支线 | `line-tapered: tapered`（锥形收细）；Colorful 等主题另有 `multi-line-colors` 六色序列 |

**做了什么**

1. `LEVEL_TYPE` 32/18/16/14 → **28/20/15/14**。XMind 的 pt 在画布上就是 CSS px（一级 20pt 的 CJK 墨迹高实测 16.7 CSS px ≈ 0.835 em）。
2. `PAD_X` 16→18、`PAD_Y` 10→9：一级卡片高 = 20×1.45 + 18 ≈ **47.0px**，对齐 XMind 实测 46.7px。
3. `NODE_RADIUS` 8→10（XMind 圆头卡片实测圆角 ≈10）。
4. 连线宽度 1.5/2.0 → **4.0（根）/ 3.0（一级）/ 2.0 / 1.5**，并新增 `SceneEdge.width_end`：每条边从父端收到子端，整条分支是一根由粗到细的笔画。
5. `push_curve` 按**弧长**插值线宽（不是按细分段序号）：曲线细分后段长不等，按序号会让锥度在弯道突然变陡。胶囊是圆头的，相邻段宽度差 <0.2px 时接缝不可见。
6. 重拍三份 golden 基线，漂移如实记录（壳层 3.284% / max 232，画布 2.268% / max 224），重拍后 `--tol 0` ×2 零差异。
7. 复原 `.cargo/config.toml`（`cargo shell` / `cargo golden` / `cargo core-test` 三个 README 里的别名在交接清理时被一并删掉，其中 golden 必须写成 `-- --golden`）。

**验收**：419 测试全绿（数量未变，字阶断言同步更新）、fmt 干净、clippy 新增 0。

**没有做**：四套自有主题的配色未动；阴影/发光仍未实现（合成器只有纯色圆角矩形与胶囊）；字重仍是 400/600 两档，没有 500。

### 4.5.1 雪枝主题（v8.1，2026-10-19）

XMind 默认主题 `M01 Snowbrush` 的核心不是颜色，而是**一级主题没有卡片**：`mainTopic` 既不写 `svg:fill` 也不写 `fo:color`，一级节点就是「一条 4→3 收细的彩线 + 一行同色字」，二级起才是 `#F8F7F7` 的浅灰圆角卡。我们原来的样式引擎假设每层都有卡片，所以先加了两项能力：

## 4.7 v9.1 拖到空白 = 分离为自由主题（2026-10-19）

**背景**：docs/06 §5 的终态一直写着「拖到空白分离为自由主题」，但 `commit_move` 在落点为空白时直接 `return false`（注释说属于后续里程碑）。顺带发现另一个洞：**自由主题无法用拖拽挪位置**——它没有父级，`MoveNode` 不适用，而空白落点又被丢弃了。

**做法**

1. 新增纯函数 `detach_commands(doc, dropped, dx, dy)`：树内节点发 `DetachNode`（保留落点），已是自由主题的发 `SetNodePos`，主根跳过；多于一个时合成 `Batch`（一次撤销全回去）。
2. 空白落点再过一道 `detach_on_blank_command(doc, dropped, pointed_inside, dx, dy)`：指针不在画布里（拖到面板上松手）就是放弃，不动结构。
3. `Moving` 新增 `inside` 字段，**在拖动过程中每帧记录**。原先在松手那一帧读 `pointer.latest_pos()` 判断，那一帧指针状态可能已被清掉，会误判成「不在画布里」。

**验证**

- `cargo test --workspace` **424 passed**（+1：`dropping_on_blank_detaches_trees_and_moves_floating_topics`，覆盖树内分离、自由主题挪位、主根不参与、指针在画布外放弃四种情况）。
- **真实输入 PASS（2026-10-19 傍晚，第二次尝试）**：换 `SendInput`（绝对坐标 `MOUSEEVENTF_MOVE | ABSOLUTE | VIRTUALDESK`）后一次通过。步骤：把 `#8fd0bc` 一级卡片从 (273,563) 拖到空白 (520,880)，松手，`Ctrl+S`，读 `content.json`：

  - 截图 `shots/qa/v9.1-drag-detach.png` 里落点处是带选中环的绿卡。

## 4.8 v9.2 主题库：经典（M03）与夜幕（M14）（2026-10-19）

**为什么是这两套**：它们各自带着一个引擎还没有的能力。

| 主题 | 官方令牌要点 | 带来的新能力 |
| --- | --- | --- |
| 经典 `M03 Classic II` | 中心白卡无描边、一级 `shape-class: underline` + `border-line-width 2`、二级起无填充、画布 `#F7F7FA`、`line-tapered: tapered`、六色 `multi-line-colors` | **下划线形状**（`Shape::Underline`） |

4. 「夜幕」的 `ui.accent` 用 `#5AA9E6`：M14 自己不定义强调色，而强调色必须是**有彩色**，否则「只借色相」的覆盖会退化成恒等（既有单测会直接抓出来）。

## 4.10 v10 Ctrl+拖拽复制（2026-10-19）

**缺口**：XMind 里按住 Ctrl 拖一个主题 = 复制；我们只有 `Ctrl+D`（原地复制同级），拖拽一律是移动。

**做法**

1. `Drag` / `Moving` 各加一个 `copy` 标志，**在按下那一刻**取 `modifiers.command`，拖动中松开 Ctrl 不改判（否则拖到一半松手会变成移动，用户完全无法预期）。
2. 新增纯函数 `copy_into_command(doc, roots, targets)`：对每个拖拽根 `copy_subtrees` → `remap_subtrees` → `InsertSubtree`；同一父级下多次插入时下标按已插入条数补偿（与 `duplicate_command` 同一条理由，否则多选复制会被反着摞起来）。
3. 落点来自既有的 `plan_moves`（`roots` 与 `moves` 一一对应、顺序相同），所以「插到哪个父级、第几位」和移动走的是同一套几何判断，不存在第二套落点逻辑。
4. 复制完成后选中的是**副本**（`remap_subtrees` 返回的新 id），方便接着摆放。

**验证**

- `cargo test --workspace` **428 passed**（+1：`ctrl_drag_copies_the_subtree_instead_of_moving_it`，覆盖原件留位、副本带子树、一次撤销回退）。
- 真实输入（SendInput，2026-10-19）：`copy-doc.zmind`（根 + 甲/乙，甲带子节点）→ 按住 Ctrl 把「甲分支」拖到「乙分支」上松手 → `Ctrl+S` 后 `content.json`：
  - 节点 4 → **6**；
  - `root.children` 仍是 `["a","b"]`（原件没被移走）；
  - `b.children` 多出 1 个副本，副本自己还带着 `甲的子节点`。
- 截图 `shots/qa/v10-ctrl-drag-copy.png`。
**v10.1 补上了 Ctrl+拖到空白**：`copy_floating_command` 用「`InsertSubtree` 挂到主根 → `DetachNode` 摘下并给坐标」两条现有命令包成一条 `Batch`，命令层不需要为「浮动子树」再开一条独立校验路径。

## 4.11 v11 导出范围：整张导图 / 选中子树（2026-10-19）

**缺口**：导出永远整棵主题树——想把「季度计划」里某一支单独导一张图给同事，只能先复制成新文档。

**做法**

1. `export::Scope { Whole, Selection }`，标签「整张导图 / 选中子树」；只对有画面的格式（PNG/SVG/PDF）出现，文本四种仍然导整份文档（对话框里也写明）。
2. `Canvas::export_scene(selection)`：以主选（没有主选就用根）为 `layout_root` 调一次 `build_scene`，布局与主题直接取 `doc.meta`，**不传行内编辑快照**——导出的永远是已提交的文档。
3. 导出对话框的「范围」行：没有选中时「选中子树」置灰并给 `on_disabled_hover_text`；选了但随后取消选中，`run_export` 里再兜一次（回退整图）。
4. PNG/PDF 走 `export_job`（场景整体传过去，包围盒由 `export::content_bounds` 按子树算）；SVG 走 `export_svg::render`，同一份场景。

**验证**

- `cargo test --workspace` **430 passed**（+1：范围的可见格式与标签）。
- 端到端（复用 `MW_EXPORT_BENCH` 探针，新增 `MW_EXPORT_SCOPE=selection`）：同一份 h4 文档、2× 比例——
  - 整张导图：`nodes=5` → **1566×308**、46,938 B；
  - 选中子树（根的第一个孩子）：`nodes=2` → **646×166**、11,358 B。
  尺寸与节点数同时缩小，说明不是把整图裁一刀，而是只排了那棵子树。

**v11.1 把范围铺到文本格式**：`subtree_document(doc, root)` 把子树摘成一份结构合法的独立文档（根清 `parent_id`、清 `pos`、剪掉指向子树外部的关系线），四个文本序列化器原样复用。对话框的「范围」行现在对全部七种格式可见。
