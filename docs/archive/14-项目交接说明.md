## 1. 不可协商的约束

这些是用户的原话级要求，**任何"先凑合"的方案都会被打回**：

1. **「原生」是硬约束**：产品里不能出现 WebView / HTML / CSS / JS / Electron / Tauri。`ui/` 目录只剩参考实现价值（见 §10），不得复活为运行路径。
2. **仅 Windows**：不做跨平台抽象。DWM/Mica/DirectWrite/输入法都按 Windows 语义做，`Win32` 细节要像原生应用而不是移植过来的。
3. **中文四痛点是验收项，不是优化项**（docs/07）：C1 IME 候选窗错位与丢字、C2 换行/禁则/标点、C3 文字发虚与字体回退、C4 拼音检索。前三条已在代码侧落地（C3 完成度最高），C1 的人工矩阵签字仍缺（§4）。
4. **质感对标 XMind / Win11 原生应用**，明确拒绝「玩具感」：铬件（选中环、线宽、折叠点）必须屏幕空间恒定；动效/吸附/幽灵这些"手感"项在 docs/12 的诊断表 D1–D10 里逐条立过案，做不到位等于没做。
5. **文档驱动**：先改 docs 再写代码。每个里程碑在 docs/13 §4.x 留一节「做了什么 + 实测数字 + 踩坑」，docs/11 记录诚实差距。**诚实优先**：没做的、只做了一半的，必须在文档里写明，不许用"基本完成"糊过去。
6. **投入**：用户全职，可投 3–6 个月，接受彻底重写；里程碑表在 docs/13 §6（M0–M5 ≈ 17–19 周）。

## 2. 架构与数据流

```
                    ┌─────────────────────────────────────────┐
   用户输入 ─────►  │ mw-shell  eframe/egui 壳（窗口·标题栏·画布面板）│
                    └───────┬─────────────────────┬───────────┘
                            │ Command             │ Camera/选中/编辑态
                    ┌───────▼───────┐     ┌───────▼───────────────────┐
                    │   mw-core     │     │ mw-ui  手势纯逻辑（新）    │
                    │ Document/命令 │     │ 选择·框选·落点·吸附        │
                    │ 布局·Scene    │     └───────┬───────────────────┘
                    │ 主题·排版·检索│             │ 计划（Move/DropTarget）
                    └───────┬───────┘     Command▼
                            │ Scene（**唯一真相源**）        ┌──────────────┐
                    ┌───────▼────────────────────────────┐ │ mw-io        │
                    │ mw-render 四层 wgpu 合成器          │ │ .zmind 读写  │
                    │ L0 点阵 / L1 边界+连线 / L2 节点 /  │ │ 导入导出     │
                    │ L3 覆盖层 + DirectWrite 字形图集    │ └──────────────┘
                    └────────────────────────────────────┘
```

**每帧固定顺序**（`crates/mw-shell/src/canvas.rs::show`，注释里也写了）：
输入 → 相机 → `sync_editing_layout`（编辑中的文本先重排）→ `build_scene` → `build_layers` → `TextEngine::paint`（填文字实例 + 图集增量 `AtlasRect`）→ `compositor.upload_atlas`（代次断档则 `take_atlas_desync` → `TextEngine::reset_atlas`）→ `render_texture` → 首次/尺寸变化时注册 egui 原生纹理 → `painter.image` → **最后**画 egui 编辑器覆盖层。

**三条架构不变量**（破坏它们会连带毁掉导出与验收）：

1. `Scene` 是几何与视觉的唯一真相源：`build_scene(doc, root, settings, theme, measure, editing)` 不依赖窗口、不依赖 DPI、不依赖 GPU（度量走 `TextMeasurer` trait，生产用 DirectWrite，测试用 `MonoMeasurer`）。
2. `Frame.viewport: Option<[f32;2]>` —— `Some` 裁剪到视口（交互），**`None` 即全图**（离屏渲染、golden、PNG/PDF 导出）。这就是「导出与画布同源」的架构保证；SVG 也读同一个 `Scene`，只换标记输出。M4 的导出器不许另起一套几何。
3. 视图层不含领域语义：`mw-render` 只接收 `Camera` + `selected/hovered/editing`，手势状态机与快捷键语义留在 `mw-shell`/`mw-ui`。

**v5-c 自定义强调色 + v5-d 键盘交接 + v5-e 窗口级剪贴板已落地（2026-10-19，来龙去脉见 [13 §4.38](13-纯Rust原生重构方案.md) / [13 §4.39](13-纯Rust原生重构方案.md) / [13 §4.40](13-纯Rust原生重构方案.md)）**：

配色主线做到「四套主题之外还能改颜色」：`DocMeta.theme_accent`（`#rrggbb`）**只借色相**——`Theme::with_accent` 把主题自己的强调色沿 OKLCH 刚体旋转，`accent`/`accent_soft`/`palette`/`palette_fill` 同角度，**彩度与感知明度逐令牌保住**。所以挑到 `#ffff00` 也不会得到一堆读不清的黄卡片（实测一级卡片墨色对比 7.89 → 8.44，方向还变好了）；按 HSL 转则实测从 9.57 漂到 6.46，这就是不用 HSL 的理由。出界时**沿半径二分回收彩度**而不是逐通道 `clamp`（后者把用户点的 60° 偷成 46.2°）。命令是 `Command::SetThemeAccent{Option<String>}`，`None` = 回主题预设；**切主题不清覆盖**；非法 hex 先拒后存且**不留撤销足迹**；容器键 `themeAccent` 有则写、无则整个键不出现。UI 在检查器：`ACCENT_HUES` 每 30° 一格共 12 格，**画的是「这套主题转到那个色相之后长成什么样」**，不是用户挑的原始颜色；拖动期间只存本地 `accent_draft`，`pointer.any_down()` 一停才发一条命令，否则一次拖动灌满撤销栈；选中环（半径 10、强调色）与焦点环（半径 11、中性 `ch.dim`）**分两层画**，egui 只给内置控件画焦点环，自绘圆盘这圈是自己画的。壳层 `sync_chrome` 的判据必须是**「主题 id + 生效强调色」这一对**——只比 id 的话换强调色不会重刷 `Chrome`，而 `install_visuals` 每帧调一次等于自造重排抖动。

v5-d 是 v5-c 的键盘可达逼出来的**一套看得见焦点的验收工具**，顺手抓出两个真缺陷。工具：`MW_TRACE=<文件>` 时 `trace::name` 让控件把语义名挂在自家 `Id` 上、`trace::observe` 在 `fn ui()` **最后一行**统一落盘「这一帧谁握着焦点」、`trace::event` 单独记状态转换；不设环境变量时零开销，与 `MW_STATS` 同纪律。缺陷一：**面板一开合，画布键盘全体失声**——`CentralPanel` 的 `Ui` 身份由「本帧注册了哪几个面板」决定，开 F8/F9 或多一个标签会让 auto-id 盐整体漂移，画布原来用 `allocate_exact_size` 就跟着漂，`Focus::end_pass` 的死人开关查不到这个 id 就清空焦点，于是 Tab 加子、方向键选节点全停，直到用户重点画布。修法是把身份钉死：`canvas_id()` 固定 `Id` + `canvas_area()` 用 `allocate_space` + `ui.interact(rect, canvas_id(), …)` 手工走完同一条路径（同样消耗一个盐，像素与布局等价）。缺陷二：**`Ctrl+Z` 在焦点不在画布时静默失灵**（撤销写在 `canvas.rs::shortcuts()` 里，整块被 `has_focus` 挡着；点一下工具条撤销按钮焦点就归那个按钮）。改法是换个唯一主人：`main.rs` 的 `window_shortcuts` 用 `consume_key` 接管、落到 `step_history(redo)`，**在画布绘制之前**跑（`consume_key` 会把事件摘掉所以不会双触发），**带 Shift 的和弦先查**（`consume_key` 的修饰键匹配放过多余 Shift），`canvas.is_editing()` 时不接、那一下归文本框。F6 交接的判据只用 `!self.wants_keys`（我们自己的模式位），**不看实时焦点**——状态栏那行指示必须和用户按下去发生的事同源。

v5-e 把同一个病根剩下的那一半收掉：五个剪贴板和弦也从 `canvas.rs::shortcuts()` 搬到窗口级（`main.rs:1479` `window_clipboard`）。结构上多了一个纯函数：`clipboard_chord(style_copy, style_paste, copy, cut, paste) -> Option<ClipboardChord>`（`canvas.rs:442`）只做「该执行哪条」，不碰 `Input`——因为**「一条都不该执行」时必须一个事件都没被摘走**。顺序是语义：带 Shift 的先判（`consume_key` 放过多余 Shift）、`Cut` 优先于 `Copy`（剪切本身就是复制+删除）。门则必须打在 `consume_key` **之前**：`canvas.input_blocked() || canvas.is_editing() || ctx.text_edit_focused()`，第三个一次覆盖搜索条、命令面板、检查器标题与备注所有 `TextEdit`（egui 0.37 不替文本框预过滤剪贴板键，而面板的输入框要到本帧后面才画）。撤销侧同一个结论提成 `history_is_ours`（`main.rs:1379`）给重做/撤销两个分支共用，不出现「撤销让位、重做不让」的裂缝。验收工具于是长出两件新东西：`panels/search.rs:215` 给输入框登记语义名 `search-input`（「键盘在框里」由应用报出，不从「文档没动」倒推），以及 `scripts/v5-clip.ps1` 的**硬件按键路由**——`SendMessage` 送不达修饰键（winit 读异步键盘状态），只能 `keybd_event` 真按，按之前用 `AttachThreadInput` 抢前台，开场两条路由各试一次定路线、结尾再复核一次，中途丢前台就整轮判词降级成 `INCONCLUSIVE`（退出码 3）。主要证据换成 `manifest.json` 的 `nodeCount` 差分，期望增量取自应用自己的 `clipboard_text()` 行数：`4→8`（粘贴）、`8→4→8`（剪切再贴回，同时钉死「一支和弦只执行一次」）、样式和弦全程不动。

**踩过的坑**：① `linear_to_srgb` 返回 0–1，写回 u8 漏乘 255，每个通道被舍成 0/1，浅绿卡片变近黑——**只看正向输出的测试完全看不出来**，它对任何输入都自洽地错，必须加往返单测且只测「会真的被转的色」；② `Response::has_focus()` = `ctx.input(|i| i.focused) && memory.has_focus(id)`，**要求窗口是 OS 前台**，验收机器的输入锁让焦点环永远不亮，看着像「Tab 走不动」。所以**判定与证据分家**：轨迹登记只看 `memory`，焦点环仍看 `has_focus`（真实用户永远在前台）；③ 像素差不能当焦点证据——状态栏那行整条是强调色画的，改配色它就重画，判「键盘有没有被抢」要看条带**墨迹覆盖**；④ 输入锁一松，一个 Windows 设置窗落进应用正中，伪造出四条产品 FAIL（35,852 px / 1,190,288 px / 墨迹 6365→5941 / 「色板抢走键盘」）。探针 `Shot` 现在先 `SetWindowPos(HWND_TOP|NOACTIVATE)` 抬 Z 序（抬序不需要前台权限），再按 90 px 网格采 216 点问 `WindowFromPoint`「这儿真是我的窗口吗」，**无标题根窗口跳过**（IME 候选窗一类自家助手窗），仍被盖住就退出码 **3 = INCONCLUSIVE**，不把桌面的动作算成产品的账；⑤ OKLab 参考矩阵是 f64 常数塞进 f32，触发满屏 `excessive precision`（core lib 43 条）。两段变换整体改 f64、进出口各转一次 → **43 → 11 条**，且**像素一个没动**（探针复跑 `card 166,193,119`、`ink 8.44:1` 逐字相同）。**遗留**：只有全局强调色、无逐节点配色，`levels` 色阶不随覆盖变；面板控件的自动 id 未钉；快捷键仍不可配置；v5-c 之后**内存未复测**，不许引用 P13 那组数字。（`Ctrl+C/X/V` 与 `Ctrl+Shift+C/V` 曾在这一行里挂着「仍在画布焦点门后」——**v5-e 已修并实测**，13 §4.40。）

**右键菜单已落地（2026-10-18，来龙去脉见 [13 §4.29](13-纯Rust原生重构方案.md)）**：

管线是「画布发请求、壳层组菜单、动作回画布」：`Canvas` 只产出 `ContextRequest { pos, target }`（右击未选中节点先置为唯一选中，组内右击保留整组），壳层 `build_context_menu` 读 `primary_collapsed` / `has_clipboard` / `can_collapse_selection` / `can_move_same_parent` 等状态决定禁用项，`run_context_action` 把意图落回 Canvas 方法；改文档仍全走 `Command`（多选折叠是一条 `Batch`）。菜单打开时 `set_input_blocked(true)`，`↑↓` 只走可执行行，`Esc`/其它键都能收起，点击卡片外关闭，贴底时整卡上翻。**踩过的坑**：① 结构动作（移入同一父级）会让布局重新居中，探针里缓存的节点坐标立刻失效——每次结构变化后必须**重扫调色板填充**再点；② 键盘行数按**可执行行**数，不是按条目下标（分隔线与禁用项不占步）：空白菜单从无高亮到「全部折叠」是 5 次 `↓`，数成 4 次会把 Enter 落在「全部展开」上；③ 探针里 `@($a / $s, $b / $s)` 会被 PowerShell 5.1 解析成「逗号并入除法右操作数」，报 `Cannot call method op_Division on System.Object[]`——先分别算好两个标量再返回（§9 教训 64/65）。**右键遗留**：整理布局、大纲行与标签页菜单未做；菜单无图标/二级子菜单；粘贴不解析系统剪贴板文本。

**结构动效已落地（2026-10-18，来龙去脉见 [13 §4.30](13-纯Rust原生重构方案.md)）**：

节点增删/折叠展开/布局切换不再硬切：`Scene` 的节点、连线、轴线、边界、概要、关系线全加 `alpha`，`mw_core::blend_scenes(from, to, t)` 在两帧场景之间插值——共同节点 `rect/text_x` 线性插值；新增节点从父盒中心淡入；被删节点向父盒收缩淡出并追加在目标节点之后（父/自由根按 id 重映射）；新连线从父侧端点生长；边界/概要/关系线按 id 插值；换布局时旧轴淡出、新轴淡入。壳层 `Motion` 用 `(0.20 + span/4000).clamp(0.20, 0.34)` 定时长、`ease_out_cubic` 缓动，布局切换 span 固定 600；连续命令时把**在飞 blend 帧**固化为新起点，避免位置回跳；编辑期、系统「减少动画」和 golden harness 都不起动画。渲染用 blend 帧，命中、选择、面板仍按目标场景算；编辑器覆盖层跟随插值盒，新节点滑出时文字不会先落终点。**踩过的坑**：① `blend_scenes` 若在 `t=0` 提前返回 `from`，删除/新增后选择与命中索引会错位——t=0 必须保留目标场景的 `ids/index`，只把几何换成起点；② 新增节点的**连线终点**也要跟着子节点走（从父端点长过去），只给 alpha 会让线先连到终点；③ 真实输入的动画窗口只有 0.20–0.34 s，`-early` 必须在按键后立即截，先 sleep 150ms 只剩尾帧；输入提交走「点空白让编辑器失焦」，不要按 Enter（中文 IME 组合期会吞掉）。**动效遗留**：无应用内开关、时长不按负载降级、动画期间没有专项帧耗时探针。

**演示模式已落地（2026-10-18，来龙去脉见 [13 §4.32](13-纯Rust原生重构方案.md)）**：

演示只做视图状态，不碰文档：`demo.rs` 克隆当前 `Scene` 与主题，把非路径节点 alpha 压到 0.16、装饰压到 0.10，只替换 `ui.canvas_bg`/`ui.bg` 为深色（不能整套换深色主题——场景样式已按原主题解析完）；壳层在演示期隐藏标题栏/标签条/状态栏/大纲/检查器/小地图/面包屑并 `set_input_blocked(true)`，只留底部控制条与演示键。**演示顺序必须用文档先序，不能用 `draw_order`**：后者是「深度 + y/x」的绘制序，思维导图左右分叉时会把视觉更高的右分支排到左分支前面，真实输入探针第 2 步就拍到了「项目乙」而不是「项目甲」——`Scene` 节点索引本身就是先序（折叠子树不下探、自由主题随后追加），所以直接升序即可，并加了 `preorder_follows_document_order_not_visual_y` 回归测试。相机 350ms：中心线性、缩放走几何（对数）插值，连按从当前插值相机续接；`Esc`/`F5` 退出精确恢复进入前相机，飞行中退出也不残留。**遗留**：没有自动播放、演讲者备注、多显示器演示窗口；演示状态不持久化；控制条不可拖动。

**M5 性能探针与打包已落地（2026-10-18，来龙去脉见 [13 §4.31](13-纯Rust原生重构方案.md)）**：

启动侧用 `MW_PERF_LOG` 写 `process_start → shell_new → doc_open_start → doc_open → first_ui → first_canvas`，`Perf` 的 `Instant` 在 `run_native` 之前创建，所以 P1/P3 是「进程内可见的最早时刻 → 首帧」，不是秒表。运行时用 `MW_STATS=1` 显示右上角卡片、`MW_STATS_LOG` 每 60 帧写一行 TSV；窗口是 240 帧滚动窗，帧间隔 >250ms 就整窗清掉（空闲时 egui 按需重绘，几百毫秒的间隔会把 FPS 拉成个位数，与 `FrameBudget` 同门槛）。`Canvas::perf_snapshot` 只在统计开启时统计与视口相交的节点。语料生成器扩成 `--nodes=N`（BFS 树、长文本/标签/图标/备注），**大文档必须用 `mindmap` 布局**：`logicRight` 在 5k 时退化成一列，只有 48% 可见，P5 的「80% 可见」前提直接不成立。探针 `scripts/m5-perf.ps1` 用 Win32 真实滚轮（+120/−120 交替）+ 中键拖拽，隔离 `APPDATA`，截完图读最后一条汇总并打印 PASS/FAIL；`-StartPage` 测 P2。内存用 `scripts/m5-memory.ps1` 按分钟采样。打包 `scripts/package-release.ps1` 产出 `dist/zhisi-<ver>-win64.zip` + SHA256，并断言 ≤30MB。

**实测**：5k 进程→首帧 325.8ms、打开→首帧 63.2ms、60fps、墙钟 p95 17.73ms、UI p95 1.78ms、4685/5000 可见；开始页 291.8ms；20k 打开→首帧 257.2ms；10k 冷开私有 340.1MB、五分钟稳态 335.2MB、开始页空应用 318–321MB ⇒ 攻关前 **P13 FAIL**；**A+B 那轮五分钟 299.6MB、空应用 276.6MB（擦线，随后由 C 收到 264.5MB / 284.4–289.6MB）**；ZIP 7.39MB、exe 20,073,984 B ⇒ **P14 PASS**（该 ZIP 产出于 M5；其后演示模式使 exe 变为 **20,251,136 B**，ZIP/SHA256 未重打包，仍远低于 30MB 预算）。核心层：5k P8 中位 8.4ms、P6 代理 p95 9.8ms、P9 撤销/重做 p95 9.0/8.0ms；**P10 后台自动保存**（10k 整份写盘 p95 27.4ms 在 `zmind-autosave` 线程；UI 线程只克隆 `Snapshot`，5k/10k/20k p95 2.7/4.7/9.2ms）；20k P12 冷查询 38.2–41.7ms、二次 11.7–14.3ms ⇒ **PASS**。**P11 后台导出**（`export_job.rs`）：5k 工作线程 70.9ms、提交→完成 107.6ms、UI 只克隆场景 0.94ms（20k 4.0ms）；但 5k/20k BFS 语料的极端长宽比触发 8192/32MP 护栏，2× 实按 0.057×/0.014× 输出，真实 2× 由 3 节点样例验证（910×300，PNG 38.8ms、PDF 30.7ms）。**M5 遗留**：P7 没有增量布局（只有全量重排代理）、P15 未测、P11 满幅 32MP 与导出期间逐帧卡顿未量；P10 的 UI 快照仍非零成本、自动保存只覆盖活动标签、未做整帧卡顿采样；**P13 攻关已判 PASS（A+B+C 全部 release 实测）**：空应用 318–321 → **264.5MB**，10k 五分钟 335.2 → **284.4–287.9MB / 289.4–289.6MB** 两次独立采样，最差余量 **10.4MB**、无上行台阶；省下来的主要是字体副本（≈34MB）与图集（GPU 3072² + 移除 CPU 镜像，≈16MB）；下一档备用清单是字体驻留策略、延迟创建适配器/渲染目标（不要先改预算）；当前只有便携 ZIP，没有安装器、文件关联、快捷方式与卸载项；仓库缺 LICENSE；低档机降级仍只关 L0 点阵。

## 9. 已付过学费的坑（不要再学一遍）

**egui 焦点与输入**

1. `Sense::click()`/`Sense::drag()`/`Sense::click_and_drag()` **可聚焦**，常量 `Sense::CLICK`/`Sense::DRAG` 不可聚焦。标题栏拖拽区、隐形热区必须用不可聚焦版本，否则给用户埋「按 Tab 焦点就消失」的隐形控件。
2. Tab 导航在控件 **allocation** 阶段就被解析掉，比本帧后面读键盘更早；画布要每帧 `set_focus_lock_filter(id, EventFilter{tab,escape,horizontal_arrows,vertical_arrows})` 才留得住这些键（`canvas.rs:156`）。
3. `Response::clicked()` 包含「焦点控件上按空格/回车」的无障碍激活（`FAKE_PRIMARY_CLICKED`）。画布必须用 `clicked_by(PointerButton::Primary)`，否则回车加同级节点会在同帧被当成点击画布，刚开的编辑器立刻被提交。
4. `Focus::begin_pass` 会在裸 Escape 时丢掉焦点——编辑器与画布之间的焦点交接要显式管（`refocus_canvas` 标志位）。

**golden / 验收 harness**

5. **harness 必须与「谁在前台」无关**。隐藏窗口的 `viewport().focused` 取决于截图那一刻的系统前台归属，标题栏文字 `dim` 在 1.0/0.55 之间跳，基线因此随机漂移（现象：1318 px 差异、包围盒正好框住标题文字）。已修：`self.harness.is_some()` 时强制 `focused = true`（`main.rs`）。
6. **`--golden` 的退出码会被管道吃掉**（`| tail` 返回的是管道状态）。判断漂移要看 stdout 文本，不是 shell 的 `$?`。
7. 渲染不确定性曾怀疑 wgpu，实际是摆位不可复现：`mw-core` 里凡从 `HashMap` 取值再决定布局/摆位的地方必须先按 id 排序（`scene.rs` 自由主题合并处有注释）。

**中文与字体**

8. egui **自身不带 CJK 字形**，标题栏/编辑器中文会成方框。`fonts.rs` 从系统装 `msyh.ttc`，**face index 必须是 1**（0 是占位），且要有 `BOLD` 变体，否则粗体节点回退到拉丁字形。
9. 近似度量（`MonoMeasurer`）会在内边距上骗人：只有 DirectWrite 真字宽跑出来的盒尺寸才可作为基线；`MonoMeasurer` 只用于无 GPU/无字体环境的单测。

**领域模型**

10. `Command::MoveNode { index }` 的口径是**以移动前的兄弟数组为参照**：同父重排时 `Document` 内部 `pre_len = len + 1`、`want = index.unwrap_or(pre_len).min(pre_len)`、`idx = want > old_pos ? want - 1 : want`；跨父时按目标长度钳制。自己先减一或先钳制会得到差一位的落点。`mw-ui::Tree::apply_move` 已逐条对齐并写了断言，改动时同步它。
11. `Scene` 的索引是 `compute_layout` 的 DFS 前序，因此按索引顺序遍历得到的兄弟**就是文档顺序**——这是 `Tree` 能当落点索引参照的前提，别在别处依赖索引等于其它顺序。

**遗留**

12. **clippy 存量 37 条**（2026-10-19 v4 后复测，按「文件:行:消息」去重）：`mw-core` lib 11 + `perf_scene` example 3；`mw-render` lib 7 + example 3 + `offscreen` test 4；`mw-shell` **5**（`command.rs` 3、`main.rs` 2；`canvas.rs` 已由 1 → **0**，清掉的是 `is_some`+`expect` 与 `clone_on_copy` 各一条）；`mw-probe` 2、`mw-io` 1、`mw-golden` 1；`mw-ui` 0。前几版交接记的 31/33/38 条是旧数；`glyph.rs` 里 274 那条是 287 的 help 锚点，不要当第二条数进来（行号会随文件改动漂移，认锚点不认行号）。v3/v4 三轮核心打磨新增代码 0 条。`_archive/mw-app` 里另有若干但不参与构建。属于纯机械清理，**没有排期**，顺手清可以，别在功能提交里夹带大规模重排。

**M2b-2 新增（2026-10-17，来龙去脉见 [13 §4.13](13-纯Rust原生重构方案.md)）**

13. **`drag_started()` / `drag_delta()` 都要等指针越过 `max_click_dist`（6px）**，`Sense::click_and_drag()` 不会在按下当帧告诉你「开始拖了」。想「按下即定手势」只能用 `button_pressed` + `press_origin`；想「第一个像素就跟手」必须自己结算增量——用 `drag_delta` 做平移会让画布永远落后指针 6px。
14. **真实输入探针的头号假故障是「窗口没被拉前台」**：`SetForegroundWindow` 会静默失败，于是 `CopyFromScreen` 截到的是压在织思上面的编辑器、点击也落在那个窗口上，现象是「代码完全没反应、截图与基线逐字节相同」。探针必须 `SetWindowPos(HWND_TOPMOST)` + `WScript.Shell.AppActivate` + **断言 `GetForegroundWindow() == hwnd`**，收尾 `HWND_NOTOPMOST`。
15. **`.ps1` 写中文必须存 UTF-8 with BOM**：Windows PowerShell 5.1 无 BOM 时按 ANSI 读，中文注释会把后面的引号吃掉，报「字符串缺少终止符」且位置指错行尾。老脚本全英文注释，所以这个坑到 M2b-2 才现形。
16. **`mouse_event` 的滚轮量在第 4 个参数（dwData）**，写成 `(WHEEL, 0, 120, 0, ...)` 会成功返回、什么也不发生——「编辑期锁缩放」的测试会因此**假通过**（两边都没动）。凡是「锁住了/没变」的结论，都要配一个「同等输入下它应该变」的对照组。
17. **`Home` 只重排布一次，窗口尺寸变了不会自己跟上**（`fitted` 是首帧一次性标志）。真实输入探针若按「初始布局」硬编码坐标，窗口一旦被 `ShowWindow(SW_RESTORE)` 改过尺寸、或者树形变了（拖一次就变），坐标立刻失效——第一版 M2b-3 探针就这样把「非法落点」测成了框选。修法：场景开始先按 `Home`，再截图对坐标。
18. **拖拽途中 `Escape` 要自己吃掉**：egui 会中止它的拖拽，但我们的 `drag`/`moving` 与快捷键是两套状态机——不 `consume_key` 掉，同一次 Esc 会「取消拖拽」+「清空选择」双杀。
19. **`any_released()` 不一定会到**：窗口失焦、鼠标被别的窗口接走时收不到 release，幽灵会永远停在画布上。收尾判定用 `released || !pointer.any_down()`。
20. **幽灵的盒子与文字是两条管线**：`instances.rs` 管矩形、`text.rs` 管字形。只做前者会得到「半透明空框在飘」，而原来那些字还亮在原地——两处必须共用同一个 `Ghost` 与同一对 alpha 常量（`GHOST_ALPHA` / `GHOST_ORIGIN_ALPHA`）。
21. **吸附是「同类线配对」**（左↔左、中↔中、右↔右），不是 any-to-any。「把 A 的左缘贴到 B 的右缘」**本来就不会吸**——第一版验收脚本恰好吃这个，差点把「没吸」当成实现错误去改代码。**先看口径，再设计用例。**
22. **`Camera::chrome(css, world_floor)` 的第二个参数是「最小世界单位」，不是「最小像素」**：给参考线写 `chrome(1.0, 1.0)` 会让 200% 缩放下线粗成 2px。正确的是 `0.3`（只在极小缩放时兜底）。单测里断言「200% 下世界线宽 = 0.5」才抓得住。
23. **锚点命中半径必须按屏幕 px 换算**：直接拿 7 当世界单位，0.5× 缩放下等于 3.5 屏幕 px，几乎点不中。视觉尺寸与命中范围都走 `css_to_world`。
24. **`IFileDialog::Show(None)` 会让对话框藏到主窗口后面**：没有 owner 就没有父子关系，而验收探针会把主窗口设成 TOPMOST——截图里一片干净，现象是「Ctrl+O 没反应」。必须传主窗口 HWND（`eframe::Frame` → `HasWindowHandle` → `RawWindowHandle::Win32`）。
25. **原生打开对话框上 Esc 不保证关得掉**：第一版探针按 Esc 后屏幕毫无变化，后面所有按键都进了那个对话框（三张截图逐字节相同）。验收脚本应当点「取消」按钮。
26. **加了未保存点会让 golden 漂**：`●`/`•` 是画在标题栏里的像素。所以 `Session::sample()` 必须把夹具文档标成「已保存」——基线不能依赖「这份文件新不新鲜」。
27. **窗口级快捷键要 `consume_key`**：`key_pressed` 只读不消费，同一帧画布的 `shortcuts` 还会再判断一次。文件类快捷键与画布快捷键必须分属两层、各消费各的。
28. **空闲时 egui 根本不跑帧**：自动保存第一版写成"每帧看一眼时钟"，编辑完等 4 秒磁盘上一个字节都没多——因为窗口静置时没有 `ui()` 调用。任何基于时间的后台动作都必须 `ctx.request_repaint_after(..)` 自己催帧。这条看着蠢，但它**编译通过、运行不报错、只是永远不触发**。
29. **并行测试别用毫秒当临时目录名**：`mw_core::now_ms()` 同一毫秒内会撞车，两个用例共用一个目录互相删文件，报「拒绝访问 (os error 5)」，看起来像保存功能坏了。用 `进程 id + 自增序号`。
30. **恢复点只认"比正本新"**：正常保存后要 `autosave::clear`，否则下次启动还弹"要恢复吗"，比丢数据更烦人。用户点了「忽略并删除」也要真删。

**M3-c-b 新增（2026-10-18，来龙去脉见 [13 §4.19](13-纯Rust原生重构方案.md)）**

31. **加选按下时绝不能窄化选择**：`Ctrl+click` 的 press 阶段若因为"节点不在组里"就把选择收成单选，release 的 additive 分支会把它 toggle 掉，结果是多选被清空。修法：additive 按下不动选择；真拖过阈值时再以光标下节点为准定幽灵。**单测测不出**——`Selection::click` 的语义是对的，错的是壳层在按下时多做了事。
32. **画在画布之后的浮层仍会先让画布收到 pointer**：egui 的绘制顺序不等于输入顺序。浮动卡片必须把矩形交给画布（`set_overlay`），在按下起点、`clicked_by(Primary)`、滚轮缩放三处都挡掉；否则小地图拖一下，底下画布的选择就被清了。
33. **面板提交表单后的同帧 Enter 会被画布快捷键吃走**：`Ctrl+Enter` 提交备注后 `request_focus` 回画布，同一帧的 Enter 又被解释成"加同级"。需要 `just_refocused` 一帧护栏，跳过画布 `shortcuts`。
34. **17×17 的按钮在 150% DPI 的真实输入下就是难命中**：小地图折叠键第一版只有 17×17 逻辑像素，探针点在 (785,544) 打偏，被下面的小地图当成拖拽，相机跑了。折叠键实际矩形是 (784..801, 546..563)，已用 (792,552) 验证；但按钮本身仍偏小，列在 13 §4.19 的 UX 缺口里。凡"点一下"的控件别低于 ~24×24。
35. **探针重启后坐标会变，窗口最小化时 EnumWindows 会给出假矩形**：检查器打开与否会改变画布宽度与 fit，同一节点的世界→屏幕坐标不同；窗口被最小化时可能报 (-21333,-21333, 158×26)，先 `ShowWindow(hwnd, 9)` 恢复再取 `ClientToScreen`。每个场景开头先截图确认布局，再使用坐标。

**M3-c-c 搜索条新增（2026-10-18，来龙去脉见 [13 §4.21](13-纯Rust原生重构方案.md)）**

36. **本机开着中文输入法时，逐键注入会进 IME 组合态**：`keybd_event` 发字母，输入法把它当成拼音串开口候选窗——候选窗既盖住搜索卡片，`Enter` 又被输入法用来上屏（不是提交搜索），现象是「按了 Enter 但计数不动、没有定位」。两条修法缺一不可：(a) 探针改用**剪贴板粘贴**（`Set-Clipboard` + `Ctrl+V`）注入文本，走同一条 `TextEdit` 文本路径但绕开 IME；(b) 代码侧在 `SearchBar::handle_keys` 顶部加「`ImeEvent::Preedit{text,..}` 非空即整条键盘横路挂起」的守卫（与节点编辑器同款纪律）。**「用户输入」类真实验收，只要本机装了 IME，就要考虑这条路。**
37. **`.ps1` 里加中文注释会立刻踩 #15 的坑**：搜索条探针第一版把中文说明写进注释、文件无 BOM，PowerShell 5.1 按 ANSI 读，报 `UnexpectedToken` 且行号指到花括号。**新脚本要么全英文注释、要么存 UTF-8 with BOM**——本仓库既有脚本多数是全英文，跟着写就对了。
38. **搜索卡片是 `Order::Foreground` 浮层，输入要挡画布**：打开搜索后必须 `canvas.set_input_blocked(true)`，否则卡片里的 `↑↓`/`Enter` 会被画布当导航/加同级；卡片上的「关闭」与点卡片外关闭也要走各自的 `Action`，别在闭包里直接改画布状态（借用检查器会拦）。

**M3-c-c 多标签新增（2026-10-18，来龙去脉见 [13 §4.22](13-纯Rust原生重构方案.md)）**

39. **多标签别急着 `Vec<Canvas>`**：每个 `Canvas` 各带一份字形图集（当时 4096² R8，CPU+GPU 各 16MB；P13 后为 3072²、且 CPU 镜像已移除）与一个合成器，线性复制会撑爆内存预算。字形键（字体/字号/字形 id）与文档无关 ⇒ 图集天然可跨文档复用，于是改成**一个 `Canvas` + 会话对调**：槽位只存 `Session/Camera/sel_ids`，切页 `mem::swap` 换文档。这条把「图集共享」从一件要改渲染核心的难事，降成一次搬移。
40. **`mem::swap` 换会话要顺手清瞬时手势态**：编辑框、拖拽、连线、悬停这些状态里的 id 属于**旧文档**，换文档后不清就会指着不存在的节点。`swap_session` 里统一置空；选择也不能直接搬索引——场景索引随文档而变，必须**按节点 id 重映射**（`set_view`）。另外切页前先 `commit_editing()`，否则正在编辑的文字会丢。
41. **条件渲染的浮层是 golden 的护身符**：标签条只在 ≥2 页时画，单标签时整根不渲染，默认界面与基线逐像素一致 ⇒ 加这个功能**不用重拍 golden**（`--tol 0` 连跑两次即过）。凡新增装饰性 chrome，优先做成「默认态不出现」，能把视觉回归的成本压到 0。

**M4 导出新增（2026-10-18，来龙去脉见 [13 §4.23](13-纯Rust原生重构方案.md)）**

42. **键盘归属：浮层开着时必须 `canvas.set_input_blocked(true)`**。导出对话框、搜索条、命令面板都是「画布之后的浮层」，egui 的绘制顺序不等于输入顺序——不屏蔽的话，对话框里的 `Enter`/`Esc` 会先被画布的 `shortcuts` 当「加同级 / 清空选择」吃掉。导出对话框额外一条：`Enter`/`Esc` 在**绘制按钮之前**读一次即可（浮层开着时画布已屏蔽，没人抢）；`open_export` 还要先 `commit_editing()`，因为编辑器的 `Enter`/`Esc` 与浮层是同一批键。
43. **Toast 的过期时刻必须用 `std::time::Instant`，不能用 egui 的 `input.time`**：原生文件对话框（打开/保存/导出）是**阻塞**调用，弹出期间 egui 的帧时间被跳过一大截；用 `input.time` 算的截止时刻会瞬间过期，现象是「toast 一出现就消失」（导出成功提示尤其明显，因为保存对话框就在导出前一步）。
44. **导出探针的两个新坑**（另见 #14 前台断言、#24 owner 与 TOPMOST）：① **保存对话框的覆盖确认默认键是「否」**——文件已存在时一次回车等于取消保存，探针若只查「文件在不在」会**假报成功**；必须断言覆盖确认窗（`#32770` 小窗）出现并按 `Alt+Y`（是），再回报文件 `mtime` 与当前时刻是否同步。② 保存路径必须给**绝对反斜杠路径**（相对路径会落进对话框记忆的上次目录）；且**在任何按键之前**断言 `GetForegroundWindow() == hwnd`，被别的前台窗口抢走时直接 `exit 1`，否则整串键会发给那个窗口、看起来像「应用没反应」。
45. **透明底导出不能改主题令牌**：`theme.ui.canvas_bg` 同时是**挖空色**——标签胶囊里的字（`text.rs:430`）、摘要主题框的底（`instances.rs:398`）、关系线标签的底（`instances.rs:423`）、折叠圆点的底（`instances.rs:655`）都拿它当橡皮擦。导出前把这条令牌改成 `TRANSPARENT`，透明 PNG 里这些前景会一起消失（1× 导出里的「验收」标签成了空壳）。正确做法：把「透明」做成**合成器的开关**（`Compositor::set_transparent`，清屏色 + 点阵底退透明），主题一动不动。**配套测试**：判「背景像素」只能靠**几何包围盒**（`world_to_phys` + `Rect::contains`）——挖空字用的就是画布底色，颜色上跟真背景分不开，按颜色判会把挖空字和抗锯齿连线边缘一起误判成背景。

**M4 后半新增（2026-10-18，来龙去脉见 [13 §4.24](13-纯Rust原生重构方案.md)）**

46. **golden 会把悬停态拍进去**：M4 后半收尾第一次 `cargo golden` 漂了 2367 px（0.135%），包围盒 x[15..65] y[17..67] 正好是汉堡按钮——上一支导入探针把鼠标留在了那里。golden 前必须把指针挪出窗口（本仓库用 `(3000,1500)`），然后**连跑两次**容差 0 才算过。凡是「只在鼠标悬停时出现」的 chrome，基线都在赌指针位置。
47. **PDF 的 xref 偏移是字节数，不是字符下标**：编码器里每个对象的 `offset` 必须取写进 `Vec<u8>` 的长度；单测若先把整份 PDF 转成 `String`（哪怕是 lossy）再用 `find("startxref")` 的字符位置，非 ASCII 内容一多就会把交叉引用表指歪，阅读器报「文件损坏」而测试仍绿。正确做法是在**原始字节**里用 `windows()` 找 `startxref\n`，从字节偏移继续解析。
48. **探针坐标是逻辑 px，注入输入前要乘 DPI**：导出探针第一版把 150% DPI 下截图上量到的物理坐标直接当逻辑坐标传，点击落在对话框外，现象是「Ctrl+E 没反应」。所有 `mouse_event`/`SetCursorPos` 前统一 `* dpi / 96`；截图坐标反推时也要先除再传。
49. **嵌位图的 PDF 是一条诚实的折中，不是偷懒**：PDF 内容流是另一套标记语言（坐标变换/字体嵌入/文本矩阵），与 SVG 的几何→标记管线不共享代码。当前 PDF 页面尺寸按 96dpi 把**世界单位**换算成点（×72/96），与取样倍率无关——2× 只是更清晰，不会让页面翻倍大；代价是文字不可选、体积偏大（2× 样例 106,935 B）。写文档时必须把这三点写明，别让用户以为导出的是矢量 PDF。
50. **导入标签的标题有两个来源**：导入的会话没有 `path`，`Session.title()` 先回落 `import_name`（来源文件名），`Ctrl+S` 必须先另存为；`save_to()` 成功后清 `import_name`，标题改跟新路径。另外 `export::file_stem` 必须剥掉**全部七种源后缀**（`.markdown/.zmind/.xmind/.opml/.mm/.md/.txt`，大小写不敏感），否则从 `大纲.md` 导入再导出，默认文件名会变成 `大纲.md.png`。

**E5 布局新增（2026-10-18，来龙去脉见 [13 §4.25](13-纯Rust原生重构方案.md)）**

51. **鱼骨肋线不能让同侧兄弟共享 x 列**：第一版所有分支根共用一条右缘列、只把分支带上下错开，肋线于是斜穿同侧邻盒。当时的单测只断言了「上下交替 / 盒落在轴上」，**全绿但画面是错的**——是 release 截图看出来的。改法是每侧一条槽位游标（`above_slot`/`below_slot`），排完一条分支就继续左移，同侧 x 区间互不重叠。几何布局的测试除了「相对位置」，还要加**带区间不相交**这类不变量，别只测几个坐标点。
52. **新面板控件的探针坐标先裁图核对**：260px 检查器里的布局 chips 是 3+2 两行，按设计稿估的行高加上 DWM 客户区偏移，点「时间轴」实际落到了「逻辑图」。裁图 `shots/qa/e5-inspector-crop.png` 量出真实矩形后才命中。任何面板控件第一次做真实输入验收，先截一张带控件边界的图，再写坐标。

**M2c 快捷键与面板/搜索动效新增（2026-10-18，来龙去脉见 [13 §4.26](13-纯Rust原生重构方案.md)）**

53. **winit 的全屏/尺寸命令走异步 `SWP_ASYNCWINDOWPOS`，DWM 会停在旧帧**：F11 用 `ViewportCommand::Fullscreen` / `InnerSize` / `OuterPosition` 时，窗口矩形已经变了，但合成器要等下一次**同步**尺寸变化才提交新帧——现象是「按 F11 没反应，鼠标一动就全屏」。修法是绕开 winit：`MonitorFromWindow` + `GetMonitorInfoW` 取显示器矩形，`ShowWindow(SW_RESTORE)` 后再 `GetWindowRect`（最大化时直接量会拿到屏幕尺寸），然后一次同步 `SetWindowPos(HWND_TOPMOST, ..., SWP_SHOWWINDOW)`。退出按保存的矩形同步还原，再按需 `SW_MAXIMIZE`；进出顺便切 `DWMWCP_DONOTROUND`/`DWMWCP_ROUND`。
54. **原始 API 改过窗口层级后，winit 的 `WindowLevel` 是 no-op**：winit 缓存了自己认为的层级；`SetWindowPos(HWND_TOPMOST)` 之后它仍以为窗口是 `Normal`，`ViewportCommand::WindowLevel(Normal)` 不会发任何系统调用。掉置顶必须同样用原始 `SetWindowPos(HWND_NOTOPMOST, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)`。
55. **`egui-winit` 会把 `Ctrl+C/X/V` 翻译成 `Event::Copy/Cut/Paste` 并 return**：按键事件根本到不了 `consume_key`。画布要在 `ui.input_mut` 里读走这三类事件自己派发节点剪贴板；复制时还要 `ctx.copy_text()` 写系统剪贴板——空剪贴板时 egui 连 `Event::Paste` 都不会发，粘贴会静默失败。
56. **`consume_key` 的修饰键匹配忽略多余 Shift/Alt**：`Ctrl+Shift+C` 会先被 `Ctrl+C` 吃掉，`Alt+Enter` 会先被裸 `Enter` 吃掉。带修饰的组合必须按「修饰键多 → 少」排序消费；`Ctrl+Shift+←→` 要排在不带 Shift 的方向键之前。
57. **「复制样式」只复制显式覆盖，继承值复制出来是空集**：演示文档的节点填充多数来自主题级联，从它们 `Ctrl+Shift+C` 不会带走任何东西。这不是 bug——粘贴后应继续跟随主题。探针第一版因此拍到「粘贴前后完全一样」的假成功；正确做法是先用检查器给源节点设一个显式填充，再复制。凡是验证「有没有复制」，先确认源数据真的非空。
58. **`Ctrl+Shift+/` 在 winit 里报 `Questionmark`，不是 `Slash`**：Shift 按下时字符是 `?`，egui 映射成 `Key::Questionmark`。全部展开要同时查 `Slash` 与 `Questionmark`，否则键位文档写着有、按下去没反应。
59. **真实输入探针的坐标有三个坐标系**：截图读到的像素是**物理屏幕坐标**，脚本里的点击参数常按**逻辑客户区**写。必须 `ClientToScreen` 加客户区原点（本次是 150,61）、再乘 DPI 比例；直接用截图坐标会点偏一个标题栏 + 边框。另外未聚焦窗口的第一次点击会被系统吃掉（只用于聚焦），探针必须先断言前台归属再点。
60. **动效帧不能当 golden 基线，harness 必须走终态**：面板开合 0.2s、搜索呼吸环 0.7s，截图时机会有 ±1 帧抖动。`panel_motion` 在 `reduce_motion || harness.is_some()` 时直接返回终态，golden 才能连跑容差 0；真实输入截图只作「动效确实在跑」的证据。减少动画读 `SPI_GETCLIENTAREAANIMATION`（启动缓存一次），降级为常亮环/直接终态。
61. **`Process.MainWindowHandle` 在启动早期会指向 winit 的辅助窗口**：`Start-Process` 之后只要句柄非零就接管，会拿到 15×15 的 `Winit Thread Event Target`（`GetWindowRect` 量出 22×22），后续点击/截图全落空。探针要等到**尺寸 ≥600×400** 的窗口再绑定，或者按类名/标题枚举；「句柄存在」不等于「主窗口已经建好」。
62. **恢复窗口几何要在画布首帧 fit 之后补一次重新取景**：`SetWindowPos` 的尺寸变化比第一帧画布的 `fit` 晚一两帧，窗口从 1620×1080 缩到 1400×900 时首帧按旧视口取景，构图会偏左且左根节点被裁掉（截图上很明显）。修法是 `Canvas::request_fit()` + 500ms 的 `refit_until` 窗口，每帧按当前 `available_size` 重 fit，落定后自动停；只在恢复路径设置，不干扰用户后续手动 resize（那仍然保持当前相机）。
63. **最大化窗口不能用 `GetWindowRect` 存「还原位置」**：最大化时 `GetWindowRect` 返回铺满显示器（无边框窗口还会外扩 11px）的矩形，存下去会把双击还原的位置覆盖成屏幕大小。持久化必须用 `GetWindowPlacement().rcNormalPosition` + `IsZoomed` 判断；恢复时先同步 `SetWindowPos` 摆常态矩形，再发 `ViewportCommand::Maximized(true)` 让 winit 自己最大化，别直接 `ShowWindow(SW_MAXIMIZE)` 绕过它的状态缓存。
64. **PowerShell 5.1 会把 `@($a / $s, $b / $s)` 里的逗号并进除法右操作数**：看起来是返回两个标量的数组，实际报 `Cannot call method op_Division on System.Object[]`。先分别算好 `$x = $a / $s`、`$y = $b / $s`，再 `return @($x, $y)`；探针里 `Get-ClientLogical` 就被这条坑过（`_archive/_ps_probe.ps1` 留了两版对照）。
65. **结构动作会让布局重新居中，探针缓存的坐标立刻失效；键盘菜单要按「可执行行」计数**：右键「移入同一父级」后节点整体重排，旧坐标的右键会落到空白（假故障：复制没反应、粘贴菜单仍禁用）——每次结构变化后重新扫描调色板/白卡取坐标。菜单 `↓` 会跳过分隔线与禁用项，空白菜单从无高亮到「全部折叠」是 **5** 次，不是按条目下标数出来的 4 次；数错时 Enter 会落在「全部展开」上，随后 `collapsed` 断言才暴露。

**结构动效新增（2026-10-18，来龙去脉见 [13 §4.30](13-纯Rust原生重构方案.md)）**

66. **`blend_scenes` 不能在 `t=0` 提前返回起点场景**：命中索引、选择环、面板都按**目标场景**的 `ids/index` 取节点。若 t=0 返回 `from`，删除/新增节点的第一帧索引就会错位——点得到不存在的节点、选择环套错盒子。正确做法是克隆 `to`，只把共同节点的几何 lerp 回起点；这条很容易「优化」掉，必须有测试兜住。
67. **新增节点的连线终点也要跟子节点走**：只给新连线 alpha 淡入，线会在第一帧连到终点，而节点还在父盒里——看起来像「线先飞过去，盒子后到」。新线的 `end` 要从父侧端点 lerp 到子节点位置；旧线反向收缩到两端节点中心。
68. **0.20–0.34 s 的动效窗口，截图必须先截早期帧**：`CopyFromScreen` 本身有延迟，先 sleep 150ms 再截只剩尾帧；`scripts/m2c-anim.ps1` 在按键后**立即**截 `-early`，再 70ms 截 `-mid`、650ms 截 `-settled`。另外新节点输入提交不要按 Enter（中文 IME 组合期会吞掉），点空白让编辑器失焦提交更稳。

**M5 探针与打包新增（2026-10-18，来龙去脉见 [13 §4.31](13-纯Rust原生重构方案.md)）**

69. **`$Home` 是 PowerShell 的只读自动变量**：探针参数写 `[switch]$Home` 会在赋值时报 `Cannot overwrite variable Home because it is read-only`，脚本一行都没跑。改用 `-StartPage` 这类非保留名；同理别用 `$PWD`、`$PID` 当参数。
70. **Git Bash 会吃掉传给 PowerShell 的反斜杠**：`-Exe target\release\mw-shell.exe` 到了脚本里变成 `targetreleasemw-shell.exe`，报找不到文件。路径统一加引号并用正斜杠（`"target/release/mw-shell.exe"`），PowerShell 接受。
71. **FPS 只在连续重绘时统计**：egui 空闲时按需重绘，帧间隔几百毫秒，直接平均会把 FPS 拉成个位数。`Stats` 只在帧间隔 ≤250ms 时入 240 帧滚动窗，超过就整窗清掉；验收必须用连续输入（滚轮/拖拽），停手后看到的数字不能当 P5。
72. **大文档语料不能用 `logicRight`**：5k 节点在向右逻辑布局里退化成一列，最小缩放只有 48% 可见，P5 的「80% 可见」前提不成立。`make-sample.mjs` 对大样本改用 `mindmap`，可见率 93%。语料布局本身会决定测试是否有效，先看可见率再读帧率。
73. **内存先测空应用基线**：P13 攻关前开始页空应用已 318–321MB，超过 P13 的 300MB；5k/10k/20k 只再增加 12–39MB。没有空基线就会把失败误归因给节点/场景。当时占用大头是 DX12/wgpu、系统雅黑两份字体（≈37MB）、4096² R8 图集（CPU+GPU 各 16MB）和全窗口渲染目标；缩图集到 2048² 仅省约 24MB，仍不够。**攻关 A+B+C 后**：字体改只读文件映射（约 −34MB）、图集 3072²（约 −7MB）、再移除图集 CPU 镜像（实测 −12.0MB 空应用 / −14.6MB 五分钟），空应用降到 **264.5MB**——先压空基线，再谈文档数据。
74. **便携 ZIP 不是安装器**：`package-release.ps1` 只产出 exe + README 的 ZIP 与 SHA256，没有 Inno Setup/NSIS、文件关联、快捷方式、卸载项。P14 的「安装包 ≤30MB」目前只能写成「便携包通过」，回复用户时不要写成「安装包已交付」。
75. **`package-release.ps1 -SkipBuild` 复用现有 exe**：改了 `.rs` 之后必须先 `cargo build -p mw-shell --release` 再打包，否则 ZIP 里还是上一版二进制。打包脚本会打印 `exe_bytes`/`zip_bytes`/SHA256，把它们与代码时间一起记进文档，避免「测的是旧 exe」。

**P13 内存攻关新增（2026-10-18 晚，来龙去脉见 [13 §4.33](13-纯Rust原生重构方案.md)）**

76. **字体 mmap 只有在 epaint「借用 blob」时才省内存**：`FontData::from_owned` 会把整个 TTC 复制进私有堆；本仓库能靠 `CreateFileMappingW` + `MapViewOfFile` 省下约 34MB，是因为 epaint 0.37 的 `FontData::from_blob` 经 `self_cell` + `skrifa::FontRef` 直接借用字节（已核对 `face_store.rs`/`font_face.rs`）。**升级 epaint 前必须复验这条**，否则 mmap 只是换了一种读文件方式，内存一分不省。`MappedFont` 的 `Send/Sync` 是手写的 unsafe，依据是视图只读且生命周期覆盖 `FontData`。
77. **去掉图集 CPU 镜像就失去「整张重传」的退路**：`AtlasUpdate` 从 `[u32;4]` 改成带 `pixels` 的 `AtlasRect` 后，`GlyphAtlas::data()` 不复存在，GPU 与 CPU 只能靠代次保持一致。代次断档（中间漏传）必须置 `atlas_desync`，由画布调 `TextEngine::reset_atlas()` 重排全部字形；图集重排不清 GPU 纹理——旧 UV 已失效，残留像素采不到。**任何新增的图集消费方都要检查这条恢复路径。**
78. **`export_job` 不许再伪造 `AtlasUpdate { generation: u64::MAX, reset: true }`**：导出器与图集都是新建的，代次 0 接 1，直接消费 `text.paint()` 返回的真实增量即可。伪造代次在全量上传模式下能跑，在增量模式下会触发一次不必要的 desync/全量重排。
79. **单次 299.6MB 不是 PASS**：A+B 的五分钟曲线是 296.7–297.0（0.5–3.5min）→ 297.2（4min）→ 299.5/299.6（4.5–5min），**末段有 +2.9MB 台阶**，原因未定位（疑似分配器/驱动增长），余量只有 0.4MB。判定至少要两次独立五分钟采样、留 ≥10MB 余量；否则下一个小功能就会把它顶回红。**这条纪律最后真的救了场**：C 落地后跑了两次独立五分钟（284.4–287.9 / 289.4–289.6），两条曲线都是平的，才有资格写 PASS；只看第一次的 285.0 会把余量算成 15MB。
80. **release 数字必须与源码 mtime 对齐**：C 的源码改于 20:49，而当时的 `target/release/mw-shell.exe` 是 20:39 构建（20,253,184 B，含 A+B），**那个 exe 里没有 C**——发现这一点是因为引用数字前对了 mtime，而不是因为测试结果不对。引用任何性能/内存数字前，先 `ls --time-style=full-iso` 对一遍 exe 与源文件时间；测到旧二进制比没测更危险。
81. **`Color32::gamma_multiply` 乘的是 RGBA 四个通道**：拿它「压暗」一支不透明墨水，得到的是**半透明**墨水（`0.45` 把 alpha 一起打到 115），贴在浅底上实测 1.4:1。派生墨水请 `mix(accent, 主题字色, t)`，永不带透明度。**更阴的是暗色档因子 >1 会掩盖同一个 bug**：`255 × 1.35` 饱和回 255，alpha 又变实了，于是只有浅色外观出问题——**两套外观都得测，测一套等于没测**（13 §4.36）。
82. **egui 的自动 id 是行为，不是实现细节**：只要上层 `Ui` 的构成变了（开合大纲/检查器、加减标签），下面所有自动分配的 id 一起漂移；画布区原来用 `allocate_exact_size` 就跟着漂，而 `Focus::end_pass` 的**死人开关**发现本帧 `used_ids` 里查不到握着焦点的 id 就清空焦点 → 画布裸键（Tab 加子、方向键导航）**全体静默失灵**，没有任何报错。任何「这一帧必须一直握着键盘」的 widget 都得钉死 id（`Id::new(...)` + `ui.interact(rect, id, sense)`）。回归要**直接断言两帧的 id 相等**，别只断言行为——先让它是红的，再让它绿（13 §4.39）。
83. **`Response::has_focus()` ≠ `memory.has_focus(id)`**：前者还要求窗口是 **OS 前台**。拿它做「键盘归谁」的判断，等于把应用行为绑在桌面此刻有没有别人抢焦点上（验收机的输入锁一锁就是几小时，焦点环永远不亮，看着像「Tab 走不动」）；拿它做验收证据，又会在无头环境里什么都看不见。**判定与证据分家**：应用只认自己的模式位（`keys_in_panels()` = `!self.wants_keys`），证据走 `MW_TRACE` 焦点轨迹（只看 `memory`，与前台无关）。**像素差也不能当焦点证据**：状态栏那行指示整条是强调色画的，改一次配色它就重画一遍——判「键盘有没有被抢走」要看条带**墨迹覆盖率**，不是像素差。
84. **一支快捷键只能有一个主人**：`InputState::consume_key` **会把事件从 `Input::events` 里摘掉**，所以窗口级链必须在画布绘制之前跑，否则两边抢同一次按键。第二条纪律：**带 Shift 的组合先查**——`consume_key(COMMAND, Z)` 的修饰键匹配会**放过多余的 Shift**，`Ctrl+Shift+Z`（重做）会被前面的 `Ctrl+Z`（撤销）吃掉；`Ctrl+Shift+C`（复制样式）同理会先被 `Ctrl+C` 吃掉。顺序即语义，这一条在 `canvas.rs` 与 `main.rs` 各写过一次注释。
85. **探针必须先证明「我看得见我要量的东西」**：`CopyFromScreen` 抓的是屏幕上那一刻的东西，任何别家窗口压在测量区上都会被当成应用画出来的。一次 Windows 设置窗落进应用正中，**同时伪造出四条产品 FAIL**（撤销没回原帧 35,852 px、清覆盖 1,190,288 px、色板没生效、键盘被抢）。现在 `v5-accent.ps1` 每次抓帧前 `SetWindowPos(HWND_TOP | NOACTIVATE)` 抬 Z 序（**后台进程抢不到前台，但抬 Z 序不需要前台权限**），再用 `WindowFromPoint` + `GetAncestor(GA_ROOT)` 按 90 px 网格采样 216 点问「这儿真的是我的窗口吗」，**无标题根窗口跳过**（IME 候选窗 / tooltip / 光标助手窗这些自家助手窗，一格压一像素不算瞎）；仍有残留遮挡 → **退出码 3 = INCONCLUSIVE**，绝不当成产品失败。写新探针请沿用这套守卫；另外「整帧往返必须一致」的断言要先划掉状态栏与标题栏的保存态（切主题/改配色会 dirty 文档，`已保存 → ● 未保存` 是合法变化，第一版没剔就误报 4797 个差异像素）。
86. **只测正向的变换测试等于没测**：`linear_to_srgb` 返回 0–1，写回 u8 时漏乘 255，于是每个通道都被四舍五入成 0 或 1（浅绿卡片变近黑）——**它对任何输入都自洽地错**，只有来回走一遍才现形（13 §4.38）。但来回测也别贪：纯 `#0000ff` 这种色域顶点**故意不测**，它坐在 sRGB 立方体的角上，正逆矩阵常数差一点就被判越界、彩度回收 0.01 就能让绿通道从 0 涨到 48，而用户那支颜色**从来只贡献一个色相数字**，根本不进 `from_oklch`。**只测真的会被转的色。**
87. **出界不要逐通道钳**：OKLCH 转 sRGB 落在色域外时，`clamp` 会把色相偷走 14°（用户点 60°、得到 46.2°）；改成**沿半径二分回收彩度**，落点 60.2°，代价只有彩度 0.198→0.142。二分端点必可行（彩度 0 是纯灰，永远在域内）。同理别把 OKLab 的 f64 参考矩阵塞进 f32：那不仅带来 32 条 clippy `excessive precision`，截短带来的色相抖动会顺着「换强调色」传到每张卡片上（v5-d 改整段 f64 后**像素一字未变**）。
88. **自绘可聚焦控件要把「生效」与「焦点」画成两层**：12 格色板里选中环用半径 10 + 强调色、焦点环用半径 11 + 中性 `ch.dim`，否则「哪一格生效」和「光标在哪」互相冒充（egui 只给内置控件画焦点环，自绘圆盘这一圈得自己画）。配套纪律：**连续触发的控件（取色器拖动）要在 `pointer.any_down()` 停了才发命令**，一次拖动 `changed` 几十次会把撤销栈填满同一件事（13 §4.38）。
89. **「该不该执行」与「把事件摘走」必须是两步**：egui 0.37 不替 `TextEdit` 预过滤剪贴板键，`Event::Copy/Cut/Paste` 就是 `events` 里的普通条目，**谁先 `retain` 谁赢**，而面板的输入框要到本帧**后面**才画。所以窗口级的门（`input_blocked() || is_editing() || ctx.text_edit_focused()`）必须打在**任何一次 `consume_key`/`retain` 之前**——打在之后，那一下按键两头落空。纯函数 `clipboard_chord()` 就是为了让这个顺序可测（13 §4.40）。
90. **`SendMessage` 送不进修饰键**：winit 的修饰键取自**异步键盘状态**（`GetKeyboardState`），帖 `WM_KEYDOWN` 不改那份状态，于是裸键（F6/Esc/Tab）能到、**任何 Ctrl 组合都到不了**。后台探针想知道「和弦能不能用」，唯一诚实的办法是开场**分别试两条路由**（sent / `keybd_event` 硬件），并**在整轮结束时复核一次**；中途别人抢走前台就把判词降级成 INCONCLUSIVE（退出码 3），因为硬件按键打进的是前台窗口，不是我们的窗口。别静默换路由——一轮里一半主张走不同物理路径，结论没法合成一句。
91. **「剪贴板可读」要先证明可写**：`Get-Clipboard` 在 STA 之外的进程直接抛异常。探针开场写哨兵再读回（不等 = 不可用），读不回来就记 blocked，绝不让它冒充成产品的 FAIL。
92. **能拿到「应用自己报出来的整数」就别数像素**：粘贴加了几个节点，像素只能答「重画了」，答不了「正好 4 个」，更看不出**一支和弦执行了两遍**。`manifest.json` 的 `nodeCount`（由 `mw_format::save` 写，自动保存走同一支函数所以不必 Ctrl+S）配 `clipboard_text()` 的行数，是几何无关的精确差分；4→8→4→8 来回同值同时钉住了「一支一次」。像素带差降为旁证。
93. **「什么都没发生」必须配一条「同一支键确实会做什么」**：主张「框里握着键盘时 `Ctrl+Z` 不动文档」单独读是空的——门把键吃掉了长得一模一样。所以探针成对跑：`search-input` 握着键盘时 0 px，Escape 之后同一支键 9,259 px。前提那一半也要由应用报出（给搜索框登记语义名 `search-input`），不能从结果倒推。

**v6 字体样式新增（2026-10-19 下午，来龙去脉见 [13 §4.41](13-纯Rust原生重构方案.md)）**

94. **对标字号要量「字墨」，不要量「控件框」或读检查器里的名义值**：XMind 窗口在 144 DPI 下，截图里的一切都是物理像素，先除 1.5 才是 CSS px；而字号只能从**暗像素墨盒**反推——拉丁看 x-height（`rust` 墨高 25 物理 ≈0.52 em ⇒ ≈32 CSS），中文看 CJK 墨高（25 物理 ≈0.87 em ⇒ ≈18.7 CSS）。字重要看**水平暗行程宽度**（中心 7–9 px、分支 2–4 px），不能凭「看起来粗」。`PrintWindow(PW_RENDERFULLCONTENT)` 是只读的，用户开着的 XMind 不要点、不要关。
95. **四套主题的字号/字重必须来自同一张常量表**：四份 `levels` 各自写数字，换主题就会顺带「换字号」，而且没有任何测试会红。v6 把 `LEVEL_TYPE: [(f32, bool); 4]` 放进 `theme.rs`，四套主题只引用它，并加 `every_theme_shares_one_type_ladder` 同时钉「四套同阶」与「只有根加粗」——后者是这次测量的语义结论，不是审美偏好（旧梯一级 17 加粗，方向反了）。
96. **改字阶会改 golden，这是合法漂移，但要量化后再重拍**：这次 `offscreen` 漂移 18,814/540,000 = 3.484%、最大差 224，包围盒 x[0..712] y[227..369] 正好是根节点文字——数字与包围盒都能对上「只改了字」，才允许 `--update`；重拍后必须 `--tol 0` 连跑两次。编辑器和 SVG/PDF 不用单独改：它们都读 `NodeGeom.font_size/bold`，改常量表就一起变。`line_height = font_size × 1.45` 是行盒口径，不要用墨高反推去动它。
