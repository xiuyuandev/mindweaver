## 4. 迭代节奏与过程

1. **每轮一个主题**，控制在 1–2 天；每轮必须留下：代码 + 测试 + 证据 + 文档。
2. **先规格后代码**：涉及交互/视觉的变更，先改 `06`/`07`/`08` 的验收条款。
3. **每轮结束的门槛**：
   - `cargo test --workspace` 全绿；
   - `cargo fmt --check` 干净；
   - clippy 新增 0；
   - 改外观 ⇒ golden 量化/重拍/连跑两次；
   - 改交互 ⇒ 至少一条真实输入证据或说明环境限制；
   - 回填 `11` 与 `13`。
4. **数字一致**：测试数、golden 漂移、内存/性能数字在 `11`、`13`、`README` 三处一致。
5. **不夸大**：未做/半做必须留在 `11` 的缺口表。

## 5. 风险登记

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 换机后 golden 与 GPU/驱动相关 | 基线误判 | 先量化差异，记录环境；只有合法外观变更才重拍 |
| 真实输入被前台锁/无桌面 | 探针无法执行 | v5-accent 的键盘-only 分支；如实记 INCONCLUSIVE |
| IME 只能人工验收 | 无法由 AI 关闭 | 保持 P0 未签字状态，准备清单给负责人 |
| 面板/焦点 id 漂移 | 键盘操作静默失效 | 持久 id + `MW_TRACE` 回归 |
| 逐节点样式语义扩散 | 卡片/连线/子树不一致 | 级联规则单测（`theme.rs`）；`branch_fill` 只由显式覆盖触发 |
| 性能余量小（P13 最差 10.4MB） | 新功能易破线 | ≥10MB 改动复测；预算见 `08 §9.1` |
| 仓库无历史 | 覆盖不可恢复 | 上传 GitHub 后启用分支/PR；本地改动前备份 |

## 6. 发布定义（1.0 的最低门槛）

- P0 全部关闭（含 IME 人工矩阵签字）。
- P1 的界面一致性项完成（字阶已完成；焦点、色板键盘可达的代码与单测已完成，真实输入探针仍待补）。
- 真安装器 + 文件关联 + 应用图标 + LICENSE。
- 在至少两台不同 DPI/GPU 的 Windows 机器上通过完整验收。
- 文档（README、HANDOFF、11、13）与代码一致，无「基本完成」。
