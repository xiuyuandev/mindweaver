## 1. 签什么、不签什么

| 对象 | 是否签名 | 说明 |
| --- | --- | --- |
| `dist/zhisi-v<版本>-win64/MindWeaver.exe` | 是（配置证书后） | 先复制到暂存目录再签，失败不会留下半签名的本地构建 |
| `dist/zhisi-v<版本>-win64.zip` | 否 | ZIP 容器本身不做 Authenticode；用户下载后校验 `.sha256` |
| `scripts/install.ps1` | 否 | 便携安装脚本，不走 Authenticode；ZIP 内附带 SHA256 |

签名钩子是 [`scripts/sign.ps1`](../scripts/sign.ps1)，已接入
[`scripts/package.ps1`](../scripts/package.ps1) 的打包流程：

```text
package.ps1
  └─ 复制 exe 到暂存目录
     └─ sign.ps1 -Path <暂存 exe> [-Require]
        ├─ 无证书       → SIGN SKIP, exit 0（-Require 时 exit 1）
        ├─ 有证书       → signtool sign /fd SHA256 /tr <时间戳>
        └─ 默认验证     → signtool verify /pa /v + Get-AuthenticodeSignature
```

## 2. 日常打包（无证书）

```powershell
# 正常打包：跳过签名，ZIP 照常产出
powershell -File scripts/package.ps1

# 发布前强制：没有证书就直接失败，防止把未签名包当正式版发出去
powershell -File scripts/package.ps1 -RequireSignature
```

预期输出（无证书时）：

```text
SIGN SKIP: no certificate configured (set MW_SIGN_PFX or MW_SIGN_THUMBPRINT).
PACKAGE OK: dist\zhisi-v0.1.0-win64.zip (...)
SHA256: ...
```

## 3. 有证书时的两种接法

凭据只从环境变量或命令行参数读，**不要把 PFX / 密码提交进仓库**。

### 3.1 PFX 文件（CI 常用）

```powershell
$env:MW_SIGN_PFX = 'D:\secrets\mindweaver-codesign.pfx'
$env:MW_SIGN_PFX_PASSWORD = '<密码>'
powershell -File scripts/package.ps1 -RequireSignature
```

也可以直接传参：

```powershell
powershell -File scripts/sign.ps1 -Path dist\...\MindWeaver.exe `
    -Pfx D:\secrets\mindweaver-codesign.pfx -Password '<密码>'
```

### 3.2 证书存储里的指纹（本机常用）

证书需在 **CurrentUser\My**（脚本暂不支持 `/sm` 机器级存储）：

```powershell
$env:MW_SIGN_THUMBPRINT = 'A1B2C3...'
powershell -File scripts/package.ps1 -RequireSignature
```

`-Pfx` 与 `-Thumbprint` 互斥，同时给会直接报 `SIGN FAIL`。

## 4. 时间戳

默认使用 DigiCert 的 RFC3161 服务：

```text
http://timestamp.digicert.com
```

可用 `MW_SIGN_TIMESTAMP_URL` 或 `-TimestampUrl` 换成公司内部时间戳服务。
时间戳让签名在证书过期后仍然有效，正式发布**不要**加 `-NoTimestamp`；
只有离线自签名冒烟才用。

## 5. 验证

```powershell
& 'C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\signtool.exe' verify /pa /v dist\...\MindWeaver.exe
(Get-AuthenticodeSignature dist\...\MindWeaver.exe) | Format-List Status, StatusMessage, SignerCertificate
```

- 受信任证书：`Status = Valid`。
- 自签名证书：`signtool verify /pa` 会失败、`Status = UnknownError`，这是根证书
  不受信任导致的，**不等于签名没写进去**（`SignatureType = Authenticode` 且有
  `SignerCertificate`）。本地冒烟用 `-NoVerify` 跳过 `/pa`。

## 6. CI 接线建议（尚未启用）

发布任务里把 PFX 以 base64 放进 Secret，构建时还原到临时目录再调用：

```powershell
$bytes = [Convert]::FromBase64String($env:MW_SIGN_PFX_BASE64)
[IO.File]::WriteAllBytes("$env:RUNNER_TEMP\codesign.pfx", $bytes)
$env:MW_SIGN_PFX = "$env:RUNNER_TEMP\codesign.pfx"
powershell -File scripts/package.ps1 -RequireSignature
Remove-Item "$env:RUNNER_TEMP\codesign.pfx" -Force
```

只有拿到证书、把 Secret 配好之后，才把 `-RequireSignature` 写进发布流水线；
本地日常打包保持“无证书跳过”。

## 7. SmartScreen 与证书选择

- 新证书没有下载信誉，前几百次下载仍可能弹 SmartScreen 警告；签名是消除
  长期警告的前提，不是即时开关。
- OV（组织验证）证书可累积信誉；EV 证书可更快建立信誉，但成本更高。
- 证书到期前续签并保留时间戳；已签名的旧版本不会因证书到期而失效。
- 若未来提供 MSI/EXE 安装器，安装器本体也需要单独签名；当前只有便携 ZIP，
  仅 exe 需要签。
