## 0. 结论先行

**推荐母题 A「素纸织线」**：它是现有四套主题（纸感/雾青/暖砂 + 墨夜）唯一能「不收推翻、只收拢」的方向——
暖纸底、墨字、发丝边本来就在跑，A 只是把这些散落的灰收敛成一条色阶，并补上两个可被一眼认出的
织线签名（画布经纬短纹、关系线双股收束、选中态缝线针脚）。B「雾光玻璃」偏冷、需要改动面板高光与
浮层描边，视觉变化面最大；C「陶砂窑火」暖度最高但暗色容易显脏，适合做第二套可选皮。

**总包数 7 个**（T1 抽令牌 → T2 语义收口 → T3 品牌落地 → T4 多主题 → T5 高清 → T6 门扩展 → T7 编辑器合并）。

T1 / T6 **零重拍**（T1 必须逐像素 0 差异）；T3 / T4 / T5 / T7 只**新增**基线（约 +8 / +8 / +12 / +5 张）。

没有一条需要标红）；G5/G6/G7 是结构门（主题数、墨夜专用），由 T6 随新增主题一起改写。

## 2. 品牌主张与视觉母题（三版）

每版都能只看文字做选择：一句主张 → 母题元素用在哪 → 两个视觉签名 → 明暗两套 hex → 取舍。
三版都**不新增字段**，全部落在现有 `ThemeUi` / `palette` / `levels` 的取值范围内。

### 2.0 三版共同的三条底线

1. **强调色只出现在「可交互/可识别」的点**：线、针脚、焦点环、选中行的小色点；不做整块实色按钮墙。
2. **层级靠留白 + 发丝边**，阴影只留给浮层（`elevation` 四档），不做「每张卡都投影」。
3. **对比度先过门再谈气质**：任何母题的取值必须让 §8 的 G1–G4 + CX 全绿，否则调色不改规则。

### 2.1 候选 A「素纸织线」（推荐）

> **一句话主张**：一张被反复编织的纸——界面是纸，内容是墨，关系是线。
> **母题元素用在哪**：
> - 画布底纹：28px 经纬短纹（每格 1 短竖 + 1 短横，长 3px，alpha 6–10%）——`ui.dot` 升级为「织纹层」，
>   亮色默认**仍关**（尊重 `06` 的纯色结论），只在「品牌强化」时打开并重拍。
> - 关系线：**双股收束**——分叉处两股 1px 并成一股，距末端 3px 内合流（等于把 `taper` 做成可见的编织感）。
> - 卡片边：只用 1px 发丝边，色温跟 `border`，不叠阴影。
> - 选中态：**缝线针脚**——2px 下划线 + 两端各 3px 方点（替代整行实色底）。
> - 空状态：中心一枚 1px 织格十字 + 一句「从这里开始织」。
> - 启动页：字标用 `ui::DISPLAY 26`，左侧一枚 12px 针织结（两段折线）。
> **视觉签名（一眼认出）**：① 所有横线/分隔都是「纸纤维」暖灰（`border #E2DCD1`），没有冷灰；
> ② 强调色只出现在针脚与色点，按钮永远是文字按钮；③ 卡片角是 6px（最紧的一档），不做大圆角。
> **取舍**：暖纸底拉低眩光 → 高级但不冷；墨字 `#21262A` 不是纯黑 → 长时间读不刺；不追求玻璃反光，

### 2.2 候选 B「雾光玻璃」

> **一句话主张**：一层薄雾盖在深空上——界面是玻璃，光是内容。
> **母题元素用在哪**：
> - 面板上缘 1px 高光（比面板底亮 6%，暗色为主、亮色 alpha 减半）——检查器/大纲/浮层的顶边。
> - 浮层双层描边：外 1px `border` + 内 1px 白 8%，像两片玻璃叠着。
> - 选中态：**环**——内 1.5px 强调环 + 外 3px 12% 外晕（不用实色底）。
> - 画布：160px 一根极细经纬网（alpha 4%），只在暗色开。
> - 空状态：一颗 2px 星点 + 三行渐隐说明。
> - 启动页：字标下的 1px 冷光分隔线。
> **视觉签名**：① 冷蓝强调 `#2F6280` / `#6FB3DA`，只做环不做底；② 所有浮层都有「上缘亮一线」；
> ③ 关系线恒 1.5px、不 taper（同等粗细，像玻璃纤维）。
> **取舍**：冷峻、科技感最强；代价是暖度没了，靠 `panel #FAFCFE` 的高亮面保阅读舒适。对比度最宽裕

## 3. 令牌分层

### 3.1 三层与命名

```
primitive（原始值，不许组件直接引用）
  └─ neutral ramp / accent ramp / 字号 / 间距 / 圆角 / 描边 / 阴影 / 动效时长
semantic（一屏之内稳定的语义，组件只读这一层）
  └─ canvas / panel / panel2 / text / dim / faint / border / accent / accent_soft
     / hover / selected / danger / ok / focus / selection / disabled
component（某个组件的成品色与几何）
  └─ inspector_row / outline_row / card / tag / edge / node_box / toast / empty_state
```

**命名**：`<surface>_<role>`，全小写下划线，不加类型后缀；语义层字段**沿用现有名字**
（`bg / panel / panel2 / text / dim / border / accent / accent_soft / hover / canvas_bg / dot`），
避免二次改名。

**硬约束（要写成测试）**：`mod primitive` 为 `pub(crate)`，只有 `theme.rs` 与 `design::semantic` 可以
`use`；所有 `component::*` 构造函数只接受 `&Semantic`，**不接受 `Rgba` 字面量**。这样"组件直接用原始色阶"
在编译期就过不去，而不是靠 review 记住。

## 4. 多主题机制

目标：像 Obsidian 那样「换皮不换骨架」——**基础色板 + 强调色 + 明暗模式**，不是每套重画一遍界面。

### 4.1 主题从哪来、存哪

| 来源 | 存法 | 优先级 |
| --- | --- | --- |
| 内置母题 | `mw-core/src/theme.rs` 的 `fn` 常量（`snow/ink/mist/sand` + 新增 `weave/weave-night` 等） | 最低（默认） |
| 用户整套主题 | `%APPDATA%\织思\themes.json`（`theme_studio.rs:30`） | 中 |
| 用户组合预设 | `%APPDATA%\织思\theme-presets.json`（`theme-presets.rs:3`） | 中（T7 与上一行合并） |
| 全局默认主题 | `%APPDATA%\织思\settings.json` 的 `theme`（`settings.rs:63`） | 高 |
| 单文档主题 | `meta.theme` + `SetTheme`（`command.rs:92`） | **最高**（打开即用文档自己的） |

解析顺序：`meta.theme` → `settings.theme` → `snow`。找不到 id 时**退回默认并在状态栏提示一次**，
不静默改文档（与 `get_theme` 的「不认识就退 cm-paper」口径保持一致）。

### 4.2 主题的数据形状（Rust）

```rust
// 现有（不改）：Theme { id, name, appearance, ui, palette, palette_fill, levels, … }
// 新增只做「组合」，不复制整套：
struct ThemeRecipe {
    base: &'static str,      // 内置母题 id
    appearance: Appearance,  // 明/暗
    accent: Option<Rgba>,    // 只换强调色（现 with_accent 只旋色相，保留）
}
```

用户整套主题**只允许改** `ui` 的 11 个颜色 + `palette`（8 支） + `appearance`；`levels` 由
`appearance` 的内置默认派生（防止用户把层级文字写成 2:1）。这是「Obsidian 可换肤」与「不许破坏 AA」
之间的取舍：**换色不换结构**。

### 4.3 切换的代价（必须验证的四件事）

1. **不重开标签页**：主题是文档级 + 全局级数据，切换只发 `Command::SetTheme`（已入撤销栈），
   标签页与卡片页不重建，滚动位置不丢（大纲 memo 的 `rev` 不动）。
2. **SceneCache 失效**：`scene.rs:1407` 已经比对**整份** `Theme`（`PartialEq`），换主题/改强调色自动失效；
   T4 只需补一条单测钉住「`accent` 变而 `id` 不变也失效」。
3. **大纲 memo 必须跟着失效**：`outline.rs:1995` 只比 `theme.id`，要改成「id + accent + 关键 ui 色」的
   轻量指纹（建议 `(id, accent, text, dim, hover, border)` 的 `u32` 哈希），否则色点停在旧色（M2）。
4. **渲染层不需要重建管线**：主题只改 uniform/顶点色与图集之外的参数；字形图集按 `ppd` 与 `face` 索引，
   与颜色无关，切换主题**不得清空图集**（否则首帧会闪一次全量重栅格化）。

### 4.4 对比度门怎么覆盖每一套

现状七条门（`crates/mw-core/tests/contrast.rs`）：
①`secondary_text_clears_aa_on_every_surface` ②`faint_text_stays_visible_but_never_becomes_body_text`
③`every_theme_keeps_branch_colours_visible_on_its_canvas` ④`text_levels_keep_wcag_aa_contrast`
⑤`the_theme_library_is_four_and_every_id_resolves` ⑥`ink_theme_is_aa_on_its_canvas`
⑦`the_new_dark_theme_uses_the_planned_tokens`。

扩展方案（T6，纯测试、零外观）：

- ⑤ 改写为 `themes().len() == THEME_IDS.len()` 且逐个 `get_theme` 可解析（删掉写死的 `== 4`，M4）。
- 遍历集合从 `themes()` 扩到 `themes()` ∪ `themes_for(doc)`，把概念图四套纳入 ①②③④（M3）。
- 新增 `user_themes_are_checked_after_legible`：用户主题加载后先跑 `legible()`，再断言 ①②③④；
  修正过的主题在 `MW_TRACE` 里记 `theme_corrected id=… field=… from=… to=…`，
  并在主题编辑器里显示一行「已自动压暗以保证可读」。
- 新增 `every_theme_has_unique_accent_and_canvas`：防止两套主题只差一个名字却同一套色（可选）。
- ⑦ 保留为「墨夜令牌不许漂」的历史钉子，不动。

## 5. 高清与可读性

### 5.1 现状（可核对）

| 事实 | 证据 |
| --- | --- |
| ppd 量化档 10 档，**向上取档** | `crates/mw-render/src/glyph.rs:34` · `const PPD_BUCKETS: &[f32] = &[0.5, 0.75, 1.0, 1.25, 1.5, 1.75, 2.0, 2.5, 3.0, 4.0];`，`quantize_ppd` 见 `:36` |
| 图集 3072²、单通道、灰度 1×1 | `glyph.rs:28` · `pub const ATLAS_SIZE: u32 = 3072;`；注释 `:24-26` 说明槽位与内存预算 |
| 键含 `ppd`，不同缩放不串用 | `glyph.rs:47-52` · `GlyphKey { face, glyph, font_size, ppd }`（`ppd: (ppd * 100.0).round() as u16`） |
| 真实字重 400/500/600 | `crates/mw-render/src/dwrite.rs` 的 `format(font_size, weight)` |
| 发丝边按 DPI 换算 | `design.rs:484` · `hairline: 1.0 / dpi,`（`content::content_metrics`，dpi 夹到 0.5–4.0） |
| 门的 DPI 覆盖 | stage-b 178 场：`Ppp 1.0` **89** 场、`1.5` **86** 场、`2.0` **3** 场；stage-cm 73 场：`1.0` 72、`1.5` 1。**1.25 档 0 场** |

### 5.2 四条规则

1. **描边按物理像素取整**：`物理px = max(1, round(css_px × dpi))`，再换算回点 `物理px / dpi`。
   1px 在 125% 下是 1.25 物理 px，若直接画会落在半像素上糊成两像素灰边——这条是 §5.3 的验收重点。
2. **字号不取整、只取档**：字阶保持整数 CSS px（11/12/13/…/30），栅格化按 `ppd` 桶向上取，
   采样用 Linear + 1×1 灰度（现路径）；**不允许**为了清晰把字号改成 `.5` 步进（会改字宽→全量重排）。
3. **1px 线不透明**：描边用实色（`border`），不用 alpha 极低的线去"柔化"——低 alpha 在 125%/175% 下会被
   重采样成更糊的一档。需要柔化时改色阶（`N9`），不改 alpha。
4. **导出与屏幕同源、不同采样**：SVG/PDF 走同一份 `Scene`（`canvas_bg` + `dot.blended`），按 1 CSS px =
   1 世界单位出图（等价 100% 缩放观感）；**不承诺**与 150% 屏幕逐像素一致，只承诺**几何与颜色同源**。

### 5.3 可测验收指标

| 指标 | 口径 | 判据 |
| --- | --- | --- |
| H1 描边不糊 | 125% 下 1px 竖线在 3 个相邻截面的灰度差 | 只允许「1 列深 + 1 列浅」；出现 3 列过渡判失败 |
| H2 文本不抖 | 同一文档在 1.0/1.25/1.5/2.0 下，行盒坐标（`MW_TRACE` 的 row y） | 缩放后坐标 = 1.0 的整数倍数，误差 ≤ 0.5 物理 px |
| H3 字重不塌 | 400/500/600 三档在 150% 下的笔画灰度均值 | 500 与 400 的均值差 ≥ 6%，600 与 500 ≥ 6%（否则 DirectWrite 退化成同一档） |
| H4 图集不重栅格 | 切主题/切标签后首帧 `glyph insert` 计数 | 0 新增（主题与颜色无关） |
| H5 降采样不二次 | 实际 ppd 与桶值 | `bucket ≥ 实际 ppd`（现有 `quantize_ppd` 已保证） |
| H6 导出同源 | 导出 SVG/PDF 的 `canvas_bg`、`dot` 混色、层级文字色 | 与 `Scene` 逐字段相等（字节级） |

**基线缺口**：1.25 档 0 场，T5 必须先补 12 张 1.25 基线（列表见 §6 T5），否则 H1/H2 无法回归。

## 10. 复算口径（可复现）

- 公式：`channel(c) = c/12.92 (c ≤ 0.03928) else ((c+0.055)/1.055)^2.4`；
  `L = 0.2126R + 0.7152G + 0.0722B`；`CR = (max(L)+0.05)/(min(L)+0.05)`。
  与 `design.rs` 的 `luminance` / `contrast` 逐行等价。
- 合成：`over(bg, fg, a) = round(bg*(1-a) + fg*a)`，alpha 取 `LIGHT_ALPHAS.text_faint = 0.68`、
  `text_secondary = 0.70`；暗色 `0.72 / 0.68`（`design.rs` 的 `LIGHT_ALPHAS` / `DARK_ALPHAS`）。
- 一级卡：`levels[1].fill` 若不透明则参与 G3；若 alpha==0 用 `canvas_bg`（现有四套都实色）。
- 链接色：`link_color` 的 5% 步进压暗最多 12 步，仍不过 4.5 则退 `text`。
- 本表数值由临时脚本一次算出（2026-11-02），脚本不在仓库；若要长期复跑，T6 把它翻译成
  `contrast.rs` 的一条 dump 测试（输出 `id, gate, surface, ratio` 的 TSV），而不是再养一份 Python。
