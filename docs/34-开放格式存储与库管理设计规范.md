# 34 · 开放格式存储与库管理设计规范

> 状态：**存储层已实现；设置面板 / 启动库门 / 卡片字号三项 UI 待做（见 §11.1 交接清单）** · 更新：2026-11-02 · 上游：05、33 · 下游：实现与验收
>
> 目标一句话：**把「织思自己的文件」换成「别的软件也打得开的文件」**——思维导图存成
> XMind 能开的 `.xmind`，概念图存成 CmapTools 能开的 `.cxl`，笔记统一 Markdown `.md`；
> 再加一个 Obsidian 式「库」（先选文件夹才能用、可多库切换）与统一设置（主题 / 库 / 卡片字号）。

---

## 1. 为什么改

`docs/05` 的 `.zmind` 是自研 ZIP + JSON 容器：思维导图和概念图都塞在里面，XMind / CmapTools
都打不开。用户离开织思，文件就成了孤岛。本文件把存储改成**三种开放格式、三个独立文件**：

| 内容 | 扩展名 | 外部可直接打开 | 容器 |
| --- | --- | --- | --- |
| 思维导图 | `.xmind` | **XMind**（2020+/Zen/8 兼容） | ZIP：`content.json` + `metadata.json` + `manifest.json` + `mindweaver.json` |
| 概念图 | `.cxl` | **CmapTools**（CXL 导入/打开） | 单文件 XML（CmapTools CXL） |
| 笔记 / 卡片 | `.md` | **Obsidian / 任意编辑器** | Markdown + YAML front matter |

**关键纪律**：三种文件**不是**一个统一容器，而是**各自独立的文件、各自的格式**（用户 2026-11-02 明确）。
不要把思维导图和概念图塞回同一个容器。

---

## 2. 保真策略：互通视图 + 保真槽

XMind / CmapTools 的模型比织思窄（缺逐节点样式、关系线端点、边界精确目标、概念分组、
命题注释……）。硬塞会丢数据。做法是**双写 + 权威槽**（与 `docs/33` §3 的 `conceptMap` 块同思路）：

- **互通视图**：按外部工具的原生 schema 写一份（XMind 的 `content.json` / CmapTools 的 CXL 标准元素），
  让 XMind / CmapTools 能打开并正确显示结构、标题、备注、标签、折叠、关系线、浮动主题、聚焦问题。
- **保真槽**：同一文件里再存一份织思的完整模型（`.xmind` 的 `mindweaver.json` 条目 / `.cxl` 的
  `<extra-properties-list>`）。外部工具**忽略**它，织思**优先读**它。

**读取优先级**：保真槽存在 → 用它（无损往返）；缺失 → 降级解析互通视图（结构/内容不丢，
织思扩展字段降级）。用户在 XMind / CmapTools 里改完另存 → 保真槽可能被丢 → 自动降级读互通视图
（优雅降级，不报错）。

**保真槽内容** = 与 `.zmind` 的 `content.json` **同构的 `FileDoc` JSON**，外面包一层
`{ docId, title, createdAt, content }`（`FileDoc` 本身不存标题，标题在 zmind 的 manifest 里，
开放格式没有 manifest，故入槽）。字段见 `docs/05` §2 / §4.3。

## 3. 思维导图 `.xmind`（XMind Zen 包）

### 3.1 ZIP 条目

| 条目 | 作用 | 谁读 |
| --- | --- | --- |
| `content.json` | XMind 互通视图（数组，一张 sheet） | XMind / 降级回读 |
| `metadata.json` | `{ creator: { name, version }, timestamp }` | XMind |
| `manifest.json` | `{ "file-entries": { ... } }`，列资源 | XMind |
| `mindweaver.json` | 保真槽（完整 `FileDoc`） | 织思（权威） |
| `Thumbnails/thumbnail.png` | 缩略图（可选） | XMind |

### 3.2 `content.json` 映射（织思 → XMind Zen schema）

| 织思 | XMind content.json | 保真度 |
| --- | --- | --- |
| `meta.title` | `sheet.title` / `rootTopic.title` | 全 |
| `node.text` | `topic.title` | 全 |
| `node.note` | `topic.notes.plain.content` | 全 |
| `node.labels` | `topic.labels` | 全 |
| `node.icon` | `topic.markers[{markerId}]`（key 反查 XMind marker） | 全 |
| `node.link` | `topic.href` | 全 |
| `node.collapsed` | `topic.branch = "folded"` | 全 |
| 子树 | `topic.children.attached` | 全 |
| 自由主题（`pos`） | `rootTopic.children.detached` + `topic.position{x,y}` | 全 |
| `relationships` | `sheet.relationships[{id,end1Id,end2Id,title}]` | 标题全；箭头/线色/虚线/线宽入保真槽 |
| `boundaries` | `topic.boundaries[{id,range:"(i,j)"}]`（目标→子项下标） | 近似；精确目标入保真槽 |
| `summaries` | XMind 双写（摘要子项 + `topic.summaries[{range,topicId}]`） | 近似；精确入保真槽 |
| `style` / `head` / `width` / `dashed` / `branchColor`… | **仅保真槽**（XMind schema 不稳） | 织思内全 |

> 反例（**不这样**）：把 `style`/`head` 等硬塞进 XMind 的 `style.properties`——XMind 各版本
> schema 不一致，写错轻则丢、重则打不开。这些进保真槽。

### 3.3 加载

`mindweaver.json` 在 → 反序列化为完整 `Document`（无损）；不在 → `content.json` 走互通解析
（复用 `mw-io::import_xmind` 的 `parse_zen`），丢失项降级。

## 4. 概念图 `.cxl`（CmapTools CXL）

### 4.1 结构（CmapTools CXL，`cmap.xsd`）

```xml
<cmap xmlns="http://cmap.ihmc.us/xml/cmap" xmlns:dc="...dc..." xmlns:dcterms="..." xmlns:vcard="...">
  <res-meta><dc:title>...</dc:title><dc:description>聚焦问题</dc:description>...</res-meta>
  <map>
    <concept-list><concept id label/></concept-list>
    <linking-phrase-list><linking-phrase id label/></linking-phrase-list>
    <connection-list><connection id from-id to-id isBidirectional/></connection-list>
    <concept-appearance-list><concept-appearance id x y width height font-size background-color border-color border-shape/></concept-appearance-list>
    <linking-phrase-appearance-list>...</linking-phrase-appearance-list>
    <connection-appearance-list><connection-appearance id arrowhead color thickness/></connection-appearance-list>
    <extra-properties-list>…保真槽…</extra-properties-list>
  </map>
</cmap>
```

### 4.2 映射（织思概念图 → CXL）

| 织思 | CXL | 保真度 |
| --- | --- | --- |
| 概念（`ConceptEntry`） | `<concept id label>` + `<concept-appearance x y>` | 全 |
| 命题（`PropositionEntry`） | 概念→`<linking-phrase label>`→概念（两条 `<connection>`） | 标签全 |
| 命题 `label` | `<linking-phrase label>` | 全 |
| 命题箭头 `head` | `connection-appearance.arrowhead`（`yes`/`no`/`if-to-concept`） | 近似 |
| 命题 `color`/`width`/`dashed`/`note` | `connection-appearance` + 保真槽 | 近似 |
| `focus_question` | `res-meta/dc:description` | 全 |
| 概念坐标 `x/y` | `concept-appearance x y` | 全 |
| 概念 `style` | `concept-appearance`（background/border/font）+ 保真槽 | 近似 |
| `pinned` / `groups` | **仅保真槽** | 织思内全 |

**命题→CXL 三元组**：CmapTools 的一条命题是「概念—短语—概念」。织思命题 `A --label--> B`
写成 `A →(connection)→ linking-phrase(label) →(connection)→ B`。无 `label` 时用空短语
（CmapTools 允许）或 `related to`。箭头方向经 `isBidirectional` + `arrowhead` 表达。

### 4.3 保真槽

`<extra-properties-list><properties-list id="mindweaver"><property><key>doc</key>
<value>{完整 FidelityDoc JSON，XML 转义}</value></property></properties-list></extra-properties-list>`。
加载时优先读它；缺失则解析 CXL 标准元素（降级）。

## 7. 库（Vault）—— Obsidian 式文件夹

### 7.1 语义

- **库 = 用户选的一个文件夹**，是文档（`.xmind`/`.cxl`/`.md`）的家。
- **先选才能用**：首次启动 / 无活动库 → 强制「选择或新建库」门，进入主界面前必须选定。
- **记住选择**：选定写入设置，下次打开直接进，不再问。
- **多库**：可建多个库、随时切换（像 Obsidian 的 vault 切换）。

### 7.2 库注册表

存 `%APPDATA%\织思\settings.json`（或独立 `vaults.json`）：

```json
{
  "vaults": [
    { "id": "…", "name": "我的知识库", "path": "D:/Notes", "createdAt": 1760000000000 }
  ],
  "activeVaultId": "…"
}
```

- `activeVaultId` 为空 / 指向不存在的库 → 启动门。
- 切换库 = 只改 `activeVaultId`，不动文件。
- 库内文件由文件系统承载（`.xmind`/`.cxl`/`.md`），库根可被 Obsidian / XMind / CmapTools 直接消费。

### 7.3 与既有「笔记库」的关系

`settings.notes_dir`（全局卡片库）升级为库的一部分：卡片 `.md` 也住在当前库里。
兼容：无库时回落到 `paths::notes_dir()`。

## 8. 统一设置（`settings.json` 扩展）

在 `docs/05` 既有设置之上新增（`#[serde(default)]`，老配置文件零迁移）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `theme` | `String` | 全局 UI 主题 id（**`snow`/`ink`/`mist`/`sand`**，即 `mw_core::theme::THEME_IDS`；设计稿旧命名 `mint`/`inkNight`/`forest` 作废），所有界面统一 |
| `cardFontSize` | `u16` | 卡片笔记编辑界面字号（12–32，默认 16） |
| `vaults` | `Vec<VaultEntry>` | 库注册表 |
| `activeVaultId` | `String` | 当前库 id；空 = 未选 → 启动门 |

设置中心分区：外观（主题 + 减少动画）/ 编辑（撤销、卡片字号）/ 自动保存 / 导出默认值 / 库（选择 / 新建 / 切换）。

### 8.1 落地细则（2026-11-02）

- **主题立即生效**：`Store.theme` 变更即 `apply_theme`（文档层）+ `chrome_of`（壳层）同步；
  未知 id 回落 `snow`。金样不拍主题切换过程（主题矩阵已有 `theme-*` 基线锁令牌）。
- **卡片字号缩放**：`k = card_font_size / 16.0`（16 = `content::READING_BODY.size` 基准）。
  `note_view::CardBody` 的字号/行高统一乘 `k`（标题、正文、引用同比缩放，保持排版比例）。
  `k = 1.0`（默认 16）时输出与现状逐字节一致——card-* 金样基线不漂。
- **库门**（`needs_vault()` 为真时启动先出「选择/新建库」门，选定才进主界面）：
  - 门上列出注册库 + 「打开文件夹」+「新建库文件夹」；选定写 `activeVaultId` 记住，下次不再问。
  - 文件夹选择走 `files::pick_folder`（`IFileDialog` + `FOS_PICKFOLDERS`，与现有 `open_zmind` 同一 COM 通道）。
  - **金样钩子**：harness（`--golden`）下自动播种一个演示库（`MW_VAULT_DEMO=0` 关闭），
    既有场景不撞门；`MW_VAULT_GATE=1` 强制出门拍 `vault-gate` 基线。
- **`notes_root` 优先级**：显式 `notes_dir` 非空 > 活动库根 > `paths::notes_dir()` 默认。
  库内卡片 `.md` 住库根（§7.3）；显式路径是用户覆盖，优先级最高，保证老配置行为不变。

## 9. 验收标准

1. 思维导图存成 `.xmind`，**XMind 能直接打开**并看到结构 / 标题 / 备注 / 标签 / 折叠 / 关系线 / 浮动主题。
2. 织思自己打开该 `.xmind` **无损**（`mindweaver.json` 往返逐字段一致，含样式/箭头/边界/概要）。
3. 概念图存成 `.cxl`，**CmapTools 能导入/打开**并看到概念 / 短语 / 连接 / 位置 / 聚焦问题。
4. 织思自己打开该 `.cxl` **无损**（保真槽往返一致，含 pinned/分组/命题注释）。
5. 笔记存成 `.md`，Obsidian / 编辑器可直接阅读（YAML front matter + Markdown 正文）。
6. 三种文件**各自独立**，不是一个容器；扩展名决定格式。
7. 首次启动强制选库；记住后不再问；可多库切换。
8. 统一设置可改全局主题、选库、卡片字号，立即生效。
9. 老 `.zmind` 仍能打开；全量测试 + 金样全绿（测试数与场次以 [`STATUS.md`](STATUS.md) §1 为准；UI 变更处按 `docs/29` §5 重拍基线）。

## 10. 不做 / 边界

- 不做 XMind / CmapTools 的**全部**特性（公式、音频、样式表命名等）——只保证互通视图正确 + 织思内无损。
- 不改 `.zmind` 容器本身（仍是 ZIP+JSON）；`.zmind` 降级为兼容格式。
- 协作 / 云同步仍为非目标（`docs/01` §5）。
- 保真槽被外部工具丢弃时**优雅降级**，不报错、不阻塞打开。

#### E. 决策点（写码前先定，别边写边猜）

1. **全局主题怎么落到当前文档**：§8.1 写的是「`Store.theme` 变更即 `apply_theme`（文档层）+ `chrome_of`（壳层）同步」，
   但 `apply_theme`（`app_methods_2.rs:1671`）走 `Command::SetTheme`，会 **revision+1、入撤销栈（label「更换主题」）**，
   与 `settings.rs` 头注释「设置是壳层的，不写进文档」有张力。三种落法：
   - (a) 照 §8.1：最省事，与标题菜单/命令面板同一入口；代价是改设置会把当前文档变脏，保存后主题随文件走。
   - (b) 只刷壳层：文档不动；但画布节点颜色来自 `session.theme`，会与壳层不一致，且下一帧 `sync_chrome` 会打回。
   - (c) 折中：有画布走 (a)，无画布直接刷 chrome。
   **无论选哪种，都要修 `sync_chrome` 的无画布回落**：现在硬编码 `get_theme("snow")`（`app_methods_2.rs:1702`），
   改成 `get_theme(&self.settings.theme)`，否则开始页改主题下一帧就回 snow。
   注意 `apply_theme` 入参是 `&'static str`（传 `THEME_IDS[i]`，别传 `&s.theme`）。
2. **后台标签页不跟主题**：`apply_theme` 只作用于活动画布。是否对 `self.tabs` 里的 doc 也发 `SetTheme`
   （会弄脏所有标签）或切标签后补发，§8 没写；先不做，记在这里。
3. **设置草稿持久化**：不先改成 `self.settings_draft`，主题 4 选、库行点击、字号滑轨都不会跨帧生效（见 A.5）。
4. **库门与 `home` 的关系**：门显示时侧栏/工具栏要不要一起藏？建议照开始页（`self.home`）的既有做法，
   门只接管中央面板，别新增一套「全屏模态」体系。
