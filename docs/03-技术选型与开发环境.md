# 03 · 技术选型与开发环境

> 状态：**当前** · 更新：2026-10-19（清理与交接轮） · 上游：01、02 · 下游：04、05、08
>
> 本文只描述**现在真正运行的栈**。2026-10-16 的 ADR-010 已否决 Tauri/WebView2 方案；旧选型文档已删除，历史结论见 `archive/12-历史注记-WebView路线.md`。
> 当前仓库**不再包含任何前端工程**（`ui/` 已删除），构建只需要 Rust。

---

## 1. 选型原则

1. **原生是硬约束**：产品进程里不出现 WebView / HTML / CSS / JS / Electron / Tauri。
2. **仅 Windows**：不做跨平台抽象；DWM、Mica、DirectWrite、IME、DPI 都按 Windows 语义实现。
3. **Rust 承载全部产品逻辑**：模型、命令、撤销、布局、渲染、文件、导入导出、壳层都是 Rust，可测试。
4. **依赖最小化**：每个直接依赖都要说明用途；不引入 GPL 系依赖。
5. **确定性**：画布与导出共用同一份 Scene；视觉基线可逐像素复现。
6. **中文一等公民**：输入法、换行禁则、字体回退、拼音检索是一级验收项，不是后期优化。

## 2. 技术栈（实际使用）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | **Rust stable**，edition **2021** | workspace 统一版本 `0.1.0` |
| 窗口 / 壳 | **eframe / egui 0.37** | 自绘标题栏、面板、菜单、对话框；没有系统 WebView |
| GPU 画布 | **wgpu 30.0.1**（锁定小版本） | 四层合成器：背景点阵 / 连线与边界 / 节点 / 覆盖层 |
| 文字 | **DirectWrite**（windows-rs 0.62） | 度量、整形、字形栅格；画布与编辑器共用一份几何 |
| 系统集成 | **windows-rs 0.62** | DWM/Mica、窗口消息、文件对话框、只读字体映射 |
| 数据 | serde 1 + serde_json 1 | `mw-core` 模型与 `.zmind` 内容 |
| 文件容器 | zip 9 | `.zmind` 是 ZIP：`mimetype` + `manifest.json` + `content.json` |
| 交换格式 | quick-xml 0.31 | OPML / FreeMind / XMind 导入 |
| 检索 | pinyin 0.10（heteronym） | 全拼 / 首字母 / 多音字展开 |
| 错误 | thiserror 2 | 各 crate 的错误类型 |
| ID | uuid 1（v4 + v7） | 文档/节点 ID |
| 测试图像 | image 0.25（仅 PNG） | golden 比对与差异热力图 |
| 性能探针 | 自写 + criterion（局部） | 只从 release 取数 |

**明确不用**：tauri、wry、任何 WebView 绑定、Node/pnpm、Svelte/TypeScript、Electron、Flutter、Qt。

## 3. 仓库结构

```
.
├─ Cargo.toml                 # workspace：8 个 crate
├─ crates/
│  ├─ mw-core/                # 领域层：模型/命令/撤销/主题/布局/Scene/检索
│  ├─ mw-format/              # .zmind ZIP 容器、原子保存、备份
│  ├─ mw-io/                  # 导入导出（MD/OPML/FreeMind/XMind/SVG/PDF）
│  ├─ mw-render/              # wgpu 合成器 + DirectWrite 文本 + 离屏渲染
│  ├─ mw-ui/                  # 与框架无关的手势/选择/吸附状态机
│  ├─ mw-shell/               # eframe 壳、画布、面板、快捷键、开始页、演示
│  ├─ mw-golden/              # golden 比对基建
│  └─ mw-probe/               # 性能/窗口探针辅助
├─ docs/                      # 设计、规格、状态、交接
├─ scripts/                   # 质量探针与打包脚本（见 scripts/README.md）
├─ shots/
│  ├─ golden/                 # 测试基线（不要手改）
│  ├─ reference/              # XMind 2026 只读参考截图（无 XMind 时看这里）
│  └─ qa/                     # 真实输入验收截图与夹具
├─ HANDOFF.md                 # 接手入口
└─ README.md
```

依赖方向（单向）：

```
mw-shell → mw-render → mw-core
mw-shell → mw-ui     → mw-core
mw-shell → mw-format/mw-io → mw-core
mw-golden（独立）
```

**禁止**：`mw-core` 依赖任何 GUI/窗口 crate；面板直接改 `Document`；导出器另写一套布局。

## 4. 开发环境

### 4.1 必备

- Windows 10/11 x64。
- Rust stable（`rustup` 管理），MSVC target。
- Visual Studio Build Tools（「使用 C++ 的桌面开发」+ Windows SDK）。
- 支持 DX12 的 GPU（wgpu 需要真实适配器；远程桌面/纯软件环境可能跑不了离屏测试）。

### 4.2 不需要

- Node.js / pnpm / npm（`scripts/make-sample.mjs` 只在生成大文档样本时需要 Node，可选）。
- WebView2 Runtime。
- XMind。**没有 XMind 完全不影响开发**；视觉基准见 `shots/reference/` 与 `docs/06`。
- 如果机器上恰好有 XMind：只用系统截图工具做只读对照，**不要点击/拖拽/关闭用户实例**；本仓库不提供、也不要新增会向 XMind 注入输入的自动化脚本（历史脚本已于 2026-10-19 清理轮删除）。

### 4.3 首次构建

```bash
rustup show                    # 确认 stable + msvc
cargo build --release -p mw-shell
```

首次会编译全部依赖，5–15 分钟后增量构建很快。产物：`target/release/mw-shell.exe`。

## 5. 常用命令

```bash
# 运行（开发用 debug；性能/截图必须 release）
cargo run -p mw-shell
cargo run --release -p mw-shell

# 全量测试（当前基线 412 项）
cargo test --workspace

# 格式与 lint（clippy 门槛：新增 0，不是总量 0）
cargo fmt --all -- --check
cargo clippy --workspace --all-targets

# 视觉基线（连跑两次，均为 0 差异才算过）
cargo golden --tol 0
cargo golden --tol 0

# 重拍基线（仅在确认是合法外观变更时）
cargo golden --update --warmup 5
MW_GOLDEN_UPDATE=1 cargo test -p mw-render --test offscreen -- canvas_matches_golden_baseline
MW_GOLDEN_UPDATE=1 cargo test -p mw-render --test text_render

# 便携打包（产物在 dist/，上传 GitHub 前不要提交）
powershell -File scripts/package-release.ps1
```

测试夹具/探针开关：

- `MW_HOME=0`：跳过开始页直接进文档（探针用）。
- `MW_OPEN=<path>`：启动即打开文档。
- `MW_WINDOW_STATE=off`：不读/不写窗口状态。
- `MW_TRACE=<file>`：输出焦点轨迹，供键盘探针断言。
- `MW_STATS=1`：FPS/帧时间浮层。
- `MW_GOLDEN_UPDATE=1`：重拍画布基线。

## 6. 测试与质量门槛

| 层级 | 内容 | 命令 |
| --- | --- | --- |
| 单元 | 模型/命令/撤销/级联/布局/文本/存储 | `cargo test -p mw-core -p mw-format -p mw-io` |
| UI 逻辑 | 选择、框选、拖拽、吸附 | `cargo test -p mw-ui` |
| 渲染 | 实例构建、离屏回读、文本布局 | `cargo test -p mw-render` |
| 壳层 | 交互状态、自动保存、快捷键、面板 | `cargo test -p mw-shell` |
| 像素 | 画布/文字/壳层三份 golden | `cargo golden --tol 0` |
| 真实输入 | 键盘/鼠标/前台窗口 | `scripts/v3-core.ps1`、`v5-*.ps1`、`v7-branch.ps1` |
| 性能 | 启动/帧率/内存 | `scripts/m5-*.ps1`，仅 release |

当前基线（2026-10-19 H2）：

- **412 tests**：core 138 / render 55 / shell 161 / ui 32 / io 14 / format 7 / golden 5。
- clippy 去重 **40 处 / 36 条**存量告警（rustc 1.98.1 工具链漂移）；**新增 0**。
- golden `--tol 0` 连跑两次通过（H2 壳层漂移 0.263% 已记录并重拍，画布基线未动）。
- 性能见 `docs/08 §9`；P13 内存 PASS 有余量 10.4MB 的限制条件。

## 7. 工程规范

- **先改 docs 再改代码**：新行为先写进 `docs/06`/`docs/02` 的验收，再实现。
- **面板只读**：`Canvas::session()` 提供只读会话；修改必须返回 `Action`/`Command`。
- **像素变化就要走 golden**：量化差异 → 判断合法性 → 重拍 → 连跑两次。
- **不做 emoji 图标**；图标用印刷符号或自绘。
- **性能数字只从 release 取**；debug 仅用于功能。
- **截图证据入库**：`shots/qa/`；基线在 `shots/golden/`，不要混用。
- **提交前**：test + fmt + clippy + golden（若改外观）+ 真实输入（若改交互）。

## 8. 国际化与许可

- 界面语言目前以简体中文为主；字符串集中在壳层，未做完整 i18n 框架。新增文案先写中文，保留以后抽取的可能。
- workspace `license = "MIT OR Apache-2.0"` 是**计划**；仓库目前**没有 LICENSE 文件**。添加双许可文件是项目负责人的决定，AI 不要擅自选择。
- 依赖许可证以 `cargo deny`/人工审计为准；不引入 GPL 系依赖。

## 9. CI 思路（尚未接入托管 CI）

最小流水线（Windows runner）：

1. `cargo fmt --all -- --check`
2. `cargo clippy --workspace --all-targets`（与基线比，新增 0）
3. `cargo test --workspace`
4. `cargo golden --tol 0`（需要 GPU runner；没有则跳过并标注）
5. `cargo build --release -p mw-shell`

真实输入探针不适合无头 CI，保留为本地验收。
