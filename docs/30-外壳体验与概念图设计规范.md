# 30 · 外壳体验与概念图设计规范

> 制定：2026-10-25 · 类型：设计合同 · 执行合同：[`docs/31`](31-外壳体验与概念图工作包.md)
> 上游公理：[`docs/28`](28-内容体验重构规范.md) §3（共同公理）、§4（共享设计系统）
> 触发：2026-10-25 用户实拍复评——「起始页太丑、功能不够、bug 多」「检查器像个玩具」
> 「新建只能建思维导图，要能建概念图（模仿 CMapTools），概念图节点也要能关联笔记」。

---

## 0. 一句话结论

**起始页重做成「工作台」而不是「宣传页」；检查器重做成「属性面板」而不是「调色盘」；
新增概念图这一种文档类型，用有向带链接短语的命题网承载概念之间的语义关系。**

三件事的共同病根是同一个：把「控件摆出来」当成了「界面做完了」。起始页在摆卡片，
检查器在摆色板，思维导图在摆节点。三者都缺**信息层级**、缺**密度纪律**、缺**动作按需出现**。

## 1. 为什么再来一轮（实拍结论）

### 1.1 起始页（`shots/golden/start/shell-ppp1.00.png`，1440×1000 @1.0）

| # | 症状 | 违反 | 判词 |
| --- | --- | --- | --- |
| S1 | 页面内容宽 1000，两侧各 220 空白，底部约 250px 全空 | `docs/28` §4.2 版心纪律 | 版心比内容需要的宽，重心漂浮，页面「没装满」 |

| # | 症状 | 违反 | 判词 |
| --- | --- | --- | --- |

### 1.3 概念图（缺口）

产品目前只有思维导图一种文档类型。思维导图表达「中心 → 分支」的层级，
表达不了「A 因为 B 才导致 C」这类**带语义的边**。用户要求新增概念图
（模仿 CMapTools 的 Novak–Gowin 式概念图），且**概念图节点要能像思维导图节点一样关联笔记**。

## 2. 范围与非范围

**在范围内**

1. 起始页 v2（`crates/mw-shell/src/start.rs`）。
2. 检查器 v2（`crates/mw-shell/src/panels/inspector.rs`）。
3. 概念图文档类型：新建入口、画布、连线与链接短语、整理布局、笔记联动、导出与往返。
4. 上述三块的 golden 场景、输入脚本、单测、证据包。

**不在范围内**

- 不重做大纲、卡片页、笔记库——它们是 Stage B2（`docs/28` / `docs/29`）的正文，本轮不动。
- 不改 `.zmind` 格式版本、不改 `Node`/`NoteCard` 字段；概念图复用既有字段（§5.2）。

  不做曲线连接线（先做直线，与 CMapTools 一致）。
- 不做云同步、多人协作、AI 生成概念图。

## 3. 起始页 v2 · 规范

### 3.1 信息架构

自上而下固定五段，顺序即优先级：

1. **品牌头**：图标 32 + 产品名 20/28 600 + 副标题 12/18 `text.secondary`（同一基线带内）。
2. **快速开始**：四张等高卡——**新建思维导图 / 新建概念图 / 打开文件… / 卡片笔记库**。
3. **最近文件**：区段标题 + 行列表 + 清除动作。
4. **模板**：十张卡分两组、同尺寸同间距——**结构模板 6 张**（思维导图、逻辑图、组织架构、鱼骨图、时间轴、**概念图**）；
   **内容模板 4 张**（空白、读书笔记、会议记录、产品规划）。每组前一行 11.5 `text.secondary` 组标题
   （「结构模板」/「内容模板」，非控件、不进 Tab 序）。
5. **提示行**：一行 32px，拖入说明 + 键帽；不再有独立大提示卡，不再有脚注行。

删除：底部两张 148/216 大提示卡、居中「本地优先」脚注、页面顶部的装饰性大留白。

### 3.2 几何与断点

| 元素 | 规格 |
| --- | --- |
| 版心 | `880 max`（原 1000），水平居中；两侧 ≥ 32 |
| 页面顶/底留白 | 40 / 40（原 ~64 / 大片空白） |
| 品牌头 | 高 44；图标 32；产品名 20/28；副标题 12/18 |
| 快速开始卡 | 高 72；间距 12；圆角 `radius::PANEL`；1px `hairline`；图标 20；标题 14/22 500；副标题 12/16 secondary |
| 最近文件行 | 高 44；图标 16；标题 13.5/20；路径 11.5/16 secondary；右时间 11.5/16 secondary（**不用 faint**） |
| 模板卡 | 高 88；结构图标 28；名称 13.5/20 500；说明 11.5/16 secondary；右上键帽 11.5 |
| 模板组标题 | 高 18；11.5/16 secondary（与卡片左缘对齐，非控件） |
| 提示行 | 高 32；12/16 secondary + 键帽 11.5 |

断点（全部收进 `start::layout(avail)`，单点判定 + 单测）：

| 可用宽 | 快速开始 | 模板列 | 最近文件行数 |
| --- | --- | --- | --- |
| ≥ 900 | 4 列一行 | 3 列 | 8 |
| 640–899 | 2×2 | 2 列 | 5 |
| < 640 | 1 列纵排 | 1 列 | 3 |

- 卡片宽度不足时**不横向溢出**：卡片内文字按可用宽截断，副标题 12/16 单行省略。
- 页面纵向滚动；窗口最小 640×460 时不出现横向裁剪与文字压边。
- 快速开始卡与模板卡等高成行；不同高度的行一律拉平（`align` 到同一基线网格）。

### 3.3 视觉与颜色

- 页面底 `surface.page`；卡片底 `surface.panel`；**无阴影**（仅 `hairline` 1px 描边）。
- **主作用卡**（新建思维导图）：`surface.panel` + 8% 强调底 + 强调色图标；
  **禁止整块强调色实底**（取代现在的绿色 hero）。
- 图标全部走 `design::icon`：`Icon::New` / `Icon::ConceptMap`（新增） / `Icon::Open` / `Icon::Library`。
- 模板卡用**结构图标**（新增 6 个：Mindmap / Logic / Org / Fishbone / Timeline / ConceptMap），
  统一 28px、单色、1.5px 主描边；**不再手绘五张彩色示意图**。
- 选中/hover：卡片 hover 4% 底；键盘焦点 1.5px 强调环画在卡外侧 2px；
  主作用卡的焦点环画 2px 内侧浅色环（避免同色叠同色）。
  实现（SE-03）：环色取 `tone.ch.accent`，2px、`rect.shrink(1.0)` + `StrokeKind::Inside`；
  实测卡内 1–2px 是强调色 (47,111,94)，卡外四方向 4px 全是页底 (244,241,235)、0 个强调色像素
  （`shots/x100/SE-03/ring-probe.txt`）。外侧 `paint_focus_ring` 对主卡不再叠加。

### 3.4 状态

| 状态 | 表现 |
| --- | --- |
| hover | 卡 4% 底 + 指针手型 + `trace::name` |
| 键盘焦点 | 1.5px 强调环（主卡内侧 2px 浅色环） |
| 激活 | 无按下缩放；按下 90% 底 |
| 最近文件缺失 | 保留行，标题 secondary，路径标「文件已移动」，点击走打开失败态 |

> 落地（SE-04）：以前启动时 `Recent::prune_missing` 直接把缺文件的行**删掉**——用户只会看到
> 「少了一条」。现在 `mark_missing` 只在载入/触摸时标一次（每帧 stat 八条磁盘没必要），
> 行留着：标题转 secondary、副行「文件已移动」、点它走既有打开失败弹窗（弹窗里有
> 「从最近列表移除」，那才是真正要删的时候）。缺失标记只进内存，`recent.json` 语义不变。
| 最近文件为空 | 左对齐两行：标题 13.5/20「还没有最近文件」+ 说明 12/16 secondary「打开或新建后，会在这里快速回来」；**不放重复的打开按钮** |
| 加载中 | 行骨架（3 行，1px hairline 占位），不转圈 |

> 落地（SE-02）：最近文件**异步读盘**（`recent::Recent::load_async`），首帧画 3 行骨架；骨架与三行真列表
> **同高**（`recents_height(3)`），到货时不跳段，且不吃点击。加载中不显示「清除列表」——没有可清的东西。
> 金样要确定：harness 里仍同步读，用 `MW_RECENTS_PENDING_FRAMES=<n>` 假装「还没读完」，`start-skeleton`
> 才拍得住（那一帧必须落在预算之内）。证据 `shots/x100/SE-02/`。
| 模板不可用 | 该卡 disabled：11.5 secondary + 无图标高亮，Enter 不响应 |

### 3.5 键盘与焦点

- Tab 顺序：快速开始四卡 → 最近文件行 → 清除按钮 → 模板十卡（结构 6 + 内容 4）→ 提示行。
  实现注（SE-03）：**提示行不是控件**（它是一行按键说明，没有可执行动作），
  所以 Tab 到模板十卡之后绕回主卡，不把焦点交给提示行——给不可操作的文字套焦点环是另一种糊弄。
  其余顺序由「注册顺序」保证：清除按钮在视觉上仍是区段标题行右边，但直到最近文件行画完才
  `ui_kit::text_button_at` 注册（`start::recents_section`），轨迹 `shots/x100/SE-03/tab-order.txt` 钉住。
- Enter / Space 等价点击；`1`–`9` 与 `0` 直选模板（概念图为 6，产品规划为 0）；`Ctrl+O` 打开；`Ctrl+N` 新建思维导图；
  `Ctrl+Shift+N` 新建概念图。
- 窗口级 Enter 新建只在**没有任何控件聚焦**时生效。
- 出现开始页时若无控件持焦，自动聚焦「新建思维导图」；从菜单进入时焦点也回该卡。
- `Esc` 仍只负责返回文档（仅菜单进入时）。

### 3.6 概念图入口

| 入口 | 行为 |
| --- | --- |
| 快速开始「新建概念图」卡 | 新建空白概念图文档（`LayoutSettings.kind = "conceptMap"`） |
| 模板第 6 张「概念图」 | 新建**带示例结构**的概念图（3 层 6 概念 + 2 条交叉连接） |
| 文件 → 新建 → 概念图 | 同上两项 |
| 快捷键 | `Ctrl+Shift+N` |

四个入口在 SE-03 收口：开始页按 `Ctrl+Shift+N` 直接建概念图（轨迹 `home new concept kind=conceptMap`），
文档里按则新开一张概念图标签页（`home new concept source=shortcut`）；文件菜单同一动作。
**判别顺序**：`NewConcept` 必须排在 `New` 之前——egui 的 `matches_logically` 只查「模式要 Shift 而没按」，
按下 `Ctrl+Shift+N` 同样满足 `Ctrl+N` 的模式，先判 `New` 会被它吃掉（单测
`the_shifted_chord_is_swallowed_by_the_plain_one_unless_judged_first` 钉住）。

### 3.7 起始页禁止项

- 禁止整块强调色实底卡；禁止 5 张以上同形手绘预览；禁止彩色示意图配色。
- 禁止 148/216 大提示卡；禁止居中脚注；禁止装饰性大留白。
- 禁止用弱灰（`text.faint`）承载时间、路径这类必须读到的信息。
- 禁止在开始页塞入第二个界面的主任务（不做最近文件搜索、不做笔记预览）。
- 禁止在开始页放「刷新」「设置」按钮。

### 3.8 验收场景

`start`（1440×1000 @1.0，`MW_HOME=1 MW_START_DEMO=1`）、`start-narrow`（720×620 @1.5）、
`start-scroll`（640×460 滚动到底）、`start-tab-focus`（Tab 到模板）、
新增 `start-concept`（1440×1000，鼠标停在「新建概念图」卡上，hover 态）、

新增 `start-templates-content`（1440×1000，两组模板标题 + 10 张卡全览，SE-12）。

## 4. 检查器 v2 · 规范

### 4.1 结构

自上而下：对象行 → 分段控件 → 分组列表 →（底部）面板级动作。

| 元素 | 规格 |
| --- | --- |
| 面板宽 | 默认 **288**（原 420），可拖 240–360，记忆；与画布之间 1px `hairline` |
| 头行 | 高 40：「检查器」12/16 secondary + 右侧关闭图标按钮 24 |
| 对象行 | 高 44：节点标题 13.5/20（省略）+ 副行 11.5/16 secondary（`一级主题 · 2 个子主题`；多选时 `3 个节点`） |
| 分段控件 | 高 30，三段（样式 / 内容 / 标记）：选中 8% 强调底 + 底部 1.5px 强调条，文字 12.5/18 500；**无描边胶囊** |
| 分组标题行 | 高 28：chevron 12 + 名称 12/16 500 + 右侧摘要 11.5/16 secondary；组间 8px hairline 分隔 |
| 组内 | 上下 8、左右 12；控件行高 28；行间距 6 |

默认展开：样式组（颜色、文本、边框与形状）；内容组（文本内容、任务、标签、链接、卡片）；
标记组折叠。折叠状态记忆到设置。

### 4.2 控件规格

| 控件 | 规格 |
| --- | --- |
| 色板 | 8 列 × 24px 圆点，列距 8；选中点 2px 强调环 + 1px 内白；第 9 格「自定义」虚线圆；另有「无颜色」斜杠格 |
| 数值 | stepper 24 高、宽 72 右对齐：`- 值 +`；字号 12–96、边宽 0–8、圆角 0–24（步 2）；标「已覆盖」圆点，↺ 恢复继承 |
| 字重 | 三段分段控件 **400 / 500 / 600**（数字直接写字面，不译成「常规/中等/半粗」）；旁边的 B 是它的二值快捷方式（开 600 / 关 400），U 开关控制下划线形态（SE-13） |
| 文本对齐 | 三段分段控件「左 / 中 / 右」，不用下拉（图标集里没有对齐图标，用汉字更省解释） |
| 形状 | 四段分段控件 **圆角 / 直角 / 胶囊 / 椭圆**；下划线不做第五段——240 面板下五个 12.5px 汉字格放不下（每格 42px < 三字 37.5px + 边距），所以它是 B / I 同排的 U 开关（SE-13） |
| 开关 | 28 高行，左标签 12.5/18 + 右侧 32×18 轨道开关（无边框） |
| 文本域 | 备注多行：3 行起、超过 8 行可展开；无白底无框，靠 `hairline` 底线 |
| 标签 | 纯文字 `12.5/18` + 6px 色点；输入框加标签后回车提交；**无 chip 墙** |
| 卡片绑定 | 三态：无绑定 → 「新建卡片」/「关联已有」/「解绑」；已绑定显示卡片标题 + 来源 |
| 作用域 | 分组标题右侧两段文字切换「本节点 / 含子树」11.5/16，选中 8% 底 + 强调色文字 |

**必选能力清单**（当前缺失项是「像玩具」的功能根因）：
颜色（填充/分支线/文字）、字号、字重（400/500/600）、文本对齐、边框宽度、圆角、形状
（矩形/椭圆/圆角矩形）、节点图标、节点备注、节点任务三态、节点链接 URL、节点标签、
节点 ↔ 卡片绑定、子树批量作用域。

> **14 项全部 `已实现`（2026-11-02，SE-13 补齐最后四项：字重 / 对齐 / 圆角 / 椭圆）。**
> 逐项落地与证据见 [`shots/x100/SE-10/report.md`](../shots/x100/SE-10/report.md) §4 与
> [`shots/x100/SE-13/report.md`](../shots/x100/SE-13/report.md)；字段例外的决定见 `docs/32` §15。

### 4.3 命令与反馈

- 全部改动走 `mw_core::Command`，一次操作一条撤销；连续拖滑杆/连点 stepper 在 500ms
  内合并为一条撤销。
- 改动**即时反映**到画布，不设「应用」按钮。
- 无选中节点：不显示属性控件，只显示一句话 + 文字动作「选中第一个主题」。
- 命令失败：面板内 28px 错误条 + toast，不静默吞掉。

### 4.4 键盘

- `Ctrl+Shift+I` 开合检查器；面板内 Tab 依次进入分组控件；↑↓ 在色板内移动、Enter 选择；
  `Esc` 先退出当前控件，再退出面板。
- 每个可改属性都有键盘路径；色板用数字键 1–9 直选。

### 4.5 检查器禁止项

- 禁止 420 宽大面板 + 大留白；禁止描边胶囊 tab；禁止三处重复的整行「自定义…」按钮。
- 禁止「应用 / 重置 / 确定」三件套；禁止把属性藏进二级弹窗。

## 5. 概念图 · 规范

### 5.1 定义

概念图 = **命题网络**。节点是概念（名词短语），边是**有向且带链接短语**的命题
（「A 因为 B」「A 导致 C」）。与思维导图的根本差别：

| | 思维导图 | 概念图 |
| --- | --- | --- |
| 结构 | 一棵中心辐射的树 | 允许多根、允许交叉、允许成环的网络 |
| 边 | 父子关系，无语义 | 有向边，**必须有链接短语** |
| 布局 | 自动树布局 | 自由摆放为主，另给一次「整理布局」 |
| 用途 | 拆解一个主题 | 表达一个领域里的因果/条件/对照关系 |

### 5.2 数据契约（不改 `.zmind`）

- 文档类型：复用 `LayoutSettings.kind`，新增取值 `"conceptMap"`。
  `kind` 已是自由字符串（`crates/mw-core/src/model.rs`），**不需要新字段、不需要版本号变更**。
- 概念节点：复用 `Node`，`parent_id = None`（浮动概念）+ `pos` 自由坐标。
  `Document.root_id` 仍指向第一个概念（保证既有不变量成立），但布局不依赖它。
  例外条款（CM-04 定）：**概念图的主概念也带 `pos`**——它是「第一个概念」，不是树根，
  必须能拖、能被整理布局摆位；`validate` 只在 `kind == "conceptMap"` 时放行，
  切回树布局时 `SetLayout` 会把这个 `pos` 交出来（否则旧不变量立刻判脏）。
- 概念之间的关系：复用 `Node.relationships`（`{ id, to, label, color }`，有向、带标签、带颜色）。
  **不用 `parent_id`/`children` 表达层级**——那会把树语义漏进概念图。
- 概念 ↔ 笔记：复用 `Node.card_id` 与 `NoteCard`，语义与思维导图节点完全一致。
- 标签、图标、备注、任务：复用 `Node.labels` / `icon` / `note` / `task`。
- **禁止**：新增字段、`.zmind` `FORMAT_VERSION` 变更、迁移脚本。
  **例外（2026-11-01 用户拍板，CM-16）**：`Relationship` 新增三个**可选键**
  `dashed` / `width` / `note`（§5.4.3，字段论证见 `docs/32` §12）。
  仍然不升 `FORMAT_VERSION`、不做迁移：缺键读成默认值，默认值不落盘，
  旧版本读新文件只会忽略这三个键。
  **第二个例外（2026-11-01 用户拍板，CM-18）**：顶层键 `groups`（概念分组，§5.5.1，
  论证见 `docs/32` §13）。空数组不写，缺键读成「没有分组」，同样不升版本。
  除此之外的字段一律仍然禁止。

### 5.3 节点

| 属性 | 规格 |
| --- | --- |
| 形状 | **椭圆**（2026-10-30 改，§12 第 9 条）：椭圆盒 = 文本盒按 **1.22（横）× 1.16（纵）** 外扩，**文本盒本身不变**——换形状不改折行、不改省略号阈值、不改 tooltip 判定。圆角矩形仍是可选形状（检查器「形状」四格之一：圆角 / 直角 / 胶囊 / 椭圆；下划线是 B / I 同排的 U 开关，见 §4.2），老文档缺 `shape` 键或写 `rounded` 时照旧画圆角矩形 |

| 卡片关联 | 右下 5px 圆点（与大纲一致），hover 出提示「已关联卡片：xxx」 |

> 「悬停 4% / 选中 8% 强调色」先铺一层淡底再画环（`instances::SELECT_FILL/HOVER_FILL`），
> 深色或彩色节点上的选中不再只靠一圈细线表达。底色在文字与内容之下，不改变可读性。

#### 5.3.1 省略、tooltip 与卡片圆点（CM-09 口径）

- **省略**：概念文字最多 2 行（`CONCEPT_H2` = 52 高），超出的行不再画，末尾按 CJK 禁则省略；
  一个字都没被截掉的盒子**不出 tooltip**（「有 tooltip」必须等于「真的被截了」）。
- **tooltip**：指针在节点上停 **400ms** 才出现（与行握把的 120ms 分开，避免扫过一堆节点时闪卡）。
  位置 = 节点盒下缘 +8px 居中，超出窗口右侧就贴右、超出下缘就翻到上缘。
  样式 = `surface.overlay` 底 + 1px `ui.border`、圆角 8、内距 8/10、11.5/16 `ui.text`，
  最大宽 320（超出换行，最多 6 行，再超出省略）。内容 = 概念全文（含未显示的行）。
- **卡片圆点**：`card_id` 存在时在**右下角内侧**画 5px 实心圆（颜色 = `content.marker`，
  与大纲行尾圆点同一颗）。悬停该圆点（或节点）时 tooltip 改为「已关联卡片：{卡片标题}」，
  卡片标题取不到时退回「已关联卡片」。圆点不是按钮，不做 hover 变色、不抢节点命中。
- 节点同时被截断又有卡片时，**一条 tooltip 只出现一次**：优先「已关联卡片：…」，
  概念全文放在第二行（`\n` 分两行画）。

#### 5.3.2 画布选中三档与键盘焦点（X27 增补，2026-11-02）

> 起因：X27 状态表（`shots/x100/X27/report.md` §3）查出**画布主选**与**画布键盘焦点**两格没有任何
> 视觉定义——代码里「所有被选中的节点完全一样」，多选时看不出哪一颗是主选；键盘遍历也没有焦点环。
> 本节把这两格补上，作为 X27 动码轮的验收依据。状态：**合同已定，实现未开始**（见 `docs/STATUS.md` §4.3）。

| 状态 | 规格（思维导图与概念图共用一套） | 与已有口径的关系 |
| --- | --- | --- |
| 选中（非主选） | 强调描边 **1.5px** + 强调底 **5%** | 概念图 §5.3 的「选中 1.5px + 8%」是**主选**那一档，8% 只给主选 |
| 主选（primary） | 强调描边 **2px** + 强调底 **8%** | 大纲行同构（主选 7% / 非主选 5%），画布不另创比例 |
| 键盘焦点 | 强调色 **80%** 的 **1.5px** 环，画在节点盒外 **1px**；只在键盘导航时出现 | 与 `docs/28` §4.6「焦点环 1.5px 强调色 80%，外偏移 1px」逐字对齐；与检查器口径一致 |
| 编辑中 | 不画选中环与焦点环，由 egui 在盒外 2px 画编辑描边（走 `corner_style`，椭圆也贴边） | 沿用 SE-13 的 `corner_style` 单一判定 |

规则：

- **主选唯一**：多选里恰有一颗主选（最近一次点/键盘落点的那颗）；三条选中道（节点 / 关系线 / 注解）
  互斥这条不变量不变（M26）。
- **悬停不是选中**：悬停仍是 1px + 4%（§5.3），不与上述三档混用；hover 在 golden 里必须用
  `MW_GOLDEN_INPUT` 脚本驱动，不许赌指针状态。
- **检查器多选**：头行必须显示「主选标题 + N 个节点」，点某一颗即改主选；只在空白处多选时
  头行显示「N 个节点」且不给主选切换入口（本项为 X27 缺口 G3，合同已定，实现未开始）。

### 5.4 连线与链接短语

| 属性 | 规格 |
| --- | --- |
| 线 | 直线段，线宽 1.5（屏幕空间恒定） |
| 箭头 | 端点实心三角形，**按屏幕空间恒定画**：尖端锚在连线终点、指向不动，长度不少于 7 css px，只放大不缩小（`instances.rs::screen_arrow`）。`Scene` 里存的是 6×4 世界单位基准，缩放补偿只在渲染层做——`Scene` 必须与缩放无关。四档端点语义（无 / → / ← / ↔）在任意缩放档位都必须能分辨 |
| 颜色 | 默认 `text.secondary` 6% 强调色的描边色；跨分支连接用来源分支色（按 `palette.len()` 取模，内置主题 6–8 色） |
| 链接短语 | 线中点画 20px 高胶囊：`surface.page` 底、无描边、11.5/16 secondary，线在标签处断开 8px |
| 空短语 | 只出现在「新建连线、还没填」的编辑态：画 12px「＋ 链接词」faint 占位。**既有命题不许清空**——模型层 `SetRelationshipLabel{label: None}` 在概念图返回 `Invalid("概念图的连接短语必填")`，壳层保留原短语并提示（打磨轮 40 / C16） |
| 编辑 | 双击短语就地编辑（同一套行内编辑契约：本地草稿、Esc 还原、Enter 提交、IME 组合不提交） |
| 交叉 | 允许两条线交叉；交叉处不画「跳线」，改用轻微弧度（曲率 ≤ 8px）区分 |
| 环 | 允许有向环（概念图常见），布局与遍历必须能处理 |
| 选中互斥 | 关系线 / 概念节点 / 注解三条道**只允许一条非空**；选中关系线后按方向键、框选、切回标签页或从检查器选概念，都会先清掉关系线选中。`Delete` 只删当前道（关系线优先于注解、注解优先于节点），一次按键不跨道（打磨轮 49 / M26 落地，轨迹 `selection_clear` / `delete_dispatch`） |

#### 5.4.1 跨分支取色与交叉微弧（CM-09 口径）

**跨分支取色**——「分支」在概念图里只有一种定义，与大纲/导出的生成树同源
（`mw_core::concept_tree::concept_rows`）：

- 每个概念的**分支号** = 它在生成树里最高的那个祖先（`depth == 1` 的行）的出场序号；
  主概念自己（`depth == 0`）与孤立概念各自算一个分支。
- 连线两端分支号**相同** → 用默认色 `theme.ui.dim`（persistent 的 `text.secondary` 口径）。
- 两端分支号**不同** → 判为跨分支连接，取**来源端**（`from`）分支号 →
  `theme.palette_at(branch % palette.len())`（按色板长度取模，内置主题 6–8 色，与一级分支同色系）。
- 用户显式设过 `relationships[].color` 的，**永远优先**，不被这条规则覆盖。
- 颜色只在绘制层算，**不写回文档**（`.zmind` 里仍是 `None`），导出/往返不受影响。

**交叉微弧**——两条连线在屏幕空间相交时，不能画成「一个 X 看不出谁在上」：

- 判定只看同层的两条直线段的**真交点**（端点相接不算，夹角 <12° 的近平行也不算）。
- 每条线最多让一次：**先声明的那条保持直线**，后一条在**中点**朝垂直方向偏 `6px`
  （上限 8px，即 `min(6, len/12)`），用一段二次曲线接回终点；箭头按终点切线重算。
- 偏的方向固定取 `同号`（`from` 在 `to` 左侧时朝上偏），保证同一份文档两次渲染一致。
- 短语胶囊跟着曲线上 `t = 0.5` 的点走，仍然压在线上、线在标签处断开 8px。

#### 5.4.2 连接的入口与手势（CM-14，2026-11-01）

CmapTools 里「连线」是概念图的第一动作。织思此前只有一条路：把指针挪到概念四边的 7px 锚点上拖出来。
节点右键菜单里没有连线项，`Ctrl+L`（思维导图的「插入关系线」）在概念图里被**显式拒绝**
（`begin_relationship_action()` 开头 `if self.concept_map() { return false }`）。结果是「连线」这个能力
技术上存在、实际上不可发现——用户原话：「概念图之间不是有联系吗，连线，目前不具备这样的能力」。

四个入口，语义一致：都落成一条 `AddRelationship`，落盘后立刻立起短语编辑框，未填短语整条撤掉（§5.9）。

| 入口 | 手势 | 结果 |
| --- | --- | --- |
| 拖锚点 | 悬停概念 → 四边 7px 锚点 → 拖到另一概念 | 建边 + 短语编辑（CM-03 既有） |
| 拖到空白 | 同上，松手在空白处 | 落点新建概念 + 建边（CM-10 ①） |
| 连线态 | 选中一个概念 → `Ctrl+L` / 右键「连接到…」→ 点另一个概念 | 建边 + 短语编辑；`Esc` 或再按一次退出 |
| 直连 | 选中两个概念 → `Ctrl+L` / 右键「连接这两个概念」 | 直接建边 + 短语编辑（源 = 场景顺序靠前的那颗，同一份文档两次操作结果一致） |

失败口径不许静默：

- 0 个选中：「先选中一个概念，再连线」；≥3 个选中：「连线只连接两个概念」；
- 自连：core 的守卫照旧拒绝（`Invalid("不能把节点连接到自身")`），壳层把它显示在提示条上；
- 连线态里点到源概念本身 = 取消（`rel_link_step` 既有），不是「连自己」。

**节点菜单的「新建概念」也按 CmapTools 改语义**：从概念出发新建的应当是**连着的**概念
（`AddLinkedConcept`，一步撤销，落点在被选概念下方一个层距），
不连的独立概念另给一行「新建独立概念」。此前只有「新建概念」= 落一个浮动概念，
和思维导图的「新建子主题」在结果上一样（多一颗孤立的盒子）——这正是「概念图被做成思维导图」的来源之一。

**关系线菜单补「反向连接」**：`Command::ReverseRelationship { from, id }` 把这条边从 `from` 名下挪到
`to` 名下、`to` 改成 `from`，短语与线色原样保留，**箭头档位不镜像**——`arrow` 恒指 `to` 端，
两端对调后箭头自然落到另一颗概念上，这正是「反向」该看到的画面（若在这里把 `Forward` 翻成
`Backward`，箭头会留在原地，用户点完看不出变化）。一条撤销记录。
理由：写反的命题（「A 导致 B」其实想说「B 导致 A」）不该靠删掉重画。
思维导图里同样可用，但目标端已有同向边时拒绝（树图仍守「一对节点一条边」）。

**短语建议（CmapTools 的 linking-phrase 下拉）**：短语编辑框里输入 ≥1 个字时，在框下方列出
**本图已用过的**链接短语（去重、按前缀过滤、频次高的在前，最多 6 条），`↑`/`↓` 选择、`Tab` 采用、
点击采用；采用 = 填字并提交，与 `Enter` 同一条路径。`IME` 组合期间不出建议、不吃 `↑`/`↓`。
它只读文档、不写文档；建议来源是「这张图自己的词汇」，不做词典、不做跨文档推荐。

#### 5.4.3 线型、线宽与命题注释（CM-16，2026-11-01）

`docs/30` §12.2 的复审把「关系线线型 / 线注释」列为缺口；用户 2026-11-01 拍板「先做这两项」。
它们都需要在 `.zmind` 里加**可选键**，因此先落本节再动代码（`docs/32` §12 是字段提案与兼容性论证）。

| 属性 | 规格 |
| --- | --- |
| 线型 | **实线 / 虚线**两档。虚线用来表达「暂定 / 推测」这类弱命题——用户不必为了标注不确定再造一个短语 |
| 虚线节奏 | **6 实 4 空，世界单位**（`mw_core::scene::REL_DASH`）。为什么不用屏幕像素：`Scene` 必须与缩放无关（§5.4 不变量），而虚线是几何——SVG / PDF 直接照这个节奏画，屏幕与导出才逐段对得上。代价：缩到 20% 时 6 世界单位 ≈ 1.2 css px，看起来接近实线；那个档位本来也读不出线型 |
| 线宽 | **三档**：细 1.0 / 标准（跟随主题 1.5）/ 粗 2.5，**屏幕空间恒定**（与 §5.4 的线宽口径一致，渲染层按 `css_to_world` 换算）。不做连续滑杆：288 面板上既挤又难精确 |
| 命题注释 | 给这条命题挂一段解释（「2026Q3 的数据」）。**不是**链接短语：短语是谓词、必填、进检索标题；注释可以长、不参与「命题」的读法、**不进检索标题**。长度上限与节点备注同一条（`MAX_NOTE_LEN`），空串归一成「没有」 |
| 注释的画布表现 | **不画角标**。命题已经有一条线和一枚短语胶囊，再加一颗点会把「线在标签处断开 8px」的留白吃掉；注释只在检查器里读（选中该线即可见）。这条是刻意取舍，不是遗漏 |
| 入口 | 检查器「关系线」页：线型两段、线宽三档、注释多行框（失焦提交）；右键关系线 →「线型」子菜单（实线/虚线，当前档打勾） |
| 导出 | PNG / SVG / PDF 三处同源：线宽从 `SceneRelationship.width` 读，虚线由 `SceneRelationship.dashed` 决定——SVG 写 `stroke-dasharray`，PDF 写 `[6 4] 0 d`，wgpu 在渲染层把曲线切成实线段 |
| 撤销 | 三个属性各一条命令（`SetRelationshipDashed` / `SetRelationshipWidth` / `SetRelationshipNote`），一次撤销一步；反向连接与撤销/重做都会把它们**原样带走** |
| 默认值 | 实线 / 跟随主题 / 无注释；三者**都不落盘**（`skip_serializing_if`），旧文件读出来就是默认值，不升 `FORMAT_VERSION` |

**禁止**：

- 禁止把注释当短语用（不写进命题的读法、不进检索标题、不在画布上代替短语）。
- 禁止为虚线引入第三种线型（点线 / 双线）；要加先改本节。
- 禁止让虚线节奏随缩放变化（`Scene` 与缩放无关）。

#### 5.4.4 多选命题（CM-17，2026-11-01）

CmapTools 允许一次选中一片链接再批量处理；织思此前 `Canvas.relationship` 是**单数**
（`Option<RelationshipSel>`），「删掉这 5 条暂定命题」只能一条一条删。

| 项 | 规格 |
| --- | --- |
| 选中模型 | `RelationshipSelection`：**顺序 = 选中顺序，最后一条是主选**。空集 = 没选 |
| 加选 / 减选 | `Ctrl` 或 `Shift` + 点击另一条线；已选中的再点一次 = 移除（框选错了撤一条） |
| 清空 | 点空白 / 点节点 / 点注解 / `Esc`（沿用 §5.4 的「三条道互斥」） |
| 主选的用途 | 检查器**单条页**只在选中 1 条时出现；右键菜单的勾、`F2` 改短语都只作用于主选 |
| 批量页 | 选中 ≥2 条时检查器切「N 条命题」页：箭头四格 / 线型两段 / 线宽三档 / 删除 N 条 / 取消选择 |
| 批量命令 | 每项都是**一条 `Command::Batch`**：一次撤销把 N 条一起退回去（`batching_relationship_style_is_one_undo` 钉住） |
| 只给单条的两项 | **链接短语**与**命题注释**是每条命题自己的文本，多选时不给入口——一次改 5 条短语没有意义，给一个改不动的控件比不给更糟 |
| 反向 | 多选时逐条反向，选中集跟着换主人（`from → to` 变 `to → from`） |
| 画布表现 | 每条选中的线都画 3px 实色强调（与单选同一段绘制，只是集合更大） |
| 菜单文案 | 「删除 N 条关系线」；`编辑关系线标签` 在多选时禁用 |

**未做（写清楚，别当已完成）**：

- **框选命中关系线**：现在橡皮筋只框节点，框不住线。
- **Shift 范围选择**（从主选到点击处整段选中）：没做。
- 检查器批量页不显示「当前值」——多选时各条的值可能不同，画勾会撒谎，所以一律不画勾。

#### 5.5.1 概念分组（CM-18，2026-11-01）

CmapTools 能把若干概念框成一组；织思此前没有。`Boundary` 用不了（它只圈同一父级的直接子节点，
概念图没有父子），所以这是 `docs/30` §5.2 的**第二个字段例外**：顶层键 `groups`。

| 项 | 规格 |
| --- | --- |
| 数据 | `ConceptGroup { id, label, members, color }`，落在 `FileDoc.groups`（顶层）。空数组不写 |
| 组框矩形 | **不进文件**：由「成员包围盒 + 24 内距」在 `Scene` 里算（`GROUP_PAD`）。派生量写进文件会和成员位置打架 |
| 画法 | 圆角 12、1.5px、6/4 虚线（与关系线虚线同一节奏）、6% 淡底；名字 12px 画在**框上沿外侧**（框里是概念，字进去会压盒子） |
| 建组 | 概念多选菜单 →「创建分组」；成员 < 2 只给提示不发命令；名字默认「分组 N」 |
| 一个概念只属于一个组 | 建新组时先把成员从旧组摘掉；摘完只剩 1 个成员的组**整组消失**（`validate` 要求成员 ≥ 2） |
| 点组框 | = 选中组内全部概念（复用现有多选拖动，**不新增拖动类型**）；命中只认框线（`BAND`），框内空白仍归画布，否则框选会被吃掉 |
| 右键组框 | 「选中组内概念 / 解组（保留概念）/ 分组颜色（5 色）」 |
| 解组 | `DeleteGroup` 只删框，概念一个不删 |
| 整组平移 | `MoveGroup { dx, dy }`：一条命令把成员一起挪，**一次撤销**（比 Batch 少一层嵌套） |
| 删概念 | 从 `members` 摘掉；不足 2 个成员的组整组消失；撤销一起还回来 |
| 导出 | PNG / SVG / PDF 同源（圆角虚线框 + 6% 淡底）；名字只在画布覆盖层与 SVG/PDF 的文字里 |
| 思维导图 | 不画分组（换布局后残留的 `groups` 保留在文件里，不丢数据） |

**未做（写清楚）**：重命名（v1 名字只有「分组 N」）、拖成员进出组、组框手动缩放、嵌套组。
`docs/32` §13 已把这几项列为下一版。

### 5.5 布局

- **自由摆放优先**：拖动即定位，落点写 `pos`；重叠时给出 1px 强调红边提示（0.25s）。
  概念图里拖到别的概念上**不改结构**（不挂子节点），只换位置；主概念同样可拖。
- **整理布局**（空白处右键「整理布局」，CM-04 落地）：分层（最长路径分层，环按首次访问截断）
  + 同层按父重心排序 + 层内等距 + 24 轮松弛；结果整体左对齐到原包围盒左上角；
  **一次命令，可撤销**。算法在 `mw_core::concept_layout`，纯函数、无 UI 依赖。
  落地时弹一条提示「已整理 N 颗概念 · Ctrl+Z 撤销」（2.4s，`shots/x100/C7/`）——
  整理会丢掉所有手工位置，用户得知道刚才动了什么、能退回去；一条概念都没动时不弹。
  **撤销连取景一起还回来**（打磨轮 18）：撤销踩到的正是整理那一条时，`rebuild()` 之后重新 `fit`
  一次，重做同样 `fit` 并把栈深重新挂上。取景是**按撤回来的位置重算**，不是回放整理前那一帧的相机——
  整理可能跑在首帧 `fit` 之前，那时存下的相机并不是用户看到的取景。
  提示条在离屏 harness 里不按 2.4s 墙钟过期（否则基线会和时钟赛跑），证据 `shots/x100/C7/`。
- 整理后不得出现节点重叠；层间距 ≥ 56，层内节点间距 ≥ 24。
- 概念图不参与思维导图的 `fit` 树布局；相机 `fit` 用所有节点包围盒。
- **启动后头若干帧要重取景**（打磨轮 19）：窗口尺寸/面板宽度晚一两帧才落定，首帧那次 `fit`
  读到的是没落定的视口（实测同一包围盒首帧 `zoom=1.2369`、落定后 `1.5`），文档会被画小一档。
  `App::update` 里按**帧**（不是墙钟）重 `fit` 12 帧；证据 `shots/x100/M13/`。

### 5.6 与笔记联动

- 与思维导图**同一套机制**：检查器「内容」组 → 卡片绑定（新建/关联/解绑）；`card_id` 相同语义。
- 反查：笔记库卡片详情里「来源」显示 `概念图名 · 概念名`，可点回画布并选中该概念。
- 大纲视图：概念图在大纲里按 `relationships` 的生成树展开（环取首次访问边），
  页头标注「概念图 · 按链接层级展开」，让用户能像编辑思维导图一样用大纲改结构。

#### 5.6.1 大纲改结构（CM-09 落地口径）

概念图的大纲每行 = **一个概念 + 进来那条边**。行首淡色前缀（`解决 →`）就是那条边的
链接短语，行的身份由「概念 id + 边 id」共同决定。所以「在大纲里改结构」只有一种含义：
**建、改、删这条进来的边**——不是改 `children`（§5.2 禁止把树语义漏进概念图）。

| 手势 | 语义 | 命令 | 细则 |
| --- | --- | --- | --- |
| `Tab` | 在当前概念下新建概念**并连一条边**，就地先写概念名、再写链接短语 | `Batch[AddFloatingTopic, AddRelationship]` | 落点 = 被选概念下 56px；边落盘时无短语，写完短语才补齐 |
| `Shift+Tab` | 不接：概念图没有「升级/降级」 | — | trace `outline_tree_key_ignored key=indent_or_move` |
| `Shift+Delete` | 只断「进来那条边」，概念留成**孤立概念**（按 `(y, x, id)` 重新排到自己那段） | `DeleteRelationship{from, id}` | 行没有进来的边时空操作，不删概念 |
| `Shift+F2` / 点行首短语 | 就地改链接短语 | `SetRelationshipLabel{from, id, label}` | 空串 = **不提交**，保留原短语并提示「概念图的连接短语不能为空」（命题必须有短语，与画布同一口径；打磨轮 40 / C16） |
| `Delete` | 删概念，连带它的出边与入边 | `DeleteNodes` | 与画布一致（CM-05 已放开主概念） |
| `Enter` | 只加概念、**不加边** | `AddFloatingTopic` | CM-07 既有行为；新概念出现在孤立概念段 |

短语就地编辑契约（与行内改名同一套，不许另开弹窗/二级页）：

1. **单一表面**：短语在行首那条淡色区里编辑，行还是那一行，高度不变。
2. **本地草稿**：`Esc` 还原原文并退出；`Enter` 提交；失焦提交；没改不写历史。
3. **IME**：组合期间 `Enter` / `Esc` / `Tab` 归输入法，预编辑串不落盘（与正文编辑同一条判定）。
4. **空短语**：`Tab` 新建的边在**未填就提交/取消**时**整条撤掉**（§5.9「未填不给连线落盘」），
   概念本身留下当孤立概念；对**既有边**，空串 = **拒绝提交**（保留原短语 + 提示），
   不会落成无短语的线团（打磨轮 40 / C16：此前这里写成「清掉短语」，与模型守卫相反）。
5. **一条命令一次撤销**：`Tab` 的「概念 + 边」是一个 `Batch`；短语是随后的
   `SetRelationshipLabel`；断边单条 `DeleteRelationship`。

### 5.7 命令

优先复用既有命令：`AddFloatingTopic`（加概念）、`SetText`（改概念文字）、
`AddRelationship` / `DeleteRelationship`（加/删连线）、`ReverseRelationship`（反向连接，CM-14）、
`SetRelationshipDashed` / `SetRelationshipWidth` / `SetRelationshipNote`（线型 / 线宽 / 命题注释，CM-16）、
`SetRelationshipLabel`（改链接短语，
若无则补一个 `Command` 变体）、`SetRelationshipColor`（改线色）、`SetRelationshipHead`（改端点箭头，
CM-10 ⑦）、节点位置写 `pos`（若无移动命令则补 `MoveConcept`）。
**所有概念图变更必须走 `Command` 与撤销栈**，不许直接改 `Document`。

**CM-11 复制语义**：概念图的复制/粘贴、`Ctrl+D`、`Ctrl+拖拽` 不允许走树的
`parent/children` 路径。副本一律是**独立浮动概念**（`parent_id = None`、`pos` 整体偏移），
只保留副本之间的有向关系线，边界/概要清空，卡片绑定不复制（副本保持未绑定）；整批一次撤销。
命令 `InsertConcepts` 只在概念图成立，`.zmind` 字段与版本不变。

**CM-05 落地的三条细则**：

1. **键盘是摆位，不是遍历**。概念图里方向键 = 把选中概念挪 1px，`Shift` + 方向 = 8px；
   多选整组一起挪，**一条 `Batch` 一次撤销**。思维导图那条「方向键换选下一个节点」在概念图不成立
   （命题网没有前驱后继）。
2. **主概念可删**。`root_id` 指向的是「第一个概念」而不是树根：`DeleteNodes` 在
   `kind == "conceptMap"` 时允许 `ids` 含 `root_id`，删完把根重挂到**剩下概念里最靠左上**
   （按 `y`、`x`、`id`）的那个；`ChangeSet` 带 `before_root / after_root`，撤销/重做把根一起还原。
   唯一拦住删除的条件是「删完一个概念都不剩」——没有零概念的文档。
3. **右键菜单不许带树语义**。概念图节点菜单里没有「新建子主题 / 新建同级 / 概要 / 边界 /
   分离为自由主题 / 折叠 / 聚焦」；空白菜单里没有「全部展开 / 全部折叠」。取而代之的是
   新建概念、编辑概念、整理布局、关联卡片笔记、排列、删除概念。
   其中「排列」（对齐 6 项 + 分布 2 项）**只在多选时出现**——单选一个概念时没有可排的东西；2026-10-27 起由 `cm-multi-menu` 锁住（多选菜单 `entries=9`）。
   2026-10-27 起后半句有基线：`cm-blank-menu`（概念图空白菜单 9 项 = 6 条动作 + 3 条分隔线，菜单引擎自报 `entries=9`，与代码逐条对得上；`全部展开 / 全部折叠` 整段不进入列表）。

### 5.8 导出与往返

- `Scene` 是几何唯一真相源：PNG / SVG / PDF 导出自动可用，无需新代码路径。
- 大纲导出（Markdown/OPML）与思维导图一致：概念图按生成树导出为层级列表，
  并在文首标注「概念图」。
- `.zmind` 往返：因未改格式，`kind` 字符串与既有字段可原样读写；往返测试须断言
  `relationships`（含 label/color）与 `pos` 逐字段相等。

### 5.9 概念图禁止项

- 禁止把概念图渲染成思维导图的辐射树（那不叫概念图）。
- 禁止无链接短语的「线团」：新建连线即进入短语编辑态，未填不给连线落盘。
- 禁止曲线/贝塞尔连接线（先做直线）；禁止自动互链、自动生成概念。
- 禁止在概念图里塞画布工具条以外的新控件（不引入第二套工具条）。
- 禁止改 `.zmind` 版本或新增字段。
- 禁止在大纲里用 `Tab` / `Shift+Tab` 表达层级（那是树语义）；`Tab` 只表示「加一条边」，
  且必须落成 `AddRelationship` + 短语，不许只改 `parent_id`。
- 禁止「有 tooltip 但没被截断」的节点：tooltip 只在真截断或真挂卡片时出现（§5.3.1）。
- 禁止把跨分支色的计算结果写回 `relationships[].color`（§5.4.1）：那是绘制层的推导，
  落盘就成了用户数据，撤销栈、往返断言、切换主题都会跟着错。
- 禁止为交叉微弧加「跳线」或第三种线型：只允许直线与「偏 6px 的二次曲线」两种（§5.4.1）。

### 5.11 浮层几何：必须夹在窗口内，超长要能滚

**规则**：任何锚在某个控件旁的浮层（标签弹层、右键菜单、子菜单）都必须满足两条——

1. **不越界**：算出的矩形要夹进窗口（`screen_rect`）四边；位置由 `Area::constrain_to(窗口内缩 8px)` 负责，
   太靠下时整体上移（不是翻转到锚点上方——实现是「夹紧」，措辞按实现写）；
2. **可滚动**：内容高度超过「可用高度」时封顶并给竖向滚动，**不许**让浮层随着条目数无限长高。

**为什么写这条**：2026-10-28 查标签弹层时它两条都不满足——`panels/outline.rs` 里 `if self.label_popup { … }` 那段
是一列 `selectable_label`，既没有高度上限也没有滚动，锚点是 `Pos2::new(r.left() - 20.0, r.bottom() + 6.0)` 的固定偏移。
标签一多，弹层就长出窗口底部；离屏基线里看不出来，因为示例文档每个节点最多 5 个标签、整篇只有 6 个。

**第 55 轮的实现与实测**（场景 `cm-outline-label-many`，120 个标签 → 66 行）：

| 量 | 值 |
| --- | --- |
| 窗口 / 锚点 | 1280×800 / y=137.3 |
| 可用高度 `max_h` | 639（= 800 − 8 边距 − 137.3 锚点 − 16 的 `Frame` 上下内边距） |
| 弹层总高 `h` | 653（= 639 视口 + 14 内边距） |
| 底边 | 790.3（窗口 800，留 8 边距 → **不越界**） |
| 内容高度 | 2 500（66 行 × 约 38）→ 视口 639，**能滚** |

**踩到的坑（值得记住）**：第一版只加了 `ScrollArea::max_height(max_h)`，实测弹层却稳定停在 400 ——
因为 `Area` 内层 ui 的 `max_rect` 是**上一帧的矩形**（egui `containers/area.rs` 里 `let max_rect = self.state.rect();`），
而 `ScrollArea` 又按「当前可用高度」封顶，两者互相喂小值，自锁在 400，永远长不到 639。
修法是在 `Frame` 里先把 `ui.set_max_height(max_h)` 顶上去，滚动区视口才等于真正可用的那一段。
另外 `Frame::popup` 的上下内边距（实测 14）不在滚动区里，不单扣就会让底边越过窗口 6px（实测 `bottom=806` / 窗口 800），
所以 `max_h` 里减掉 `POPUP_FRAME_PAD = 16`。

**验收**：
- 单测 `panels::outline::tests::popup_max_height_caps_to_window_bottom`：贴底边只剩 floor、锚点在上方时等于下方那段、窗口极矮仍给 floor；
- 画面 `cm-outline-label-many`：66 行不撑开弹层，底边停在窗口内 8px；
- 旧场景 `outline-search-labels`（本来就是这个弹层）因几何变化重拍：41 526 px 变化、2 257 强差，包围盒 `x734..1294 / y230..306`，只落在弹层那一块。

### 5.12 切换型交互：拍「加上」也要拍「撤下」

**规则**：凡是 toggle 语义的交互（Shift/Ctrl 多选、勾选、折叠、开关），验收必须包含**撤下**那一态，
并且撤下的判据要落在**已有基线**上，而不是「另拍一张看起来没问题的新图」。

**为什么**：加上那一态，bug 只会「少显示」；撤下那一态，bug 才会「多显示」——多选环没撤、检查器目标没换，
这两种都只在撤下之后才看得见，而且它们不会让任何「加上」的基线变红。

**做法**（第 56 轮 `mm-annot-multi-off` 的样板）：

1. 夹具走完整条路径：加两条 → 都选中 → 再按 additive 取消一条；
2. trace 先断言状态机（`annot_multi selected=2` → `annot_multi_off left=1 kinds=[Summary]`）；
3. 画面用三条数字比：强调绿回到「单选那张」的数值、与多选那张的差只落在被取消的那一圈上、
   与「单选那张」**0 强像素**（剩下的弱差只能是对象自身的淡色底——对象还在，只是没选中）。

注意别把判据写成「与单选那张逐像素相等」：那张图里对象不存在，这张里对象存在但不被选中，
两者本来就该差一片淡色底。分不清这两件事，就会把正确实现误判成 bug。

### 5.13 拖拽类交互：拍「拖拽中」也要拍「松手之后」

**规则**：凡是有预览态的拖拽（跨度手柄、关系线改接、移动、吸附），验收要分成两半：
**拖拽中**拍预览画面对不对，**松手之后**拍「命令发没发、发几条、能不能撤回来」。

**为什么**：拖拽中那次绘制是纯视觉的，松手才是改数据的那一跳。两者可以各自独立地坏——
预览画得漂亮但松手什么都不发（用户白拖一次），或者发了但发了三条命令（撤一次只回退一半）。

**做法**（第 57 轮 `mm-span-commit` 的样板）：

1. 夹具走完整路径：起拖 → 改预览 → 提交；
2. trace 读**文档**（不读缓存）三行：`span_commit before=2 after=3 changed=true`、`span_commit_undo back=2`、`span_commit_redo targets=3`；
   撤销一次就回到原值，等价于「只发了一条命令」——这比数撤销栈长度稳，因为它顺带证明了撤销栈没被污染；
3. 画面比「提交后」与「提交前那张基线」，并且**按 y 带核局部性**：本次 `y0..440` 与 `y610..1200` 各 0 px，
   差异全在 `y440..610`，说明不是整页重排。只报总差 7 198 px 是不够的，总差可能被「全页位移」凑出来。

## 7. 证据与验收总则

1. 四类证据齐全：机器证据（tests / fmt / clippy / release）、golden 对比图、
   交互 trace / 输入脚本、人工判词。
2. 新增 golden 场景必须给出**旧哈希**（重拍前）与**新哈希**，并双跑 `--tol 0`。
3. 「好看」不能由 golden 证明：起始页、检查器、概念图三处都要有人工判词
   （截图判读 + 眼手试用记录）。
4. 改动外观前先记录漂移量与包围盒，漂移原因写进报告。
5. 状态词只有「未开始 / 进行中 / 已实现 / 已验证 / 阻塞 / 延后」；
   `已验证` 只在人工门通过后使用。
6. **可量化的视觉项不许只写"更好看"**，必须给数字并落成会红的测试：
   - 文字对比度：承担正文的次要文字（`ui.dim`）在 `panel` / `panel2` / `hover` / `canvas_bg`
     **四种底上全部 ≥ 4.5:1**；`text_faint`（占位符/禁用/装饰）**≥ 3.0:1** 且必须**严格淡于** `dim`。
     门：`crates/mw-core/tests/contrast.rs`（逐主题 × 逐底断言）。
   - 铬件尺寸：折叠圆点、悬停工具条、**关系线箭头**等一切"看得见才存在"的部件，按屏幕空间恒定画
     （`Camera::chrome` / `screen_arrow`），低缩放不消失、高缩放不变钝。
   - 字号只有 `design::text::*` 五个令牌（`CANVAS_CENTER/MAIN/SUB/LEAF` + 面板用 `TITLE/CANVAS_SUB…`），
     画布里不许出现裸字号字面量。
7. 像素差不是唯一判据：改了颜色/形状要同时给出**对比度数值**与**盒子界证明**（例如椭圆外扩后
   文字仍在内接矩形内），否则"没坏"只是没测。

#### 12.2.3 结论

**不，没有齐。** 16–19 与 21 五项都卡在同一条硬约束上（§5.2 禁止新增字段、不改 `FORMAT_VERSION`），
要动它们必须先拍板；20 不动数据但改选择模型；22 随时可补；23 是独立的互操作工程。

建议次序：

1. **线型 + 线注释**（18 / 19）：两个可选键，与 `Relationship.color` / `head` 同款先例
   （`#[serde(default)]` + `skip_serializing_if`，旧文件读出来是默认值，不升版本）。
   字段提案见 `docs/32` §12。风险点在虚线要动 wgpu 画线，需要金样。
2. **多选关系线**（20）：不动数据，纯选择模型 + 批量命令，建议单独一包。
3. **嵌套 / 分组**（16 / 17）：工作量最大、动结构，建议单独一批并先写验收场景。
4. **22** 可以随手做；**23** 取决于是否需要与 CmapTools 用户交换文件。
