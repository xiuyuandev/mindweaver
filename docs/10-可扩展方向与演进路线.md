# 10 · 可扩展方向与演进路线

> 状态：草案 v0.2 · 更新：2026-10-17 · 上游：01（非目标清单）、05（预留设计）· 定位：规划性文档，非承诺
>
> ⚠️ 读法只有一条：**本文里凡「前端」= 视图层（`mw-shell` + `mw-render` + `mw-ui`）**。§6「技术债管理」里那条评审红线——「`mw-core` 与前端之间任何绕过命令层直改数据的临时方案」——在原生栈同样成立，而且更硬——`mw-render` 只吃 `Scene`，连改数据的类型都拿不到（14 §2 不变量 3）。永久非目标清单（§5）**不受路线变更影响，继续防住协作/云同步/账号**。
>
> 产品性质已明确定位：**个人使用的免费开源工具**（01 §2）。因此本文不包含协作、云同步、账号等任何联网服务方向——它们是永久非目标（§5）。所有演进只围绕一件事：**把单机思维导图的编辑与使用体验，打磨到成熟商业产品的水准。**
>
> 规模标注：S ≤ 2 周 · M = 2–6 周 · L > 6 周（按单人开发者产能折算）。

---

## 1. 演进总原则

1. **体验优先于功能**：候选功能先回答"它是否让记录思路这件事更舒服"，答案模糊就不做；
2. **小步精修**：1.x 每个版本聚焦 1–2 个主题，不堆功能清单、不发"大版本"；
3. **不过度为未来设计**：只保留 05 §8 已列的预留点，不新增投机性抽象；
4. **个人节奏**：无商业排期压力，质量不达标就不发版。

## 2. 1.x 精修路线（建议顺序）

| 版本 | 主题 | 内容 | 规模 |
| --- | --- | --- | --- |
| 1.1 | 补齐编辑缺口 | 查找替换转正（02 §3 P2）；多选批量能力增强；演示模式转正（02 §9，规格已冻结） | S |
| 1.2 | 表达力 | 图片节点（粘贴/拖入，走 `assets/` 预留）；受限富文本（加粗/高亮/行内代码，不做全功能文字处理） | M |
| 1.3 | 布局扩展 | 鱼骨图（因果分析）、时间线（事件梳理）——布局引擎纯函数化（04 §2），逐个接入 | 每 S–M |
| 1.4 | 舒适性长尾 | 手写笔 Ink 输入（Surface/学生场景）；拖标签出窗多窗口对照；界面 en-US（翻译框架就绪，ADR-009） | M |
| 1.5+ | 按真实使用反馈排序 | 模板库扩充、`.ztheme` 主题分享、HTML 导出转正等 | S–M |

每个版本同步消化 GitHub issue 中的高频诉求；issue 的数量与热度将替代"路线图承诺"，成为优先级的主要输入。

## 3. 开源项目运营（与功能同级的"成熟度"工作）

对标成熟 GitHub 项目，随 1.0 一并就绪并持续维护：

| 项 | 内容 |
| --- | --- |
| 仓库门户 | README：演示 GIF、30 秒上手、下载指引（含 SmartScreen 引导）；本 `docs/` 体系全文公开 |
| 贡献机制 | CONTRIBUTING（环境搭建指向 03 §6）；issue / PR 模板；good first issue 标签；PR 即视为按项目双许可授权，不设 CLA |
| 决策透明 | ADR 全文公开（04 §10）；重大变更先开 issue 讨论，共识后再实施 |
| 质量可信 | CI 徽章；每夜性能基准趋势页公开（08 §8）；`.zmind` 格式规范 v1 文档化并随仓库维护 |
| 沟通渠道 | GitHub Discussions（问答 / 想法区）；不建群、不运营社区活动，保持个人项目可持续的维护强度 |

## 4. 远期可选评估（无排期，仅记立项条件）

| 方向 | 立项条件 | 备注 |
| --- | --- | --- |
| CLI 无头导出（`zmind-cli`） | 出现真实自动化需求（如脚本批量导出） | 文本测量抽象为 trait + Rust 端渲染，ADR-003 既定演进路径；M 规模 |
| 插件系统（WASM 沙箱） | 社区出现 PR 形式无法满足的扩展诉求 | 渲染与核心模型不开放直改（稳定性红线）；L 规模 |
| 本地 AI 辅助（节点续写/总结） | 作者本人有日常使用欲望才立项 | 仅本地模型（如 Ollama）；输出作为可撤销建议进入命令层；**不做联网 API**（01 隐私原则） |

## 5. 永久非目标（明确不做，不再评估）

| 方向 | 理由 |
| --- | --- |
| 多人协作 / CRDT | 个人工具定位；省去合并语义、服务端与整块最重的复杂度——**这是质量决策而非妥协** |
| 云同步 / 官方云存储 | 文件即数据：OneDrive / 坚果云等系统级方案天然可用；织思只需做好"文件被外部改动检测"（05 §6） |
| 账号体系 / 登录 | 无服务端即无身份需求 |
| 移动端 / 网页版 | 无同步即无意义；把 Windows 桌面这一件事做到极致 |
| 团队 / 企业功能（权限、空间、管理后台） | 与"个人工具"性质冲突 |

> 把协作与云划出边界，换来的是：更小的攻击面、更简单的数据模型、更可测试的核心、更低的长期维护成本。**这是个人项目能长期保持"成熟产品质感"的前提。**

## 6. 技术债管理（贯穿全程，不单独立项）

- 08 §8 每夜性能基准的劣化跟踪（任一指标 >10% 劣化即 CI 黄牌）；
- `mw-core` 与前端之间任何"绕过命令层直改数据"的临时方案 = 评审红线；
- 每个 minor 预留 ≤10% 产能用于重构与依赖升级；
- 文档同步义务：实现与文档偏差处，PR 内必须更新对应文档（ADR 或正文）。

## 7. 长期愿景

不追求功能无限膨胀，终点是一句话：**"在 Windows 上写中文思维导图，织思是那个不用犹豫、直接打开的工具。"** 到达这个状态后，项目进入"维护 + 微精修"的低耗长期运行——这正是个人开源工具最好的生命周期。
