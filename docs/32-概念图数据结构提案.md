## 1. 为什么这两条不能「只改绘制」

| 项 | 为什么必须落盘 |
| --- | --- |
| ⑥ 聚焦问题 | 它是**这张图的问题陈述**（CmapTools 的 focus question），关掉再打开必须还在；只在内存里等于每次重打 |

## 2. ⑥ 聚焦问题

字段（`mw-core` `Meta.layout`，即 `LayoutSettings`）：

```rust
pub struct LayoutSettings {
    // …现有字段…
    /// 这张概念图要回答的问题（CmapTools 的 focus question）。
    /// `None` = 没设，图顶部不占位；空串按 `None` 处理。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub focus_question: Option<String>,
}
```

- **版本**：不升 `FORMAT_VERSION`。`Relationship.color` 已经是「可选 + `skip_serializing_if`」的同款先例；
  `LayoutSettings` 带 `#[serde(default)]`，旧文件读出来就是 `None`，新文件被旧版本读到也只是忽略该键（serde 默认忽略未知字段）。
- **命令**：`Command::SetFocusQuestion { text: Option<String> }`，一条撤销记录；空串等价 `None`。
- **显示**：
  - 画布：概念图顶部一条约 32px 的问题带（行高 + 上下 7px 内边距；不在场景图元里，走 egui 层，
    避免影响 `Scene` 的几何与导出）——**只在设了问题时出现**，没设一个像素都不多，
    所以 14 张既有 `cm-*` 基线逐张不变；
  - 大纲（CM-07 页头）与导出 PNG/PDF/SVG：走各自已有的页头/标题位，文字取同一个字段（导出**已补**，见 §6；大纲页头**未做**，见 §4）。
- **编辑入口**：检查器「布局」页一个单行输入；画布问题带上双击就地编辑。
- **验收**：
  - 单测：`SetFocusQuestion` 一轮 undo/redo 后字段还原；空串 → `None`；
  - golden：`cm-focus-question`（设了问题时顶部带子出现、未设时不占位）；
  - 导出：SVG 字符串断言含问题文字；PDF/PNG 各一张。

## 3. ⑦ 箭头样式（**已实现**）

> 落地时改掉了提案里的三处判断，原因写在下面。最重要的一处：提案把「现状」记成了
> 「不画箭头」，实测不是——关系线从 CM-03 起就一直在画前向箭头。

字段（`mw-core` `Relationship`）：

```rust
pub enum ArrowHead { Off, Forward, Backward, Both }   // Default = Forward

pub struct Relationship {
    // …现有字段…
    #[serde(default, skip_serializing_if = "ArrowHead::is_forward")]
    pub head: ArrowHead,
}
```

- **默认是 `Forward`，不是「不画」**：`Scene` 里关系线的箭头三角形（`straight_between` /
  `curve_between` 画的 6×4 实心三角形）一直存在，`mw-render/src/instances.rs` 与
  `export_svg.rs` / `export_pdf.rs` 都无条件消费它。所以「与今天逐像素一致」的那一档是
  `Forward`；若按提案把默认设成「不画」，全部 `cm-*` 基线会集体掉箭头。
- **变体叫 `Off` 不叫 `None`**：这一档是「用户明确选了不画」，不是「没设置」；
  没设置就是 `Forward`。避开 `None` 是因为它和 `Option::None` 混在一起没法读。
- **版本**：仍不升。缺键 → `Forward` → 与今天逐像素一致；而且默认值不写回文件
  （`skip_serializing_if`），否则每个文件的 diff 都会多一行没意义的键。
- **几何只在 `Scene` 算一次**：`SceneRelationship.arrow: Option<[Point; 3]>`（终点端）、
  `arrow_back: Option<[Point; 3]>`（起点端）。`Backward` / `Both` 的起点端箭头由
  `mirror_tri()` 围绕连线中点镜像得到——重算会因为两端切线不同而画出两个不一样大的箭头。
  wgpu 渲染、egui 覆盖层、SVG、PDF 四处只读这一份几何。
- **命令**：`Command::SetRelationshipHead { from, id, head }`，一条撤销记录。
- **入口**：检查器「关系线」块里的「箭头」四格（`selectable_label`），只在这儿改；
  画布上没有加浮条，因为关系线的选中态已经有「标签 / 线色 / 删除」三件事，再塞一组会挤。
- **验收**：单测三条（撤销、默认不落盘、缺键读成 `Forward`）；
  golden `cm-arrow-off` / `cm-arrow-backward` / `cm-arrow-both` 三张（`forward` 由 `cm-default` 覆盖），
  `--tol 0` 各跑两遍。

## 6. ⑥ 导出补齐：带子进 `Scene`，但只在导出时（第 22 轮）

第 20 轮把问题带画在 egui 层，`Scene` 里没有它，于是 PNG / PDF / SVG 导出**看不见聚焦问题**。
CmapTools 的导出是带上的。补齐之前先想清楚一件事：**两边的几何本来就不一样**。

| | 锚点 | 为什么 |
| --- | --- | --- |
| 画布 | 视口顶部（pinned） | 滚动时问题始终看得见，这是 CmapTools 的观感 |
| 导出 | 内容顶部 | 导出没有视口，只有一个内容包围盒 |

所以「把 egui 那条带子搬进 `Scene`、让画布也从 `Scene` 画」是错的解法：搬进去之后画布上的
带子会跟着内容滚走。真正要的是**同一份文字排版，两个锚点**。

落法：

1. `Scene` 新增 `focus_note: Option<SceneNote>`（`rect` / `text` / `font_size`），
   **只有导出路径会填**，画布永远 `None`——所以既有的 `cm-*` 基线仍然零漂移。
2. 位置在 `scene.bounds` **之上**（y 向上延伸），并把 `bounds` 向上扩：
   不移动任何既有几何，导出取景自然带上，`content_bounds()` 一行不用改。
3. 文字走两处既有管线：`mw-render/src/text.rs::text_jobs()`（PNG 与 PDF 共用同一份排版，
   PDF 的 `outlines()` 也读它）与 `export_svg.rs` 的 `<text>`。**不新建排版器**。

验收：

- 单测：`focus_question` 为 `None` 时导出画面与原来逐像素一致（高度、bounds 都不变）；
  为 `Some` 时 bounds 高度增加一个带子高，且 SVG 里能搜到问题文字；
- 不新增 golden 基线（画布零变化），导出的证据是实拍 PNG 的尺寸与像素统计；
- 回滚：删字段 + 三处分支，退回「导出没有聚焦问题」。

> ⑥ 的三处落点（画布 / 导出 / 大纲页）至此全部补齐：画布见 §2，导出见 §6，大纲页见 §7。

## 7. ⑥ 大纲页的聚焦问题：贴在页头下沿，不挤进 40px 控制台（第 23 轮）

大纲页（全屏）的页头是一行 40px 控制台：返回 / 面包屑 / 计数 / 搜索 / 更多，
而且已经挂着「· 概念图 · 按链接层级展开」这类副标题，**按可用宽度省略**。
把问题塞进同一行，长问题会被省略号吃掉——而恰恰是长问题才更需要被看见。

| 方案 | 结果 |
| --- | --- |
| 塞进页头那一行 | 与「概念图 · 按链接层级展开」抢宽度，长问题被 elide；问题是这一页最该被读到的一句话，不该最先被裁掉 |
| **页头下沿一条独立带子**（选这个） | 完整显示；读的时候一直在（它在 `outline.show` 的 `ScrollArea` **之外**，不随正文滚走）；不动正文列宽 |

几何：`content_kit::question_band(page, margin, line_h)`——宽 = 页宽 − 2×`column_margin`（与正文列同一口径），
高 = 行高 + 上下各 `QUESTION_BAND_PAD`（7）。**这个 7 与画布那条带子的 `pad.y`、导出那条的 `FOCUS_NOTE_PAD` 是同一个数**，
三处各写一份就会出现三种松紧。排版照抄画布：`READING_BODY` 字号、`ui.dim` 墨色、居中。

实测（`MW_TRACE` 临时打印，窗口 1920×1200、`READING_BODY` 16px）：页头底 **88** → 带子 **96→130**
（高 34 = 字高 20 + 7×2）→ 正文行起点 **138**。96 上面那 8 和 130 下面那 8 **不是我加的**，是 egui 的
`item_spacing`：带内 7/7、带外各 8，视觉上 15/15。

带子底下**不画分隔线**：上下已有 8px 间距，再加一条 1px 线就成了「双线」，反而像第二个页头（第一版画了，撤掉）。
长问题按列宽**换行**、不用省略号：两行时带子跟着变高（`galley.size().y` 本来就带着行数）。

为什么**不**进 `Scene`：大纲页不是画布，它渲染的是文档树；问题在这里是**页面文案**，不是几何。
能共用的只有文字排版与那三个留白数字，不是坐标。

只在「概念图 + 真的写了问题」时出现 ⇒ 既有四张 `cm-outline*` 基线零漂移；新增第 21 张 `cm-outline-focus`。

验收：

- 单测 `content_kit::tests::question_band_sits_in_the_column_and_keeps_seven_above_and_below`（含窄窗收零宽）；
- 新基线 `cm-outline-focus`：门 20 → **21 场**，两遍共 42 次比较；
- 回滚：删掉那段 `if` 与场景记录，退回「大纲页不显示问题」。

## 8. ⑥ 大纲页那条带子可以就地改（第 24 轮）

上一轮把大纲页的问题带做成**只读**，理由写在 `shots/x100/CM-10/report.md` §3 第 5 条：「读结构的地方不开写入口」。
这一轮推翻这半句——理由站不住：读完一层结构之后，最常见的下一个动作就是「这句问得不对，改一下」，
让用户为此回一趟画布，等于把改问题的成本抬到「离开当前页」。

| 做法 | 结果 |
| --- | --- |
| 只读（第 23 轮） | 少写一个入口，但改问题要回画布 |
| **双击就地改**（第 24 轮，选这个） | 与画布同一条手势；键盘、提交、取消、撤销全部复用 |

**手势与画布一致：双击。** 画布上单击归选择与拖动画布，这条规矩不为大纲页破例；
悬停给底色 + 文本光标 + 1px 强调线，就是在说「这行字能点」。

**控件只有一份**：`content_kit::question_field()`——字号 `READING_BODY`、内边距 16/7、占位提示、单行无边框，
画布与大纲页都调它。底色由调用方给：画布 `canvas_bg`，大纲页 `Color32::TRANSPARENT`
（页面背景自己铺，这一处填死一个 token 迟早对不上）。

**判定也只有一份**：`content_kit::question_edit_outcome(text, opening, esc, done)` → `Continue` / `Cancel` / `Commit(String)`。

- Esc 优先于提交；
- 没改（**trim 后**比较，只在末尾多敲空格不算）就关掉、不发命令——撤销栈里不留空记录；
- 提交走 `Command::SetFocusQuestion`，归一化（trim 后为空 ⇒ `None`）由命令负责。

**一个实测出来的坑**：编辑框立起来的第一帧拿到焦点，第二帧就被抢走了。
抢的人不在问题带里，而是 `outline.show` 之后那条「首次进大纲，把焦点给第一行」的请求——
它有意排在 `ScrollArea` 收尾之后（不然会反过来被滚动条抢走）。
修法：编辑框立着时（`keys_blocked`）这一帧的行焦点请求**直接让开**，并留一条 `outline_focus_request_skipped` trace。
这不是 golden 特有的问题：真实用户双击那行字，也一样会在下一帧失去光标。

**机身不跳**：带宽仍按「已提交的那句」算，编辑框套在同一个 `col` 里；
`ui.put` 是绝对放置、不推进光标 ⇒ 正文行一格不动（实测：静态 152/204/243，编辑态 152/204/243，完全一致）。

**基线**：第 22 张 `cm-outline-focus-edit`。与 `cm-outline-focus` 的差异只在带子那一行（设备行 105–121），
文字从居中 849–1062 变成左对齐 576–790（列左沿 560 + 16 内距）。

验收：

- 单测 `content_kit::tests::question_edit_outcome_says_cancel_continue_or_commit`（Esc 优先 / 未改不发命令 / trim 后提交 / 清空提交空串）；

## 9. ⑥ 画布那条带子遇到长问题会换行（第 25 轮）

问题可以问得很长。第 24 轮给大纲页那条做了按列宽换行，画布这条却还是 `layout_no_wrap`：
一条 137 字的问题在 1280×800 的画面里排成一行，ink 从 x=1 铺到 x=1918——被窗口左右**硬切**。
更糟的是它**看不出被切**：没有省略号、没有换行提示，用户只会以为句子就这么长。

修法（三处，都是小改）：

- 行宽上限 = 画布宽 − 64：`focus_wrap_width(origin) = (origin.width() - 64).max(120.0)`。
  这 64 = `focus_band_rect` 对带子宽的 −32，再加上带子左右各 16 的内距；
- `Painter::layout(...)` 第四个参数就是换行宽，`layout_no_wrap` 改 `layout`；
- 换行后带子高度**不用另算**：`focus_band_rect` 本来就按 `text.y + 14` 取高，行数一多自己就长高。

窄窗仍收在 120 的最小行宽，不会退化成一行一个字。短问题零漂移：18 字的 `cm-focus-question`
在两种写法下 galley 宽度相同，所以第 22 张基线逐张不变。

实测（设备 px，1920×1200 基线；137 字的问题）：

| | 改前 | 改后 |
| --- | --- | --- |
| 行数 | 1 | **2** |
| ink 横向范围 | x **1..1918**（贴住两沿） | x **33..1885** |
| 第一行 / 第二行宽 | 1917 / — | 1853 / 326 |

**仍然存在的取舍**：带子现在会随问题变高。问题极长（几百字）时它会压掉画布顶部一大块。
没有加行数上限，因为「问题写得长」本身是作者的选择，截断比占地方更糟；
真遇到就先记在这里，等真实用例说话（`shots/x100/CM-10/report.md` §3 第 6 条）。

验收：

- 单测 `canvas::tests::focus_wrap_width_leaves_sixteen_of_padding_on_both_sides`（1280 → 1216；120 宽窗 → 120）；
- 单测 `canvas::tests::focus_band_grows_with_wrapped_lines_and_stays_inside_the_canvas`（两行 40 高 → 54；宽 768；仍在画布内且居中）；

## 10. ⑦ 箭头四档：菜单里当前那档打勾（第 26 轮）

⑦ 给了四档（无箭头 / 单向 → / 反向 ← / 双向 ↔），但菜单里那四行**长得一模一样**。
点了「反向 ←」之后只有画布上的箭头端点变了，再打开菜单看不出现在是哪一档——
用户只能靠数端点去猜。互斥选项组不给勾，等于每点一次都要重新确认一遍。

修法分三层，都很薄：

- 菜单模型：`Entry::action_checked(label, shortcut, action, enabled, checked)` 把 `check: Some(bool)` 带上；
- 绘制：`paint_row` 里 `Some(true)` 画勾（强调色）、`Some(false)` 留空；
  **图标槽宽度不变**，所以四行文字的左缘仍然对齐（这条不改，勾一进来整组文字就会错位）；
- 取值：`Canvas::selected_relationship_head()` 从文档现读当前关系线的 `head`。
  不缓存——撤销之后缓存会骗人，而撤销恰恰是这个菜单最常撞上的操作。

验收钩子：`MW_CONCEPT_ARROW_MENU=1` 选中示例图里第一条关系线，并展开「箭头方向」子菜单。

实测（设备 px，1920×1200 基线；子菜单四行文字在 y = 177 / 207 / 237 / 267）：

| 当前档 | 勾的位置 |
| --- | --- |
| 无箭头（`MW_CONCEPT_ARROW=off`） | 第 1 行，y **177–186** |
| 反向 ←（`MW_CONCEPT_ARROW=backward`） | 第 3 行，y **238–245** |

两处勾都是 10×12、42 px 的强调色笔画，落在行左的图标槽（x 610–621）。

其实差分只说「这两块不同」，不说哪块属于哪张图。改成**逐图直接检色**（饱和色 = 强调色）才对上：
勾一直在对的那一行。测颜色位置别用差分归因。

## 11. 激活证据的边界（2026-10-27 04:50）

⑦ 的「勾在哪一行」是**状态**，第 26 轮已经锁住（`cm-arrow-menu`）。
但状态对不对，和「选了它会不会真的改」是两件事。第 27 轮补后者时撞出一条边界，记在这里。

**菜单条目能被选中的四条路，基线覆盖情况：**

| 选法 | 能不能在离屏里锁 | 现有证据 |
| --- | --- | --- |
| 加速键 / 快捷键（`key 1`、`key Delete`） | 能 | `start-menu-input`、`outline-menu-input` |
| 键盘导航 + `Enter`（`ArrowDown` / `Enter`） | 能 | 新增 `cm-arrow-menu-key`：`menu_nav` → `menu_activate` → `relationship head … both` |
| 指针点击弹层行 | **能**（2026-10-27 17:30 更正） | `cm-arrow-menu-click`：点「双向 ↔」→ `menu_click` + `relationship head … both`；原「不派发」是坐标算错 |
| 指针点击画布/标题栏 | 能 | `menu-canvas-click`、`start-scroll` 等 |

**负结果的准确说法**：在 `MW_GOLDEN_INPUT` 注入的指针下，点在弹层菜单行上不会派发动作，
连「点空白关菜单」都没有发生。原因未定位（离屏没有真实指针的按下-保持-释放生命周期），
本轮不追。它的影响是**证据面**而不是产品面：不能据此说鼠标点不动菜单——真实鼠标路径仍未验证。

**设计上的结论只有一句**：菜单里「互斥档位」这种条目，要锁两件事——
勾在哪一行（静态可锁）、选完文档变成什么（需要一次激活，走键盘）。两件都锁了，才算锁住这个条目。

### 12.1 关系线线型（§12.2 第 18 项）· **已实现（CM-16）**

`Relationship` 现在只有 `id / to / label / color / head`。加两个可选键：

```rust
pub struct Relationship {
    // …现有字段…
    /// 虚线：`true` = 虚线。默认 `false`，**默认值不落盘**。
    #[serde(default, skip_serializing_if = "is_false")]
    pub dashed: bool,
    /// 线宽（css px，1.0–3.0）。`None` = 跟随主题（1.5，§5.4 的屏幕空间恒定口径）。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub width: Option<f32>,
}
```

- **兼容**：与 `Relationship.color` / `head` 完全同款——缺键读成默认值，默认值不写回文件，
  不升 `FORMAT_VERSION`；旧版本读新文件只会忽略这两个键（serde 默认忽略未知字段）。
- **代价**：`SceneRelationship` 要带 `dashed` / `width`；wgpu 画线目前是整段 quad，
  虚线要么在 `scene.rs` 里把线段切成 dash 段（几何变多、`Scene` 变重），
  要么在 shader 里按屏幕坐标做 dash（要新增 uniform/attribute）。
  **两种都要重拍全部 `cm-*` 基线**（线宽进 `Scene` 会改所有既有线的几何）。
- **回滚**：删两个字段 + 删 apply 分支 + 删渲染分支。
- **验收**：单测（往返、撤销、缺键默认）、新场景 `cm-line-dash` / `cm-line-width`。

### 12.2 关系线注释（§12.2 第 19 项）· **已实现（CM-16）**

```rust
pub struct Relationship {
    // …现有字段…
    /// 命题的补充说明（不是短语本身，不进「命题」的读法）。`None` = 没有。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub note: Option<String>,
}
```

- **为什么不能复用短语**：短语是命题的谓词（「导致」），必须短、要进检索标题；
  注释是给这条命题的解释（「2026Q3 的数据」），可以长、不该被当成谓词读出来。
- **代价**：小。检查器加一个多行框（`SetRelationshipNote` 一条命令），画布上加一个小角标
  （与节点卡片圆点同款，5px）。**不动渲染管线**。
- **验收**：单测（往返、撤销、长度上限）、新场景 `cm-rel-note`。

### 12.3 嵌套概念 / 分组（§12.2 第 16、17 项）· **仍待拍板**

这两项**不建议**用「再加一个可选键」的方式做，原因是它们改的是**结构**而不是属性：

- 嵌套概念要让一个概念「拥有」别的概念，等于在命题网里再插一层包含关系；
  一旦落地，`concept_tree::concept_rows`（大纲）、`concept_layout`（分层）、
  导出、检索、`validate` 全都要认这层关系，否则会出现「大纲里看不见、导出里丢了」的半吊子状态。
- 分组更像「画布上的一块区域」：可以只存 `{ id, label, members, rect, color }` 到 `meta`，
  不改 `Node`；但拖动/缩放组、把概念拖进拖出、与整理布局的关系，都要单独定义。

**建议**：等 §12.1 / §12.2 落地并跑完一轮门之后再立项，且先写验收场景（至少 5 张金样：
建组、拖组、拖入/拖出、解组、导出）再动数据。

## 13. 概念分组（`groups` 顶层键，2026-11-01，CM-18）· **已实现**

> 背景：CM-15 复审第 ⑰ 项。CmapTools 能把若干概念框成一组（可命名、可整体拖动、可解组）。
> 织思没有这个能力，且 `Boundary` **用不了**——它只圈「同一父级的直接子节点」，概念图没有父子。
> **拍板（2026-11-01，用户选「批准分组 v1」）**：按本节字段实现，合同见 `docs/30` §5.5.1。
> 实现与提案的差异只有一处：`MoveGroup` 没有走 `Batch[MoveConcept]`，而是自己一条命令
> 直接挪成员（少一层嵌套，撤销文案也干净）。

### 13.1 为什么不能复用现有字段

| 候选 | 为什么不行 |
| --- | --- |
| `Boundary`（边界） | 目标必须是「同一父级的直接子节点」；概念图里所有概念都是浮点根，建不出来 |
| `Node.parent_id` | 那是树语义。给概念图挂父子会把「概念图不用 parent/children 表达关系」这条根规则推翻 |
| 把成员写进某个概念的 `style` | 组是**多个概念**的关系，不是某个概念的属性 |

结论：需要一个**文档级**的新集合，即顶层键 `groups`。

### 13.2 字段

```rust
/// 概念分组：把若干概念框在一起，可命名、可整体拖动、可解组。
/// 组不是「父子关系」——成员仍是独立的浮点概念，删组不会删概念。
#[derive(Serialize, Deserialize, Clone, Debug, PartialEq, Default)]
#[serde(rename_all = "camelCase", default)]
pub struct ConceptGroup {
    pub id: String,
    pub label: String,
    /// 成员概念 id。重建时按「成员还存在」逐条过滤，空了就整组丢弃。
    pub members: Vec<String>,
    /// 组框颜色（#rrggbb）；`None` 跟随主题的 dim 色。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub color: Option<String>,
}
```

- 落盘位置：`FileDoc.groups`（顶层，缺省空数组且**空数组不写**）。
- **组框矩形不进文件**：它由「成员包围盒 + 24 内距」算出来（`Scene` 里算）。
  理由：矩形是派生量，写进文件就会和成员位置打架（成员一动，存下来的矩形就过期）。
  代价：用户不能「把组框拖大」——那属于下一版（要引入 `rect` 覆盖，届时再拍板）。

### 13.3 命令（都一条撤销）

| 命令 | 语义 |
| --- | --- |
| `CreateGroup { members, label }` | 从当前选中概念建组；成员 < 2 拒绝；成员已在别的组里 → 先从旧组摘掉（一个概念只属于一个组） |
| `DeleteGroup { id }` | **解组**：只删组框，概念一个不删 |
| `SetGroupLabel { id, label }` | 改名（空串回落「分组」） |
| `SetGroupColor { id, color }` | 改框色 |
| `MoveGroup { id, dx, dy }` | 整组平移 = 一条 `Batch[MoveConcept × N]`，一次撤销 |

### 13.4 交互（v1 的最小闭环）

- **建组**：概念多选菜单 →「创建分组」；组框左上角显示名字。
- **点组框**：等价于 `select_many(members)`——复用现成的多选拖动，**不新增拖动类型**。
- **改名/改色/解组**：组框右键菜单（或在检查器里）。
- **成员维护**：概念被删 → 重建时从 `members` 摘掉；组空了整组消失。不做「拖进/拖出组」。

### 13.5 代价与风险

- 顶层键是**格式变更**（虽然缺省不写、旧版本忽略未知键），必须按 `docs/32` 的规矩先在
  §5.2 记例外。
- 渲染：组框画在 L1 最底层（边界之前），圆角 12、1.5px 虚线、8% 淡底；
  PNG/SVG/PDF 三处都要加（与 `SceneBoundary` 同一段绘制的思路）。
- 命中：新增 `Target::Group(i)`，只做「点击选中成员」，不做拖动。
- **不做**：嵌套组、拖成员进出组、组内独立布局、组框手动缩放。

### 13.6 与「嵌套概念」（第 ⑯ 项）的区别

嵌套概念是「一个概念里装着别的概念」，它改变的是**结构**：大纲要显示层级、整理布局要认包含、
导出与检索都要跟着改。分组只是**视觉容器**，不改任何结构语义。
所以先做分组，嵌套概念单独一批、单独拍板。

## 14. 卡片归档（`NoteCard.archived`，2026-11-01，CER-22）· **已拍板并实现**

### 14.1 为什么不能复用现有字段

`docs/28` §7.1 把侧栏改成五个入口：全部卡片 / 收件箱 / 未打标签 / 归档 / 标签树，
其中「收件箱不再等于全部卡片」。要区分这四者，需要三个正交的判定：

| 判定 | 现有字段能不能表达 |
| --- | --- |
| 有没有标签 | 能：`tags.is_empty()` |
| 有没有挂到导图节点 | 能：`source_node.is_some()` |
| 有没有被用户**收起来** | **不能** |

第三条是唯一缺的。当时库里有两个候选，都否掉了：

- **复用 `source_node`**：旧的 `NoteStore::archive_to_node` 就是拿「挂到节点」当「归档」。
  但挂节点是**整理**（这张卡属于某张图），归档是**收起**（这张卡我不想再在列表里看到）。
  一张卡完全可以既挂着节点又被归档；拿一个字段表达两件事，就会出现
  「取消归档顺手把来源节点也清了」这种解释不通的行为。
- **加一个「归档时间戳」`archived_at: Option<i64>`**：能表达，但库没有「按归档时间排序」
  的需求（§7.4 三种排序里没有它），多存的时间戳只是没用的字节。

### 14.2 字段

```rust
pub struct NoteCard {
    // ……原有字段不动……
    #[serde(skip_serializing_if = "is_false")]
    pub archived: bool,
}
```

- **camelCase**：`archived`（无下划线，序列化后同名）。
- **缺键即老行为**：`#[serde(default)]` 在结构体上，老 `.zmind` / 老卡片 Markdown /
  老 `index.json` 读回来是 `false`。
- **只在 `true` 时写键**：未归档的卡片**字节不变**，所以既有的格式夹具、
  `card_folders_export_import_byte_exact_and_keep_tags` 的字节级断言、
  以及所有 `card-*` 金样都不漂。
- **不升 `FORMAT_VERSION`、不写迁移、不引数据库。**
- 三处编码同时认这个键：`.zmind` 内嵌卡片（JSON）、独立卡片 Markdown 的 front matter
  （`mw_format::card_markdown`）、本地库索引 `index.json`（`CardMeta.archived`，
  索引坏了本来就会扫盘重建，所以 `INDEX_VERSION` 也不升）。

### 14.3 语义边界

- 归档**不改内容**，所以 `set_archived` **不碰 `updated_at`**：
  否则按「最近更新」排序时，归档这个动作会把卡片顶到列表最前面。
- 归档卡离开「全部卡片 / 收件箱 / 未打标签」，只留在「归档」里；
  标签树的计数也只算未归档卡（§7.1）。
- 检索不自己判定归档：`NoteStore::library_hits` 只返回命中 id 集合，
  作用域由 `mw_core::note::CardQuery` 统一裁决——否则「在归档里搜」永远搜不到东西。
- 旧 API 改名以消除歧义：`archive_to_node` → `attach_to_node`、`unarchive` → `detach_from_node`。

### 14.4 落点与证据

- 领域层：`crates/mw-core/src/note.rs`（字段 + `CardRef` / `CardScope` / `CardQuery` /
  `scope_counts` / `tag_tree`）。
- 编码层：`crates/mw-format/src/lib.rs`（front matter 只在 `true` 时写）。
- 存储层：`crates/mw-shell/src/note_store.rs`（`CardMeta.archived` + `set_archived`
  等批量 API，逐 id 报告）。
- 证据：`shots/x100/CER-22/`；单测 `new_cards_start_unarchived`（core）、
  `embedded_card_json_treats_missing_archived_as_false` /
  `card_markdown_round_trips_and_rejects_garbage`（format）、
  `archiving_keeps_updated_at_and_survives_reopen` /
  `archived_cards_only_show_up_under_archive` / `batch_reports_every_id_including_failures`（store）。

### 14.5 回滚路径

删掉字段与 `is_false`，三处编码回到原样即可：因为 `true` 才写键，
**已归档的卡片文件里会残留一个 `archived: true` 键**，回滚后旧代码按「未知键」忽略
（`unknown_keys_survive_a_read_save_read_roundtrip` 已经钉住这条），
再存一次就自然消失。不需要迁移脚本。

## 15. 样式覆盖三个可选键（`weight` / `align` / `radius`，2026-11-02，SE-13）· **已实现**

### 15.1 为什么这次动 `StyleOverride`

`docs/30` §4.2 的必选能力清单里，字重（400/500/600）、文本对齐、圆角三项一直没有字段承载：
`StyleOverride` 只有 `bold: Option<bool>` 这样的二值，形状也只有 `Shape` 的四档枚举，
圆角半径是渲染层按形状算出来的常数。SE-10 把这三项判为 `延后`，理由就是「要动 `StyleOverride`、
属数据模型变更，需单独批准」；G-B3-2 第 4 条判词（能力清单齐全）因此卡在 4/5。

### 15.2 字段

```rust
pub struct StyleOverride {
    // ……原有字段不动……
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub weight: Option<u16>,   // 400 / 500 / 600
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub align: Option<String>, // left / center / right
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub radius: Option<f32>,   // 0–24
}
```

- **三键全部可选**：缺键 = 老行为（字重回退 `bold ? 600 : 400`、左对齐、形状自带圆角）。
- **`bold` 变成别名**：`true` 解析成 **600**（不是 700）。TYPO-01 定的画布粗体字面就是
  Segoe UI Semibold 600，取 700 会把所有既有基线的粗体字宽换掉——「缺键即老行为」优先。
- **`shape` 增加 `ellipse` 与 `underline` 两个值**：`Shape` 枚举本来就有这两档（概念图/下划线），
  只是 `StyleOverride::shape` 的字符串到枚举映射没开放；本轮只开放映射，不新增枚举档。
- **不升 `FORMAT_VERSION`、不写迁移**：三个键都是 `Option` + `skip_serializing_if`，
  旧文件缺键读成 `None`；没设过就不写键，既有 `.zmind` 与字节级夹具一个字节都不变
  （`StyleOverride` 整体仍是 `Option`，整个样式对象都没有覆盖时写 `null`，这是既有形态）。

### 15.3 生效点（一处解析、多处消费）

| 位置 | 用法 |
| --- | --- |
| `mw_core::theme::resolve_all` | `weight` 夹 400–700、`align` 走 `TextAlign::from_name`、`radius` 夹 0–24 |
| `mw_core::text::TextMeasurer` | 度量签名从 `bold: bool` 改成 `weight: u16`，盒宽跟着字面走 |
| `mw_core::scene` | `BoxKey` 增加 `weight` 字段，换字重必须重测盒宽 |
| `mw-render`（`dwrite` / `text`） | 文本格式按 `(size, weight)` 缓存；`TextJob.weight` / `OutlinedText.weight` |
| `mw_render::corner_style` | 圆角覆盖只对 `rounded` / `rect` 生效，椭圆走负哨兵 `ELLIPSE_CODE` |
| 导出（SVG / PDF） | SVG 写真实 `font-weight`、`text-anchor` 跟对齐走；PDF 走字形轮廓，天然同源 |

### 15.4 回滚路径

删三个字段 + 删解析分支 + 恢复 `TextMeasurer::measure(bold)` 签名即可回到 SE-10 的状态；
没有文件迁移、没有历史数据要重写。
