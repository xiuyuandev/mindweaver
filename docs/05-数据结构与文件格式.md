# 05 · 数据结构与文件格式

> 状态：**当前实现** · 更新：2026-10-19 · 上游：04 · 下游：07、10
>
> 本文以代码为准：`mw-core` 模型 + `mw-format` 的 `.zmind` 读写。格式**尚未对外冻结**，`formatVersion` 与 `content.schema` 目前都是 1；测试数见 [`STATUS.md`](STATUS.md) §1（本文不再复制快照）。
>
> 当前能力边界：
>
> - 已实现：`.zmind` 读写、临时文件落盘 + `*.zmind.bak` 滚动备份；
> - 已实现导入：`.zmind` / Markdown / 缩进文本 / OPML / FreeMind / XMind（**XMind 只导入，不导出**）；
> - 已实现导出：PNG / SVG / PDF / Markdown / 纯文本大纲 / OPML / FreeMind；
> - **未实现**：缩略图、HTML 导出、XMind 导出、自定义主题对象（`.ztheme`）、附件的真实读写、外部修改检测、单实例。

## 1. 设计原则

1. **人读得懂**：容器内全部为 UTF-8 JSON，文本编辑器可直接查看（便于用户信任与第三方工具处理）；
2. **补丁友好**：扁平节点表（id → node），子树局部变更天然映射为小补丁；
3. **前向兼容**：未知字段一律忽略不报错（模型结构体均为 `#[serde(default)]`，未开 `deny_unknown_fields`）；写入侧会把 `Option` 写成 `null`，只有 `themeAccent` 在缺省时整键省略；
4. **只加显式字段**：容器预留 `assets/` 条目；模型**没有**通用 `ext` 扩展袋，新能力以有类型的字段加入（如 v7 的逐节点样式），避免出现无人校验的 JSON 黑洞；
5. **计算与存储分离**：凡可推导的数据一律不入文件——布局坐标、拼音索引、级联后的样式都不存；唯一例外是**自由主题的 `pos`**，它是用户亲手摆放的数据，不是推导结果。

## 2. 内存模型（mw-core）

JSON 键统一为 camelCase；Rust 字段为 snake_case。

### 2.1 Node（节点）

| 字段（JSON） | Rust 类型 | 必填 | 说明 / 约束 |
| --- | --- | --- | --- |
| `id` | `String` | ✔ | UUID v7 文本；全文档唯一 |
| `parentId` | `Option<String>` | ✔ | 主根与自由主题为 `null`；其余指向父节点 |
| `children` | `Vec<String>` | ✔ | 有序子节点；与子节点的 `parentId` 双向一致（`Document::validate` 保证） |
| `text` | `String` | ✔ | 标题；≤2,000 字符；可含 `\n`（软换行） |
| `note` | `Option<String>` | | 备注；≤10,000 字符 |
| `link` | `Option<String>` | | URL 或本地路径；≤2,048 字符 |
| `icon` | `Option<String>` | | 12 个内置 key：`priority-1..6` / `task-todo` / `task-doing` / `task-done` / `star` / `question` / `exclaim`；未知 key 按无图标渲染 |
| `labels` | `Vec<String>` | ✔ | 节点下方的标签胶囊；最多 5 个，每个 ≤64 字符 |
| `relationships` | `Vec<Relationship>` | ✔ | 关系线，起点为本节点；见 §2.1.1 |
| `boundaries` | `Vec<Boundary>` | ✔ | 边界，圈住 `targets` 指定的直接子节点 |
| `summaries` | `Vec<Summary>` | ✔ | 概要，覆盖 `targets` 指定的直接子节点 |
| `collapsed` | `bool` | ✔ | 折叠状态；入文件以跨会话保持 |
| `style` | `Option<StyleOverride>` | | 节点级覆盖（§2.3）；`null` = 无覆盖 |
| `pos` | `Option<Position>` | | 自由主题的世界坐标 `{x, y}`；非自由主题带 `pos` 会被校验器拒绝 |
| `modifiedAt` | `i64` | ✔ | Unix 毫秒时间戳（展示用） |

#### 2.1.1 附属结构

| 结构 | 字段 | 说明 |
| --- | --- | --- |
| `Relationship` | `id` / `to` / `label?` / `color?` / `head?` | `to` 为目标节点 id；`label` ≤200 字符；`color` 为 HEX；`head` 取 `off` / `forward` / `backward` / `both`，**缺键即 `forward`**（等值时不写键），见 §2.1.2 |
| `Boundary` | `id` / `targets` / `color?` | `targets` 为直接子节点 id 列表；`color` 为 HEX |
| `Summary` | `id` / `targets` / `text` | `targets` 为直接子节点 id 列表；`text` ≤200 字符 |
| `Position` | `x` / `y` | 世界坐标（f32） |

> 森林语义：`rootId` 是主根；`parentId == null` 的其他节点是「自由主题」，各自构成独立小树。模型、场景与 `Command::AddFloatingTopic / SetNodePos / DetachNode` 已支持；**壳层入口 2026-11-02 已补齐**（新建自由主题、拖放分离、`Ctrl+Shift+N` 一类入口在 `mw-shell` 画布与命令面板里，缺口表见 [`archive/11-实现状态.md`](archive/11-实现状态.md)，现状以 [`STATUS.md`](STATUS.md) §1 为准）。

#### 2.1.2 关系线端点箭头（2026-10-27 新增）

| 键 | 值 | 画的箭头 |
| --- | --- | --- |
| 缺省 / `forward` | 默认 | 只在终点端画 |
| `off` | 显式不画 | 两端都不画，但仍是一条线（语义是「相关」） |
| `backward` | 反向 | 只在起点端画 |
| `both` | 双向 | 两端都画 |

> 不升 `FORMAT_VERSION`：缺键 = `forward` = 本键引入之前的行为，老文件打开后逐像素不变。
> 「没有箭头」是 `off`，不是缺键——缺键必须留作默认值，否则老图会突然掉箭头。
### 2.2 Document（文档）

| 字段 | 类型 | 持久化位置 | 说明 |
| --- | --- | --- | --- |
| `id` | `String` | `manifest.docId` | 文档标识；与文件名解耦，`content.json` 里不重复存 |
| `meta.title` | `String` | `manifest.title` | 文档标题 |
| `meta.theme` | `String` | `content.theme` | 内置主题 id：`snow` / `mint` / `inkNight` / `forest`；未知 id 回退 `snow` |
| `meta.themeAccent` | `Option<String>` | `content.themeAccent` | 自定义强调色 `#rrggbb`；`None` 时整个键不写 |
| `meta.layout` | `LayoutSettings` | `content.layout` | 见 §2.2.1 |
| `rootId` | `String` | `content.rootId` | 主根节点 |
| `nodes` | `HashMap<String, Node>` | `content.nodes` | 扁平节点表 |
| `revision` | `u64` | **不持久化** | 运行时修订号，每次命令 +1；用于对账与测试 |
| `undo_stack` / `redo_stack` | `Vec<ChangeSet>` | **不持久化** | 撤销/重做内存栈，上限 500 条 |
| `search` | `SearchIndex` | **不持久化** | 拼音/子串检索缓存 |

#### 2.2.1 LayoutSettings

平铺对象，没有 `options` 包装层：

```json
{ "kind": "mindmap", "siblingGap": 24.0, "levelGap": 80.0, "maxNodeWidth": 300.0 }
```

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `kind` | `String` | `mindmap` | `mindmap` / `logicRight` / `orgChart` / `fishbone` / `timeline`；未知值回退 `mindmap` |
| `siblingGap` | `f32` | 24.0 | 同级间距 |
| `levelGap` | `f32` | 80.0 | 层间距 |
| `maxNodeWidth` | `f32` | 300.0 | 节点最大宽度（排版换行依据） |

### 2.3 样式覆盖（StyleOverride）

全部字段可选；省略或 `null` = 继承。模型层**不做数值钳制**，UI 负责给出可选范围（字号菜单为 12/14/16/18/20/24/28/32/40 px）。

| 字段（JSON） | 类型 | 说明 |
| --- | --- | --- |
| `fill` / `textColor` / `stroke` | `Option<String>` | 六位/八位 HEX |
| `strokeWidth` | `Option<f32>` | 描边宽度 |
| `bold` / `italic` | `Option<bool>` | — |
| `fontSize` | `Option<u16>` | 字号（px） |
| `shape` | `Option<String>` | `rounded` / `rect` / `capsule` / `ellipse` / `underline`；未知值回退 `rounded` |
| `radius` | `Option<f32>` | 圆角半径 0–24（SE-13，2026-11-02）；只对 `rounded` / `rect` 生效，缺键按形状默认值 |
| `align` | `Option<String>` | 文本水平对齐 `left` / `center` / `right`（SE-13，2026-11-02）；缺键 = 左对齐（概念图另由 `center_text` 居中） |
| `weight` | `Option<u16>` | 字重 400 / 500 / 600（SE-13，2026-11-02）；缺键回退 `bold ? 600 : 400`，`bold` 是 600 的兼容别名 |
| `branchColor` | `Option<String>` | 该节点向下整条分支的连线颜色与派生色源：自身及子孙的连线/描边/淡染跟随；深度 1 节点若显式设置，其卡片填充改为 `theme.branch_fill(color)`（v7） |
| `applyTextToSubtree` | `Option<bool>` | 文字色是否作用于未覆盖的子孙（默认 false）；只影响文字色，不传字号/字重/斜体 |

## 3. 样式级联（core 中的确定性解析）

解析顺序（后命中者覆盖前者）：

```
① 主题默认令牌（背景/连线风格/各级形状与字号/调色板）
   → ② 级别样式（按 depth 取主题的 level token，超出深度循环最后一档）
     → ③ 分支继承（branchColor 沿祖先链向下；显式设置即成为该子树的派生色源）
       → ④ 节点显式覆盖（node.style）
```

- `theme::resolve_all(doc, theme)` 每次构建场景时重新计算，结果同时供画布、SVG 与离屏 PNG/PDF 使用，**全进程只有一套色值**；
- 调色板：主题给出 8 色循环序列，一级分支按序取色，子孙默认继承分支色；
- **v7 派生规则**（`core/theme.rs`）：
  - 一级卡片填充：有显式 `branchColor` → `theme.branch_fill(branch)`；否则 `palette_fill_at(sibling_idx)`；
  - 二级及更深卡片：`level.fill.mix(branch, 0.07)`——整条分支读成一个色系，而不是一排白卡；描边 `mix(branch, 0.20)`；
  - `branch_fill`：亮色主题 = 白色与分支色 `mix 0.5`；暗色主题 = 面板底色与分支色 `mix 0.2`；
  - `applyTextToSubtree` 只控制文字色是否下传；字号/字重等覆盖默认不下传。

## 4. `.zmind` 容器结构（mw-format）

### 4.1 ZIP 条目表

| 条目 | 压缩 | 当前写出 | 说明 |
| --- | --- | --- | --- |
| `mimetype` | STORED | ✔ | 固定字符串 `application/vnd.mindweaver.zmind`，写入时置于首个条目 |
| `manifest.json` | DEFLATE | ✔ | 元数据与版本（§4.2），pretty JSON |
| `content.json` | DEFLATE | ✔ | 文档主体（§4.3），紧凑 JSON |
| `thumbnail.png` | — | ✖ | **规划项**：当前 `save()` 不生成缩略图 |
| `assets/*` | — | ✖ | 1.x 图片/附件预留；文件名规划为 UUID+扩展 |
| `ext/*` | — | ✖ | 历史/插件数据预留；无读写实现 |

> 读取器当前只校验并读取 `manifest.json` 与 `content.json`：`mimetype` 是写入约定，不是打开文件的硬门槛。条目顺序、STORED/DEFLATE 只在写入侧保证。

### 4.2 manifest.json

```json
{
  "formatVersion": 1,
  "app": "MindWeaver/0.1.0",
  "docId": "0193f8c2-7a1b-7000-8000-3fa2e1b2c3d4",
  "title": "产品规划",
  "createdAt": 1760597400000,
  "modifiedAt": 1760613731000,
  "nodeCount": 3
}
```

- `createdAt` / `modifiedAt` 是 **Unix 毫秒整数**，不是 ISO 字符串；`createdAt` 在覆盖保存时沿用旧 manifest 的值；
- `nodeCount` 取 `Document::node_count()`（含自由主题）；
- 没有 `locale` 字段。

### 4.4 自定义主题（未实现）

`theme` 目前只是内置主题 id 字符串；不存在内嵌 `theme.custom` 对象，也没有 `.ztheme` 文件读写。唯一的主题级自定义是 `themeAccent`（只取色相，明度/饱和度由主题保住）。自定义主题属于 1.x 方向（`10`），**不要按旧草案里的 `theme.custom` 形状读写**。

## 5. schema 版本与迁移策略

当前实现（只有 v1）：

- 写入：`manifest.formatVersion = content.schema = FORMAT_VERSION = 1`；
- 读取：只校验 `manifest.formatVersion`；更高版本直接拒绝并提示「此文件由更新版本的织思创建」，绝不猜测解析；
- `content.schema` 字段已解析但**尚未单独校验**；`manifest` 更高版本已足以挡住未来文件；
- **没有迁移器链**，也没有「已从 vX 升级」提示——v1 是唯一存在的格式。

未来冻结与升级纪律（尚未实现，写在这里防止走偏）：

1. `manifest.formatVersion` 管容器，`content.schema` 管内容，两者独立递增；
2. 只读旧不读新；迁移器链式执行（v1→v2→…），每步配固定样本测试；
3. 打开旧版后另存 `.bak`，再写新版；不静默覆盖唯一副本。

## 6. 读写安全（mw-format / mw-shell 现状）

| 主题 | 当前实现 | 状态 |
| --- | --- | --- |
| 写入中断 | 先写同目录临时文件 `.{文件名}.tmp`；若正本存在，先改名为 `{文件名}.bak`，再把临时文件改名为正本 | ✔ 已实现；不是 `ReplaceFile`，改名窗口内正本可能短暂缺失，但 `.bak` 是完整旧文件 |
| 滚动备份 | 每次覆盖保存前删除旧 `.bak` 再改名；只保留一份 | ✔ |
| zip bomb | 解压总大小 ≤256MB、单条目 ≤64MB、条目数 ≤1,024 | ✔ |
| Zip Slip | `enclosed_name()` 拒绝绝对路径与 `..` | ✔ |
| XML 外部实体 | 导入使用 quick-xml，默认不解析 DTD/外部实体 | ✔ |
| 版本守卫 | `manifest.formatVersion > 支持版本` → 拒绝 | ✔ |
| 自动保存 | 每 3 秒后台写恢复点，不碰正本；正本保存后作废恢复点；启动仅接受比正本新的恢复点 | ✔ |
| 恢复点路径 | 已落盘文档：`<文档目录>/.autosave/<stem>.autosave.zmind`；未命名：`%APPDATA%\织思\autosave\未命名.autosave.zmind` | ✔ |
| 缩略图 | 无 | ✖ 规划 |
| 外部修改检测 | 无 mtime+size 对账，也不提示重新载入 | ✖ |
| 单实例 | 无；同一文件靠「已开标签则切换」避免重复打开 | ✖ |

## 7. 导入导出映射

### 7.1 导入（mw-io，均已实现）

| 来源 | 映射规则 | 主要损失 |
| --- | --- | --- |
| `.zmind` | 原生往返（`mw-format`） | 无（未知字段被忽略） |
| Markdown | H1–H6 建主干；`-`/`*`/`+`/有序列表按缩进挂载；`>` 与普通行归入上一节点备注 | 行内强调、代码块/链接语法不解析（按纯文本进备注） |
| 缩进纯文本 | 首行为根；Tab 按 4 空格计；缩进单位取相邻层级差的最小值 | 空行 |
| OPML | 嵌套 `outline`；`text`/`title` → 标题；`_note` → 备注 | 自定义属性 |
| FreeMind `.mm` | `node` 的 `TEXT`/`FOLDED`/`COLOR`/`LINK`；`richcontent` 文本 → 备注 | 云、箭头、自定义图标 |
| XMind | `content.json` 与 `content.xml` 双解析；title/notes/折叠/markers→icon/labels/relationships/floatingTopics→`pos` | 边界、概要、评论、逐节点样式、链接、图片附件 |

### 7.2 导出（mw-shell，均已实现）

| 目标 | 实现方式 |
| --- | --- |
| PNG | 离屏 wgpu 渲染整棵主题树（折叠子树也导出）；可选缩放与透明背景，超上限按比例回退并提示 |
| SVG | 独立几何→标记管线，矢量文字与图形；与 PNG 共用同一取景框 |
| PDF | 第一版内嵌一张离屏位图（不是矢量 PDF） |
| Markdown | 根=H1，深度 1–5→H2–H6，更深转列表；备注→引用块 |
| 纯文本大纲 | 深度 × 缩进单位 + `- ` 前缀 |
| OPML | 树→嵌套 `outline` |
| FreeMind | 节点属性尽力写出，保证 FreeMind 可打开 |

**未实现导出**：XMind、HTML（旧草案里的单文件双视图没有落地）。
