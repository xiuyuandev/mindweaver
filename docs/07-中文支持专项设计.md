## 1. 范围定义

"完美支持中文编辑"在本项目中拆解为六个子域，各自有硬性验收标准：

| 子域 | 内容 | 章节 |
| --- | --- | --- |
| 输入 | IME 组合输入（拼音/五笔/形码）、快捷键与组合期冲突 | §3 |
| 排版 | CJK 禁则、中英混排、全半角、标点 | §4 |
| 字体 | 界面/画布/导出三端字体一致与回退 | §5 |
| 检索 | 拼音全拼/首字母/多音字搜索 | §6 |
| 文件 | CJK 文件名/路径/拖拽/长路径 | §7 前 2 条 |
| 导出 | 导出物中中文保真（文本层/字体/命名） | §7 |

## 2. 基础设施决策

- 全链路 UTF-8：JSON、日志、剪贴板文本、IPC 字符串一律 UTF-8；
- **编辑态使用 WebView 原生 DOM 输入元素**（06 §7）：这是中文体验的架构基石——候选窗定位、预编辑（preedit）下划线、组合文本内联显示全部由 Chromium 管线原生处理，与用户在 Edge 中的输入体验完全一致；
- 日期/时间/数字格式化使用 zh-CN locale（`Intl` + Rust 侧 `jiff`/手动 zh 格式）。

## 3. IME 协调（规则可穷举，前端 `input/ime.ts` 统一实现）

### 3.1 状态机

```
非编辑 ──(F2/双击/直接输入)──▶ 编辑·未组合 ──(compositionstart)──▶ 编辑·组合中
   ▲                              │  ▲                                │
   │◀──(提交/取消)────────────────┘  └────(compositionend)────────────┘
```

### 3.2 事件行为表（实现与测试的唯一依据）

| 按键/事件 | 编辑·未组合 | 编辑·组合中（isComposing） |
| --- | --- | --- |
| 可打印字符/组合输入 | 正常输入 | IME 消费，应用零干预（R1） |
| `Enter` | 提交编辑 → 触发语义（如"新建同级"仅当来自编辑提交热键） | IME 上屏候选，**不提交编辑**（R2） |
| `Tab` | 提交编辑 → 新建子节点 | IME 内部/忽略，**不新建**（R2） |
| `Esc` | 取消编辑还原 | 取消候选（IME），**不取消编辑**（R2） |
| `Del / Backspace` | 正常删除 | IME 消费 |
| `方向键 / Home / End` | 光标移动 | IME/光标消费 |
| 全局快捷键（Ctrl+S/Z/F/K…） | 正常执行 | **一律吞掉不执行**（R3） |
| 窗口失焦 | 提交已确认文本，丢弃未上屏组合 | 同左（compositionend 先于 blur 到达） |
| 画布平移（空格+拖） | 可用 | 可用（编辑元素跟随节点） |
| 缩放（Ctrl+滚轮） | 可用 | **锁定**（防候选窗与光标错位，R4） |

### 3.3 实现规则（代码评审检查项）

- **R1**：所有键盘事件处理器以 `event.isComposing || event.keyCode === 229` 为第一道守卫（229 为 Windows IME 事件序号残留，双保险）；
- **R2**：组合期间 `Enter/Esc/Tab` 等语义键不得穿透到应用层（不得新建/取消/提交）；
- **R3**：组合期间禁用一切全局快捷键（含 Ctrl+S/Ctrl+Z/Ctrl+F/Alt+Enter/F9…）；
- **R4**：组合期间锁定画布缩放与"适应画布"类视口变化；平移允许但编辑元素同步跟随；
- **R5**：文本仅在**编辑会话提交**时打包为 `SetText` 命令（04 §5.2），组合中的字节永远不进命令流、不进撤销栈、不触发自动保存；
- 组合期间状态栏显示输入法状态图标（通过 Windows 输入法指示器 API，P2）；
- 剪贴板：中文文本读写无 NFC/NFD 强制归一（保留用户原始形式），比较时按 NFC 归一。

## 4. 排版规范

| 项 | 规则 | 实现方 |
| --- | --- | --- |
| 行首禁则字符 | `，。、；：？！）】」』》…—·%` 等不出现在行首 | 浏览器排版引擎（CSS 内建），**无需自研** |
| 行尾禁则字符 | `（【「『《` 等不出现在行尾 | 同上 |
| 中英混排间距 | 中文字符与拉丁/数字之间渲染空隙 0.1em（视觉更佳） | P1 用 CSS 字距微调实现，系统不支持时跳过；P2 评估 `text-autospace` |
| 全角/半角 | 输入什么显示什么（不擅自转换）；节点文本统计按"全角=1、半角=0.5"显示字数（P2） | 前端 |
| 标点 | 顿号、省略号 `……`、破折号 `——` 原样保留（不做"智能替换"，避免干扰专业输入） | 前端 |
| 软换行 | `Shift+Enter` 插入 `\n`；自动折行宽度由布局参数控制（02 §3） | 浏览器 |
| 行内 Emoji | 回退链含 `Segoe UI Emoji`；Emoji 不参与禁则计算 | 字体栈（§5） |
| 导出一致性 | **前端排版为唯一权威**：导出用前端产出的已分行文本（tspan），两端禁则结果天然一致（04 §5.4） | 场景图契约 |

## 5. 字体策略（三端一致）

| 端 | 字体栈 | 说明 |
| --- | --- | --- |
| 界面（Chrome/面板） | `"Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans SC", "Segoe UI", sans-serif` | 雅黑 UI 是 Windows 中文 UI 标配，米字间距与 ClearType 调优最好 |
| 画布节点 | 同上（同一 CSS 变量驱动，编辑态与 SVG 渲染零差异） | 保证编辑→提交无字形跳动 |
| 导出（resvg/fontdb） | 系统字体库加载，查找顺序：微软雅黑 → 等线 → Noto Sans SC；SVG 导出提供"文本转路径"选项保证他机一致 | Win10/11 均预装雅黑，跨机差异极小 |

- 捆绑字体策略：v1 **不捆绑**（Windows 必有雅黑；避免包体与许可问题）；若用户反馈等宽/衬线需求，1.x 评估捆绑思源黑体子集（OFL 许可，03 §9）；
- 字体渲染：WebView2 默认开启 ClearType 与亚像素抗锯齿，禁止关闭抗锯齿的 CSS。

> ⚠️ §5 的三端字体栈**择一顺序照旧有效**（雅黑 UI → 雅黑 → Noto Sans SC → Segoe UI，`mw-render::dwrite` 已按此实现，locale `zh-Hans`、粗体 600；egui 侧由 `mw-shell/src/fonts.rs` 装 `msyh.ttc` **face index 1**），但载体全换：
> · 「同一 CSS 变量驱动」→ 编辑态与渲染态共用**同一份 `Scene` + 同一套 DirectWrite 度量**，节点盒随输入实时增长（13 §4.12），比旧版的"零差异"更强；
> · 「ClearType / 禁关抗锯齿的 CSS」→ 自绘路径改为 **R8 单通道灰度字形图集**（主路径 `IDWriteFactory2` 的 `ALIASED_1x1` 栅格；基工厂 ClearType 只作兜底，按亮度合回灰度）+ **gamma 空间预乘混合** + 无 MSAA 的解析抗锯齿（带宽由 uniform 推导，不用 `fwidth`，为的是容差 0）。**「不许发虚」的要求不变**，已用四档 ppp（1.0/1.25/1.5/2.0）物理高度线性与文字 golden 容差 0 验收（13 §4.7/§4.9）；
> · 表中「导出（resvg/fontdb）」一行**作废**：resvg / svg2pdf 依赖从未进入原生栈，PNG/SVG/PDF 由 `mw-render` 离屏 + `Frame.viewport = None` 承担，M4 落地；
> · 「不捆绑字体」的策略不变（Windows 必有雅黑）。

## 6. 文件系统与 CJK 路径

- 全部路径 API 走 Rust `std::path` + Windows UTF-16 边界（`wide` 转换），杜绝 `char` 型 ANSI 路径 API；
- 支持场景全测：中文文件名/目录名、Emoji 文件名、空格/全角空格、超 260 字符路径（启用长路径感知）、UNC 路径（`\\server\share`）；
- 拖拽：从资源管理器拖入含中文路径文件、拖出导出文件（落桌面中文名）；最近文件列表正确显示与刷新；
- 导出默认文件名：`{文档标题}-YYYY-MM-DD.{ext}`（标题含非法字符 `\/:*?"<>|` 时替换为 `_`）。

## 7. 拼音检索（mw-core search 模块）

- 索引：节点**标题 + 备注 + 链接文本**（打磨轮 41 / M19；`docs/02` §4 的 P0 口径），
  以及概念图的**命题短语**（关系线 `label`，打磨轮 42 / C17；身份是「源节点 + 边 id」）→
  全拼小写串（`xiangmuqidong`）+ 首字母串（`xmqd`）；多音字取 rust-pinyin 常用音集合展开
  （匹配任一读音即命中）。备注/链接/命题短语的拼音索引只建到 240 字（`FIELD_PINYIN_CAP`），
  更长的文本仍可原文命中——20k 文档 × 长备注全量展开多音字会炸内存与首查耗时；
- 匹配：连续子串匹配（非首字母 T9 式），命中高亮返回命中字段内的字符区间（拼音命中映射回原文区间）；
  备注/链接/命题命中时结果行显示**命中处的摘录**（前后各 24 字，两端 `…`），高亮区间折算到摘录坐标系；
- 排序：标题命中 > 备注命中 > 链接命中（同字段再按原文 > 全拼 > 首字母、越靠前分越高）；
  同一节点三个字段都命中时只出一条，取分数最高的字段；命题短语单独成组
  （原文 560 / 全拼 450 / 首字母 350），同分按源节点文档前序、再按边在节点内的下标；
- 示例：节点「项目启动」命中 `项目`、`xiangmu`、`xm`、`xmqd`、`qídòng`（多音字 `其/启` 交替亦命中）；
- 索引增量更新：命令提交后仅重建变更节点（04 §5.2 回调）；20k 节点全量重建预算 <100ms（08 §2）；
- 查找面板中拼音模式与文本模式统一输入框（自动识别 ASCII 字母即拼音匹配 + 文本匹配取并集，去重排序）。

## 9. 本地化与文案规范（zh-CN 源语言）

- 界面文案：简体中文、句号结尾可省（按钮与标签不加句号）；术语统一（节点/子节点/分支/画布/大纲/检查器，与文档术语表一致）；
- 敬语策略：对用户称呼「你」不用「您」（现代工具类产品惯例，与整体气质一致）；
- 数字与单位：阿拉伯数字 + 半角空格（`128 节点`）；日期 `YYYY-MM-DD`、时间 `HH:mm`（24 小时制）；
- 错误消息模板：`{动作}失败：{原因}。{建议操作}`，例：`保存失败：文件被其他程序占用。请关闭后重试。`
