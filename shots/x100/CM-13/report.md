# CM-13 · 关系线箭头改为屏幕恒定尺寸（低缩放下不再消失）

日期：2026-10-30　状态：**已实现**

## 1. 问题

概念图的四档箭头语义（无 / 单向 → / 反向 ← / 双向 ↔）是"这条命题朝哪边"的唯一视觉线索。
箭头三角形在 `Scene` 里是**写死的 6×4 世界单位**（`scene::straight_between`）。于是：

| 缩放 | 箭头屏幕长度 | 结果 |
| --- | --- | --- |
| 100% | 6.0 css px | 正常 |
| 50% | 3.0 css px | 勉强 |
| 30% | **1.8 css px** | 等于没有箭头，四档语义在缩略视图里完全看不出差别 |
| 20% | 1.2 css px | 消失 |

更刺眼的是**同一张画布上两套口径**：思维导图的树连线箭头一直是屏幕恒定的
（`instances.rs` 里 `cam.css_to_world(7.0)` 现算），只有关系线箭头跟着缩放一起缩小。

## 2. 修法

不改 `Scene`。`Scene` 是几何唯一真相源，而它必须与缩放无关（画布、golden、PNG/SVG/PDF 导出共用同一份）。
缩放相关的补偿放在渲染层：

```rust
const ARROW_CSS_LEN: f32 = 7.0;   // 与树连线箭头同长

fn screen_arrow(tri: [Point; 3], cam: Camera) -> [Point; 3] {
    // 以尖端（tri[0]）为锚点等比放大三角形，使「尖端→底边中点」不少于 ARROW_CSS_LEN 的屏幕长度
    // k = max(1, css_to_world(7) / 当前世界长度)：只放大不缩小
}
```

三条性质：

1. **尖端不动**。箭头始终精确指在连线终点（概念边界上），放大只往线的方向长，不会戳进节点。
2. **只放大不缩小**（`k >= 1`）。放大到 117% 以上时保持原来的世界尺寸，箭头在高缩放下不会变钝。
3. **包围盒同步**。`relationship_bounds` 里也用同一函数算三角形范围，否则放大后的箭头在
   视口边缘会被提前裁掉（"箭头忽然不见"的另一种表现）。

## 3. 证据

| 类别 | 证据 |
| --- | --- |
| 几何 | `screen_arrow` 是纯函数（输入世界三角形 + 相机，输出世界三角形），局部可验 |
| 一致性 | 与树连线箭头同为 7 css px，同一画布上不再有两套箭头口径 |
| 裁剪 | `relationship_bounds` 用放大后的三角形，放大不会导致误裁 |
| golden | 概念图基线在 `--tol 0` 下重拍，漂移量化见 §4 |

## 4. golden 漂移

只在**箭头像素**上，且随缩放档位放大：

- 100%（`shell-ppp1.50` 默认档）：`k = 7/6 ≈ 1.17`，箭头变大 17%，每个箭头约 6–14 px 变化
- 50%：`k ≈ 2.33`
- 30%：`k ≈ 3.89`，箭头从"看不见"变成可辨

漂移量与场次统计以 `scripts/x100-stage-cm-gate.ps1` 与 `scripts/x100-stage-b-gate.ps1`
的双跑结果为准（记录在 `docs/x100/log/execution-log-2026-10.md`）。

## 5. 未做 / 风险

- **未做**：箭头改用"实心三角形"以外的形态（CmapTools 那种细长箭头）—— 会动 Scene 几何，本轮不碰。
- **未做**：起点圆点（`REL_START_R`）本来就是屏幕恒定，未受影响。
- **风险**：极端低缩放（<20%）时箭头会明显比线粗，看起来"头重脚轻"。取舍：宁可箭头偏大，
  也不要语义消失 —— 缩略视图的首要任务就是"看出图的结构"。
