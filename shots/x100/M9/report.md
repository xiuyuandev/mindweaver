## 1. 这一轮要解决什么

账本 M9 行写着「折叠动画与点击热区」，两样都没有证据：场景层的单测
（`blend_collapse_slides_children_into_parent_and_edges_follow`）钉住了 `blend_scenes` 的中点，
但**壳层到屏幕这一路**没人拍过；热区只在 `toggle_center_hits_toggle_and_beats_parent` 里验了圆心，
把 `TOGGLE_HIT_CSS` 错写成世界单位那条单测照样过（圆心在哪种写法下都命中）。

要回答的是三件事：

| 问题 | 怎么答 |
| --- | --- |
| 折叠是瞬间跳变还是有过渡？ | `MW_MOTION_T` 分别钉 0.0 / 0.5 / 1.0，与终态比像素 |
| 过渡的中间帧长什么样？ | 定格 0.5 存成基线 `mm-collapse-mid` |
| 圆点的热区有多大、随缩放变不变？ | 点圆心下方 9px / 12px + 三个缩放档的单测 |

## 2. 非目标

- **不改**热区半径（现在是 `TOGGLE_R + 2 = 10 CSS px`）。没有任何证据说明它偏大或偏小，
  只把它**钉住**；要改得先有实机手感数据。
- 不改折叠动画的时长令牌（`SCENE_MIN 0.20s` / `SCENE_MAX 0.34s`）与曲线。
- 不碰 `SetCollapsedAll`（`Ctrl+Alt+0` 一类的整图折叠）与聚焦模式下的折叠语义。
- 不测触屏 / 触控笔（本机没有）。

## 4. 证据

### 4.1 折叠有过渡，不是瞬间跳变

同一段脚本（点「纯 Rust 原生」的圆点，屏幕 `(623,473)`）跑三次，只改 `MW_MOTION_T`，
与终态（不钉）比像素，`--tol 0`：

| 钉住的 t | 与终态不同的像素 | 最大差 | 怎么读 |
| --- | --- | --- | --- |
| 0.0 | 34374（1.965%） | 208 | 起点与终态差得最多——过渡真的从旧布局出发 |
| 0.5 | 27913（1.595%） | 191 | 中间帧既不是起点也不是终点 |
| 1.0 | **0** | 0 | 终点与终态逐字节一致——过渡不会停在半路 |

包围盒 `x[339..829] y[429..663]` 落在被收起的那两条分支（「winit + windows-rs」「wgpu 四层合成器」）
与它们的连线上，别的区域一个像素都没动。

### 4.2 热区：9px 还折叠，12px 不误折叠

圆点画出来是 `r8 + 1.5px` 底色光晕，命中半径 `TOGGLE_HIT_CSS = TOGGLE_R + 2 = 10`。
脚本点圆心正下方 9px（在环外、在命中半径内）与 12px（都在外）：

```
mm-toggle-edge  canvas_click at=(623,482) … hit=01a18416-…  toggle idx=1 collapsed=true kids=2
mm-toggle-miss  canvas_click at=(623,485) … hit=none        （没有 toggle 事件）
```

（`hit=` 打的是归属节点的 id，这里省掉全部 id 只留形状。）

**两张图逐字节相同**（`84BE6968C60C`）——热区的证据在轨迹里，不在图上：9px 与圆心那一击
落到同一个折叠终态，而 12px 那一击什么都没命中（`hit=none`，连节点都没选中，因为那一点在盒外）。

### 4.3 热区不随缩放走

新单测三档（0.5× / 1× / 2×）：圆心下方 `8/zoom` 世界单位必须命中、`12/zoom` 必须不命中。
这条钉住的是「CSS px 常量要除以缩放再比」——写成世界常量的话，50% 档的热区会缩到 5px、200% 档涨到 20px，
「看得见就点得中」立刻不成立。

## 6. 未做 / 风险

- **实机手感没量**：触控笔、按住不放、150%/200% DPI 下的实际点击，都只有离屏推理。
- **热区 10 CSS px 是原值**：直径 20px 比 Win11 的触控建议（44×44）小得多；鼠标点击够用，
  但要不要放大是产品决定，本轮没动。
- **只拍 ppp 1.0**：折算是纯 `css_to_world`，理论上与 ppp 无关，但没有金样作证。
- **整图折叠**（`set_all_collapsed`）与聚焦模式下的圆点没拍。
