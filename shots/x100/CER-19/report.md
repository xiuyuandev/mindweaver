# CER-19 · 专注模式与打字机模式（`已实现`）

> 合同：`docs/29` CER-19 行、`docs/28` §6.4。状态只用 `未开始/进行中/已实现/已验证/阻塞/延后`。
> 机器门已绿（`card-focus` / `card-typewriter` 各有基线，双跑 `--tol 0` 零差异）；
> **人工门未开**，所以不是 `已验证`。

## 1. 范围

| 项 | 合同要求 | 本文档怎么落 |
| --- | --- | --- |
| 专注模式 `Alt+Z` | 当前块 100%，其他块淡到 **35%**；不是 0、不是模糊、**不加遮罩** | 在 `build_job` 里按**行区间**给非当前块的每个 `TextFormat` 乘 alpha（文字自己变淡），不画任何遮罩矩形 |
| 背景/标题/元信息不变 | —— | 只动正文块，标题输入框、元信息、标签、页尾不参与 |
| 120ms 渐变 | 减少动画时立即落位 | 每帧按 `dt` 推进 `t: 0→1`，`alpha = lerp(1.0, 0.35, t)`；减少动画时 `t` 直接置 1 |
| 再按一次或 `Esc` 退出 | `Esc` 先退专注，再退页面 | 键位优先级：菜单 → 专注 → 关页面 |
| 打字机 `Alt+Shift+Z` | 光标保持视口 **42%** 高度 | 键盘输入后算「光标内容坐标 − 42% 视口高」得**绝对滚动偏移**，作为锚点交给 `scroll_to_rect` |
| 只在键盘输入时滚动 | 鼠标点击默认不强制居中 | 只有「正文收到键盘输入」才开修正窗口；`click` 不触发 |
| 180ms ease-out | 减少动画时瞬时 | 窗口覆盖 180ms（16 帧），每帧重申同一个绝对目标；egui 的缓动负责动画 |
| 不改变选区 | —— | 只动滚动偏移，不碰 `CCursorRange` |
| 两种模式可叠加 | 会话内记住，不写文档 | 两个 `bool` 放视图状态，随 `NoteView` 存活，不进 `.zmind` |

## 2. 非目标

- 不做「专注模式」下隐藏其他块（合同明确要求是淡出，不是删除）。
- 不做打字机模式的设置项「始终居中」（合同写「可在设置改为始终居中」，属设置页，本包只做默认行为）。
- 不动 `.zmind`、不加字段、不写配置文件（会话内记忆即可）。

## 3. 验收场景

| 场景 | 判据 |
| --- | --- |
| `card-focus` | 同一张卡片开/关专注各拍一张：非当前块文字平均亮度按 35% 落，**不出现整块遮罩色**（纯白背景一个字都不变） |
| `card-typewriter` | 光标停在正文可视区 **42%**：`MW_TW_PROBE` 记录的光标屏幕 y 与视口顶差 ÷ 视口高 = 0.420；两趟逐字节相同 |

## 4. 证据

### 4.1 专注模式（`card-focus`，像素级，A/B 干净）

门里的 `card-focus`（`MW_CARD_FOCUS=1`）与同场景对照组（`MW_CARD_FOCUS=0`，其余 env 完全相同）
各在**同一窗口**拍一次，基线本身连跑两趟 `--tol 0` 零差异，所以两张图的差别只来自「淡没淡」。

| 项 | 关（`MW_CARD_FOCUS=0`） | 开（`MW_CARD_FOCUS=1`） |
| --- | --- | --- |
| 尺寸 | 1620×1080 @ ppp 1.50 | 同 |
| SHA256 前 12 | `703FB926BBD4` | `D26BA0BC5B9B` |
| 稳定性 | 两趟 `--tol 0` 相同 | 两趟 `--tol 0` 相同 |
| 深色像素数（luma < 128） | 25 510 | 9 846 |
| 被淡墨迹的最低亮度 | 67 | 182 |

- **改动量**：23 591 px = 1.348%（1620×1080 全图），外接框 `x[267..667] y[339..772]`
  —— 正好是正文块所在的列，标题、元信息、标签、页尾都没被碰。
- **不加遮罩**：两张图逐像素比对，**纯白（255,255,255）像素被改动的个数 = 0**。
  「≥250 的近白」只有 492 个像素变了，最大偏差 4/255——那是文字抗锯齿的边缘，
  不是整块底色。合同禁止的「整块遮罩色」不存在。
- **35% 是算出来的，不是看出来的**：在「对照组是深色墨迹」的像素上求
  `(255 − 开) / (255 − 关)`，p10 / 中位 / p90 **全是 0.347**（同一常数 ⇒ 整体乘 alpha，
  而不是换了颜色）；被淡墨迹最低亮度 67 → 182。三处独立算法一致，35% 落地。
- 当前块不动：差异行区间为 `339–382 / 408–449 / 588–612 / 637–661 / 682–706 / 742–772`
  六段，段与段之间（当前块那几行）逐字节相同。

### 4.2 打字机模式（`card-typewriter`，量出来的 42%）

夹具：`MW_CARD_TALL=1`（20 段长文，正文 1640 CSS 高 > 视口 732）+ `MW_CARD_TYPEWRITER=1` +
输入脚本 `card-typewriter.txt`（等 6 帧，敲一个「甲」）。基线连跑两趟 `--tol 0` 零差异。

`MW_TW_PROBE` 的过程记录（节选，两趟逐字相同）：

```
[tw] caret_y=958.1 view_top=68.0 view_h=732.0 want=375.4 dy=582.7 off=0.0 target=582.7 ratio=1.216
[tw-apply] off=582.7 view_top=68.0 view_h=732.0 max=908.1 content=1640.1
[tw-idle] caret_y=375.4 view_top=68.0 view_h=732.0 want=375.4 dy=-0.0 off=582.7 target=582.7 ratio=0.420
```

| 项 | 值 | 说明 |
| --- | --- | --- |
| 视口 | 顶 68 / 高 732 CSS | 正文滚动区，`ui.clip_rect()` |
| 敲字前光标 | y = 958.1 | 在视口下方（可见区底 800） |
| 目标 | 68 + 0.42×732 = **375.4** | 合同 42% |
| 实际落点 | y = **375.4**，dy = **−0.0** | 误差小于 0.05px |
| 比例 | **0.420** | (375.4 − 68) ÷ 732 |
| 偏移 | 0 → **582.7**（上限 908.1） | 一次到位，未被夹到上限 |

A/B 像素佐证：与「不开打字机、其余 env 相同」的对照组比，1800×1200 里 **229 439 px
（10.62%）**变化，外接框 `x[360..1439] y[102..1187]` 覆盖整个正文列——整段正文确实被滚过，
而页头、顶栏、页尾不动。

#### 4.2.1 收口时发现并修掉的缺陷

拍这两张基线时发现，原来的实现**没有真的把光标放到 42%**，而且**同一份脚本两趟会拍出两种画面**：

1. **锚点里含当帧 offset ⇒ 自我反馈**。原实现用 `scroll_to_rect` 锚点 `caret − 42%视口高 + gap`，
   其中 `gap` 是「内容顶 + 当前偏移 − 视口顶」在**收尾时**量的；而 egui 在收尾时已经把这一帧的
   滚动请求施加过了，于是 `gap` 每帧都多带一份本帧位移。实测 8 帧窗口里比例在
   1.216 → 0.524 → 0.431 → −0.024 → 0.338 → 0.793 之间来回，最后 `off` 被拉回 0。
2. **绝对目标 / 相对增量混用**。改用 `scroll_with_delta` 后，`TextEdit` 自己也排了一个
   「把光标拉进视口」的请求（`scroll_to_rect(…, None)`，+181px），两者在同一帧**相加**；
   谁先谁后取决于帧时序，所以两趟拍到两种画面（一趟落在 42%，一趟被推到 17%）。

修法（`crates/mw-shell/src/note_view.rs`）：

- 目标改为**绝对偏移**：`target = 光标屏幕 y + 当前偏移 − 视口顶 − 42%视口高`
  （`typewriter_target_offset`）。当前偏移从 `ScrollArea` 上一帧存的状态里读，
  与这一帧布局用的是同一个值，所以这个 target 与滚没滚无关，是个不变量。
- 交给 `scroll_to_rect` 的锚点是 `target + 内容顶 + 内容 ui 的 item_spacing`：
  egui 的换算是 `offset = anchor − 内容顶 − spacing`（`Align::Min` 时 spacing 取负），
  补上这两项得到的就正好是 target。锚点请求会**覆盖** `TextEdit` 同一帧排的请求，不再相加。
- 修正窗口从「敲字那一帧」延到 16 帧，覆盖 180ms 缓动：窗口内每帧重申同一个绝对目标
  （幂等），把 `TextEdit` 在光标还没进视口时反复排的请求逐帧盖回来；落位后 `dy` 归零即停。
- 删掉 `tw_gap` / `tw_vmin` 两个反馈用字段。

## 5. 未做 / 风险

1. **动效只在真机可见**：`FOCUS_SECS = 0.120`、`TYPEWRITER_SECS = 0.180` 两条缓动被 golden 的
   减少动画开关（`card_reader_for` 里 `reduce_motion || harness.is_some()`）强制跳过，
   所以两张基线都是「终态」。时长的正确性只由单测与代码路径覆盖，**动效本身未人工看过**。
   这是有意为之：带缓动的 golden 永远拍不稳。
2. **动画路径靠逐帧重申目标**：非「减少动画」时，光标从视口外滚到 42% 的过程中，
   `TextEdit` 每帧都可能重排「拉进视口」的请求，所以我们每帧都盖一次。这条路径**没有实拍**
   （golden 必开减少动画）；逻辑上幂等，但真机观感要人工确认一次。
3. **修正窗口 16 帧**：打字机模式下，敲字后约 270ms 内的滚动会被拉回 42%。滚轮/拖动仍归用户，
   但「敲完立刻滚走」会被拽回来。这个折中没写进合同，属实现细节。
4. **42% 是视口高，不是行高**：矮窗口（例如 400px 高）时 42% 只剩 168px，视觉上更靠上。
   合同没规定下限，暂不特殊处理。
5. **窗口尺寸被本机屏幕夹过**：门里写 `MW_WINDOW_SIZE=1200x1000`，本机按
   `with_clamp_size_to_monitor_size` 夹成 **1200×800 CSS（1800×1200 px）**。
   基线记的是夹过之后的尺寸；换一台更高分辨率的机器重拍会得到不同尺寸的 PNG。
6. **`Alt+Z` / `Alt+Shift+Z` 的键位冲突**：`Alt+Z` 先判专注、`Alt+Shift+Z` 判打字机；两者都开时
   专注只影响其他块的 alpha，互不干扰。但**输入法开着时 Alt 组合键可能被 IME 吃掉**，
   真机 IME 核对并入 CER-07。
7. **环境残留（不是本包代码问题）**：本机 `%TEMP%` 对 cargo 拉起的测试进程拒绝写入
   （`Os { code: 5, PermissionDenied }`），跑测试前要把 `TEMP`/`TMP` 指到 `target/tmp`。
   `scripts/test.ps1` 与三个门脚本已内置这层重定向。
