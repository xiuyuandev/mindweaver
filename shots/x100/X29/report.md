# X29 · 空画布 / 空文档 / 加载 / 错误 / 只读 / 冲突状态（现状审计）

> 谁做的：只读测绘（独立 agent）。**本文件只记录现状、差距与验收草案；本轮不动 `crates/`，
> 不拍任何 golden。** 状态词只用「未开始 / 进行中 / 延后」。
> 数字与门状态只以 [`docs/STATUS.md`](../../../docs/STATUS.md) §1 为准，本文不复制场次。
> **一句话结论**：六类状态里「错误」「空文档」已经成体系且有基线；「加载」「只读」「冲突」
> 只做了一半——**尤其文档标签的只读只拦住保存、没拦住编辑**，这是本轮唯一的硬伤。

## 1. 范围与非目标

**范围**（`docs/24` §阶段 C 第 104 行：「X29 完成空画布、空文档、加载、错误、只读和冲突状态」）：

1. 六类状态在**七种表面**上的实际呈现：画布 / 大纲 / 检查器 / 起始页 / 标签栏 / 卡片页（含笔记库）/ 弹窗层；
2. 每类状态的触发方式、文案、可恢复性（用户能不能自己走出来）、出处（文件 + 那一行的字面）；
3. 特别核对两件事：**「保存失败」到底有几条路径**；**只读是否真的拦住了所有 `Command` 入口**；
4. 现成的基线/夹具盘点（哪些已经有、哪些零证据）。

**非目标（本轮明确不做）**：

- 不改代码、不改 `docs/`、不拍图、不重拍基线、不登记进 `scripts/`；
- 不裁决产品口径（只读要不要禁编辑、冲突要不要主动提醒）——写进 §3 由用户/Lead 拍板；
- 不碰 X27（交互状态表，已完成悬停/选中/禁用那一层）与 X28（折叠圆点）；
- 不评估实机 DPI/字体（欠账口径同前一包）。

**X29 状态：`进行中`（本文件只做了文档与现状审计）。** §3 各条的状态见该节表格。

**`FormatError` 的六类原因**（全部经 E1 弹窗展示，字面就是用户看到的）：
`读写文件失败：{0}` / `压缩包损坏：{0}` / `文件内容解析失败：{0}` /
`此文件由更新版本的织思创建（格式版本 {0}），请升级后再打开` / `无效的 .zmind 文件：{0}` / `文档结构损坏：{0}`
（`mw-format/src/lib.rs:36-49`）。

**「保存失败」到底有几条路径（本轮要核的那一条）**：

- **文案出口 5 个**：E2 手动保存、E3 自动保存恢复点、E4 卡片笔记、E5 导出、E6 命令失败（不是保存，但同属失败反馈）；
  另有一次性的 `恢复失败：{e}`（恢复点装载失败，`app_methods_1.rs:2689`）。
- **写盘入口 4 条**：① `pump_save`（`Ctrl+S` / 芯片点击 / 关闭确认 / 冲突「覆盖保存」共用）；
  ② `action_save_as` 走 `canvas.save_to`（**另存为失败直接 toast 裸错误 `{e}`，没有「保存失败：」前缀**——与 E2 不一致，`app_methods_2.rs:3039` `self.set_toast(e.clone(), true);`）；
  ③ 自动保存恢复点（`autosave.rs` 后台线程 + 退避）；④ 卡片笔记（`NoteStore::upsert` 去抖 / 卡片页 flush）。
- 结论：**不是「一条路径」，是「四条写盘入口 / 五个文案出口」**，而且 E2 与「另存为」的措辞不一致（见 G-8）。

**判读（本轮硬伤）**：**只读在卡片页是「真只读」，在文档标签是「只不能存」。**

所以「外部改过但你没保存」这段时间里，用户看到的是旧内容、且没有任何提示。

## 3. 差距清单（严重度 / 用户能不能自己走出来）

是「只读就真禁写」，还是「只读 = 保护磁盘、允许本地改、明确告诉用户另存为」。
G-5 的文案也要一句口径（空画布要不要给引导语）。其余是可自行收口的工程项。

### 4.3 重试路径断言

| 状态 | 路径 | 期望 |
| --- | --- | --- |
| 打开失败 | 「重试」→ 同一路径重新走两段式 | 轨迹 `open_start` → `open_fail`（仍失败）或 `open_ok`（修好了）；不丢弹窗上下文 |
| 手动保存失败 | 点状态芯片 → 再 `Ctrl+S` | 轨迹 `save_start` → `save_fail` → `save_start` → `save_ok`；失败后编辑一次 → 芯片回 `未保存` |
| 自动保存失败 | 连续失败 5 次 | 轨迹 `autosave_fail … attempts=1..5`，第 5 次后不再自增；用户再编辑 → `attempts` 归 1 |
| 卡片保存失败 | 点「重试」 | 草稿仍在（正文不变），成功后顶栏 `已保存` |
| 冲突 | 覆盖保存 / 重新加载 | 覆盖后 `save_ok` + toast `已覆盖磁盘上的版本`；重载先过脏检查（不静默丢改动） |
| 只读 | 另存为 | 成功后可写（新路径重新 `arm` 锁），旧只读标签保留 |

## 6. 未做 / 风险

- **本轮零代码、零基线、零 `scripts/` 改动**：所有结论来自 `grep`/`read`（`crates/` 有并行会话，只读测绘）。
- **G-1 是硬伤，且它的修法有两种方向**（禁写 vs 只保护磁盘），必须先拍板；在拍板前谁都不该动
  `active_read_only()` 的消费者，否则会把「另存为」的活路一起堵死。
- **只读的锁语义有一个已确认的窄口（跨进程）**：协作锁文件名按**原样路径**拼（`file_guard.rs` `lock_path`），
  不做 `canonicalize`；两个进程用 `C:/a/b.zmind` 与 `c:/a/./b.zmind` 打开同一文件时，两把 `.lock` 互不可见，
  双方都拿到可写锁。保存时的指纹比对能兜住一部分（`mw-format` 的 `same_path` 会 `canonicalize`），
  但「同时编辑」这段窗口没有任何拦截。**同一进程内**的双路径打开已被 `tab_index_of_path` 的
  `canonicalize` 挡住（`app_methods_1.rs:2443-2457`），不产生第二个标签。
- **恢复点/历史/库损坏三条只做了`读`的一侧**：`recovery_prompt` 与库损坏行内条都有实现，
  本轮只确认了文案与位置，没有逐条核对解构后的动作链（`docs/28` §7.7 的「重试」是否真重试库扫描）。
- **未量化**：加载耗时分档（小文档 / 20k / PDF 导出）没有本轮测量，`文档` 侧只记录了「可取消/不可取消」。
- **欠账照旧**：`已验证` 仍欠实机微软拼音 + 系统 DPI；本包任何「文案过门」都不替代实机目检。
