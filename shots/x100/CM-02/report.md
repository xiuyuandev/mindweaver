## 2. 范围（本包）

1. `LayoutKind::ConceptMap`（`from_kind` / `as_str`），概念图不再冒充 `Mindmap`。
2. 概念节点样式：浅色面板 + `ui.border` 1px 描边 + 圆角 + 14/20 居中；主概念 15/22 600 + 8% 强调底。
3. 盒宽 = 文本 + 28，夹在 96–240；高 36（双行 52）。
4. 关系线：直线 + 6×4 箭头；链接短语仍用既有胶囊，线在标签处断开。
5. 相机 `fit` 用全部节点包围盒（含浮动概念）。
6. 场景：`cm-default`（宽）、`cm-narrow`（640×460）。

## 3. 非目标

- 不做连线拖拽创建与短语就地编辑（CM-03）。
- 不做整理布局与重叠提示（CM-04）。
- 不做概念 ↔ 卡片联动（CM-06）、大纲视图与导出（CM-07）。
- 不做曲线/跳线；概念图**只走直线**（§5.4）。

### 4.2 为什么样式覆盖放在级联之后

`resolve_all` 的级联是「一级主题实色卡 → 二三级淡染色」的思维导图逻辑，
概念图在这套规则下必然变成 6 块深色实底（旧现状 V1）。放在级联之后覆盖，
既能一次覆盖所有概念（`root_id` 与浮动概念的级联起点不同），又不会把
「用户在检查器里选了填充色」也一起盖掉——`apply_concept_defaults` 里每项都先看
`Node.style` 有没有显式值。

## 6. 未做 / 偏差

1. **圆角是 12 不是 8**：`Shape::Rounded` 用的是全局 `NODE_RADIUS = design::radius::MD = 12`，
   `ResolvedStyle` 没有 `radius` 字段。要精确到 8 需要给 `Shape` 加带参变体或给样式加字段，
   属于「改数据结构」的范畴，本轮不动；视觉上 12 与 8 在 36px 高的盒子上差异很小。
2. **箭头是 8.4×9（世界单位）不是 6×4 CSS**：箭头几何在 `build_scene` 里按世界单位写死，
   要精确到 CSS 尺寸需要把箭头三角挪到渲染层按 `cam.css_to_world` 换算。记为偏差。
3. **悬停/选中态的 1px/1.5px 描边**用的是画布既有选中环，未按概念图单独调；
   `cm-node-edit` / `cm-crosslink` 等交互场景随 CM-03/CM-05 一起验。
4. **短语胶囊 20px 高、线断 8px** 沿用既有 `REL_LABEL_H`，未单独为概念图调断口宽度。
5. **相机 fit 只保证「用全部节点包围盒」**（已验），但不含「概念图专用留白」。
