# CER-13 · 卡片页骨架与单一表面

- 批次：B2-B（CER-13–CER-21），门 G-B2-2
- 状态：**已实现**（第 58 轮补完版心像素断言与四主题证据；人工门 G-B2-2 未过，不记 `已验证`）
- 依赖：CER-02、CER-03（均已 `已实现`）
- 合同：`docs/29` §7 CER-13；设计以 `docs/28` §6 为准

## 1. 范围

把卡片页从「顶栏 + 右目录 + 三套按钮」改成 Typora 式**单一写作表面**：

| # | 交付 | 现状（实测） | 目标 |
| --- | --- | --- | --- |
| 1 | 顶栏 40px | `note_view.rs:304` 起的顶栏含返回/标题/保存态/关闭，高度由内容撑开 | 固定 40px：返回、来源面包屑、字数、保存状态、更多 |
| 2 | 去掉顶栏重复标题 | 顶栏里有一份可编辑标题 | 顶栏不出现标题；标题就是正文 `# H1` |
| 3 | 去掉常驻右目录 | `note_view.rs:531` 起：`total >= 1040` 时右栏 204px + gap 26 | 右栏删除；目录能力改为命令/浮层（非本包） |
| 4 | 版心 | `article = (total - toc_w - gap - 96).clamp(320, 720)` | 720（宽窗）/ 640（窄窗），上 48 / 下 96 |
| 5 | 三套按钮合一 | 顶栏 + 页脚各有一套动作 | 只留顶栏一处（更多菜单里收） |

## 2. 非目标

- 不做 Markdown 块排版 v2（CER-15）。
- 不做语法揭示/块标记显隐（CER-16）。
- 不扩数据结构（`.zmind`、`NoteCard` 字段不动）。
- 不做目录浮层（延到 B2-D 或 Stage G，视 G-B2-2 判词）。

## 3. 验收场景与预计证据

| 场景 | 证据 |
| --- | --- |
| `card-default` | golden：版心 720、上 48/下 96、顶栏 40px、无标题重复、无右栏 |
| `card-empty` | golden：空卡片只有光标占位与提示，不出现按钮墙 |
| 版心标尺 | 从 golden 量顶栏高度与首行基线（像素断言写进报告） |
| 四主题 | 四个主题各拍一张，确认版心不随主题变 |
| 窄窗 | 宽 < 1000 时版心退到 640 且不出现横向滚动 |

## 4. 风险

1. `show()` 单函数 587 行（`note_view.rs:206`–793），改动容易碰坏 IME/光标保持；先做骨架、留旧路径可回退。
2. 去掉右目录后 `toc_click`/`heading` 相关状态与测试会失效，需要同步删除或标记 deprecated。
3. 顶栏高度变成常量后，滚动区起点随之变化，所有依赖 `rect` 的命中测试要复查。

### 5.3 像素测量

新写 `scripts/measure3.ps1`（System.Drawing 读像素，只认亮度 < 150 的暗墨迹，排除窗口衬边与浅灰分隔线）：

```
dark_bbox: x=36..1574 w=1539 y=40..801
logical: left=24.0 width=1026.0 top=26.7
```

读法：左边界 24 逻辑像素 = 顶栏 `add_space(22)` + 字形左衬；整页墨迹宽 1026 = 顶栏两端文字（返回 … 字数/保存态）撑满，不是版心宽度——版心宽度要用**正文区**（y > 110 逻辑）单独测，这条还没做。

### 5.4 版心像素级断言（第 58 轮补）

§5.3 那条「版心宽度未像素级断言」的缺口，用**长段落**补上了：短段落量不出 720，只有长到必须换行的段落，
换行线才落在版心右边界上。

夹具 `MW_CARD_LONG=1`：正文一段无空格长中文（156 字 × 6 遍），CJK 断行必然触发。
两个场景：`card-long`（默认窗 1080）、`card-narrow`（`MW_WINDOW_SIZE=900x700`）。

#### 实测（ppp 1.5，墨迹阈值：与背景主色差 > 90）

| 场景 | 窗口 | 版心左（逻辑） | 换行右（逻辑） | 实测宽 | 代码期望 | 行数 |
| --- | --- | --- | --- | --- | --- | --- |
| `card-long` | 1080×720 | **180.0** | **890.7–892.7** | **710.7–712.7** | 720，左 `(1080-720)/2 = 180` | 7 行正文 + 标题 |
| `card-narrow` | 900×700 | **130.0** | **764.0–764.7** | **633.3–634.7** | 640，左 `(900-640)/2 = 130` | 8 行正文 + 标题 |

读法：左边界与 `(窗口宽 − 版心) / 2` **精确相等**（180.0 / 130.0），说明版心是居中的；
实测宽比 720/640 少 5.3–9.3 逻辑像素，那是最后一个字形的右侧留白（墨迹右缘不等于排版右缘），不是版心少了。

#### 四主题几何不变

同一份 `card-long` 在 snow / ink / mist / sand 四个主题下各拍一张，正文区（`y400..900`）量出来**完全相同**：
`left 180.0 / right 892.7 / width 712.7 / 7 行`。四张的背景色分别是 `#20242a`（ink）与 `#ffffff`（其余三个），
墨迹用「与背景主色差 > 90」判定，所以深色主题不会因为阈值方向把字判丢。

## 6 附带修复：两处让 golden 假红的基建缺陷（第 58 轮）

这一轮把 `card-default` / `card-empty` / `card-long` / `card-narrow` 登记进门之后，第一次跑 stage-b 门是**红的**，
红的不是卡片页，而是 `library` 三档基线 + 全量测试 `exit 101`。两个都是环境/夹具缺陷，不是本轮改坏的。

### 6.1 stage-b 门没有把 TEMP 指到仓库内

`scripts/x100-stage-b-gate.ps1` 跑全量测试时，`mw-format` 有 8 个用例在 `crates/mw-format/src/lib.rs` 的 `temp_path()`
（那行是 `std::fs::create_dir_all(&dir).unwrap()`）panic：`Os { code: 5, kind: PermissionDenied }`。

`scripts/ci.ps1` 与 `scripts/x100-stage-cm-gate.ps1` 早就为同一问题加了 TEMP 重定向（注释写得很清楚：受限令牌下系统 Temp 可能不可写），
**stage-b 门漏了这一段**——同一个环境问题换一个脚本再犯一次。已补齐（三处逻辑一致）。

### 6.2 笔记库夹具把卡片写进了不可写的 Temp，失败还被吞掉

`crates/mw-shell/src/demo_notes.rs`（`MW_LIBRARY_DEMO`）原本把示例库写到 `std::env::temp_dir()`，
并且 `let _ = store.upsert(&card);` **忽略写盘错误**。本机受限令牌下 `std::env::temp_dir()` 返回的用户 Temp 是拒写的，
于是 4 张示例卡一张也没落盘 → 页面画**空态**（一颗强调色按钮）→ `library` 三档基线全红（4.306% / 7.992% / 12.191%）。

这一条最危险的地方不是红，而是**静默**：golden 只报「和基线不一样」，没人知道是夹具没写进去。
现在：

- 落地目录改成仓库内 `target/tmp/mw-library-demo-v2`（可用 `MW_DEMO_LIB` 覆盖），不再赌用户 Temp 的权限；
- 每次**先删再种**，固定 `demo-01..04` 四个 id（随机 id 会让「按时间倒序、同时间按 id」的排序每次不同）；
- 写盘失败直接 panic，种完再 `assert_eq!` 张数。**夹具不确定就必须炸，不能悄悄画另一页。**

修完重拍三档，连跑两次零差异：`352E863E8771`（1.0）/ `561FA6CEA15B`（1.5）/ `2A3F134B8D5B`（2.0）。
1.5 那张量出来正文墨迹 55 793 px、18 条文字带，与旧基线同构（4 张卡的列表），说明库页本身没坏，坏的是夹具。
