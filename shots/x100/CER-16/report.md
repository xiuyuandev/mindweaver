# CER-16 · 单一表面编辑引擎与语法揭示

> 设计合同：`docs/28` §6.3；执行合同：`docs/29` §7 CER-16（B2-B 生死线）。
> 顺序：§1–§4 片段级标记揭示（第一刀）、§6–§9 行尾回车与列表（后半第一刀）、
> §10 即时转换 + 一次撤销（后半第二刀，2026-10-28 深夜收口）。
> **仍未做**：实机微软拼音组合态核对（与 CER-17 共用 IME 门）。

## 1. 范围

- 光标在某个行内片段（`**粗体**`、`` `行内码` ``、`~~删除~~`、`[文字](链接)`、`[[双链]]`、`![图](url)`）内时，
  **只露出该片段的标记**，其余片段的标记收起；光标离开片段立即收起。
- 块级标记（`#`/`##`/`>`/`-`/`1.`）仍按「光标所在行」整行露出（§6.3 允许，且不影响光标映射）。
- 正文 buffer **一个字节都不改**：`markdown_job_preserves_every_byte` 继续钉着这条不变量。

## 2. 非目标

- 不做即时转换（`#` + 空格 → 标题），那是本轮之后的一半（CER-16 剩余 + CER-17）。
- 不拆多控件、不加预览分栏（合同禁止）。
- 不改 `.zmind`、不加字段。

## 3. 实现

1. `MarkerMode::OnlyLine(Option<usize>)` → `OnlyLine(Option<(usize, usize)>)`：带上**行内字节列**。
   光标位置原本只有「行号」，无法判断落在哪个片段。
2. `col_in_line(text, char_idx)`：字符索引 → 行内字节列（中文正文里字符数与字节数不同，不换算会错一段）。
3. `inline_spans(s, caret)`：宽松预扫一遍，返回**包含光标**的片段字节跨度；
   解析比样式那一遍宽松（判错只影响显不显示，不改字节）。
4. `push_inline` 的 `mark` 闭包改成位置化 `mark(st, at)`：`at` 落在光标片段内才可见。
   闭包原本与位置无关（`hide` 一个布尔决定整行），改成位置化之后，同一个 `push_inline`
   里不同片段的标记可以各自决定显隐。
5. 状态：`self.active_line: Option<usize>` → `self.active: Option<(usize, usize)>`；
   每帧从 `TextEdit` 的 `cursor_range.primary.index`（字符索引）换算出「行号 + 行内字节列」。
6. 块级标记（`#`/`>`/`-`/`1.`/围栏）仍由 `hide` 决定，行为与 CER-15 完全一致：
   只要光标在这一行就整行露出——合同允许，且不改动任何字节。

### 3.1 为什么片段扫描是第二遍解析

样式那一遍要「边扫边定样式」（`flags` 是状态机），而「光标在哪一段」需要**先知道整段的边界**。
硬把它塞进同一遍会让样式机变成两遍扫描的回溯机；独立一遍 `inline_spans` 更小、更好测。
两遍规则若有分歧，症状只是「标记该露没露」，不会改变文本、光标或行高——
`markdown_job_preserves_every_byte` 把这条底线钉住。

### 5.1.1 写测试时抓到的一个真 bug

`![示意](a.png)` 的片段跨度原本从 `[` 起算（`inline_spans` 没有 `!` 分支），
`![` 里的 `!` 落在跨度之外，于是**光标停在图片说明里时那个 `!` 永远不会露出来**——
用户会看到 `[示意]` 的位置出现一个孤零零的 `!`（或反之）。补 `!` 分支后跨度从 `!` 起算。
这条是写第二条单测时才发现的：手工点进去几乎不可能注意到少了一个 `!`。

### 5.2 门里的一张老场景：`outline-20k-deep` 的滚动没落定（已修）

第 62 轮门第一遍，`outline-20k-deep` 报 **11424 px / 0.496%**，包围盒 `x[595..709] y[100..1147]`（一条竖到底的窄条）；

排查顺序与结论：

1. 单独复现该场景（直接跑二进制，warmup 10/10/16/16）→ 4 次全部逐位相同；
2. 换成门里一模一样的命令与环境（`cargo golden` + `APPDATA` 指向 `target/ci-appdata/gate-outline-20k-deep`，冷/热两种）→ 也全部相同；
3. 所以不是基线错、不是 appdata、也不是本轮改动。差别只剩**负载**：门是串行跑 61 场、每场前后都有 cargo 动作，

## 6. 后半第一刀：行尾回车的列表行为（`已实现`）

> 状态口径：代码、单测、两张像素实拍、门与 CI 都已落，所以记 `已实现`；
> **仍未过 IME 门**（`Enter` 归属输入法只做了「有 IME 事件就跳过」），按 `docs/29` 第 242 行它与 CER-17 共用一道门，
> 那道门过了才谈 `已验证`。

### 6.1 为什么先做这条

缓冲区存的就是 Markdown 源文，所以「输入 `#` + 空格变标题」这件事本身是**免费的**——
用户敲出来的 `# ` 就是标题的源文。真正缺的是 `docs/28` §6.8 的两条键盘行为：
**空列表项回车退出列表**、**有内容回车续写同型前缀**。这两条现在会留下脏前缀，是明显的体验缺口。

### 6.2 实现

- `list_prefix(line)`：认 `- [ ] ` / `- [x] ` / `- [X] `（任务）、`- ` / `* ` / `+ `（无序）、`1. ` 起的（有序），
  返回（前缀字符数，续写前缀，序号）。**无序符号续写时统一成 `- `**，不在同一份列表里换符号。
- `enter_edit(text, caret)`：只接管「光标在行尾」的情况；空项删前缀、非空项插 `\n` + 前缀（有序 +1）。
  标题、段落一律返回 `None`——它们本来就不该接管（标题换行自然不带 `##`）。
- 接线在正文 `TextEdit` **之前**：先**探测**（`key_pressed(Enter)` 且无修饰键）→ 算出结果 → 
  再 `consume_key` 把它吃掉。顺序反了会让普通段落回车失灵（吃掉了却不做事）。
- **IME 优先**：这一帧只要出现 `Event::Ime(_)` 就整段跳过，`Enter` 完全留给输入法。
  真正的合判仍要等 CER-17（`docs/29` 第 242 行要求两包共用一道 IME 门）。
- 光标写回用 `TextEditState::load → set_char_range(CCursorRange::one(CCursor::new(at))) → store`，
  与勾选框那条既有路径同一套写法。

### 6.3 单测（9 条）

空无序项退出 / 空有序项退出 / 空任务项退出 / 有内容无序项续写 / `* ` 归一成 `- ` / `9. ` → `10. ` /

## 7. IME：组合串原地长、确认后原地换（`已实现`，机器半边）

`docs/29` 把 `card-ime` 写在 CER-16 的验收里，CER-17 又要「输入类必须覆盖 IME」。这一节补的就是它：
**组合串（preedit）不参与排版**，确认（commit）后原地替换，前后两段的 y 一个像素都不动。

### 7.1 场景

夹具 `MW_CARD_IME`：标题「输入法不许打架」，正文两段（中间一个空行），光标用 `click 700 244` + `key ctrl+End` 落到文末。
脚本只差最后一步：

| 场景 | 脚本尾 | 应当看到 |
| --- | --- | --- |
| `card-ime-preedit` | `ime preedit 你好世界` | 组合串长在光标处，**带下划线** |
| `card-ime-commit` | `ime preedit 你好世界` → `ime commit 你好世界` | 下划线消失，字原地不动 |

### 7.2 量出来的三件事

1. **段落位置逐像素相同**：两张图的正文行段都是 `(226,241) (258,289) (366,377) (389,400)` —— 组合串没有把下面的段落推走。
2. **两张图只差 1792 px**，bbox `(652,260)-(715,287)`，全部落在光标右侧那一小段里；页面别处零差异。
3. **下划线只出现在组合态**：阈值 170 下逐行扫，`preedit` 在 `y=271` 有一条 `x 654..695` 的连续横线，`commit` 同一条带上没有。

这三条合起来就是「输入法不打架」在像素上的判据：组合态**只加装饰**（下划线），不加行、不换行、不推移。

### 7.3 边界（别把它当成人机 IME 验收）

- 这是 `MW_GOLDEN_INPUT` 造的 `Event::Ime` 序列，**不是真输入法**。真机 MS-IME / 搜狗的组合窗位置、候选条遮挡、
  全半角切换这些，仍要 CER-07 那套人工核对，本轮不记 `已验证`。
- 组合态下 `Enter` 归属输入法这条，落成了「这一帧只要有 `Ime` 事件就跳过回车接管」（§6.2），
  这里只有构造事件覆盖，没有真机复核。

## 8. 粘贴：Markdown 自动保留结构，纯文本按当前块补前缀（`已实现`）

### 8.1 为什么这里只用写一半

缓冲里存的就是 Markdown 源文，所以「粘 Markdown 保留结构」**不需要任何代码**——
粘进来的是源文，排版层照着排。真正缺的是 `docs/29` CER-17 的后半句「粘贴纯文本按当前块处理」：
把两行纯文本粘进列表项，第二行如果裸着插进去，就成了「列表项 + 断行」，结构直接坏掉。

### 8.2 实现

`fn paste_list(text, caret, clip) -> Option<(String, usize)>`：

- 剪贴板里**没有换行**就返回 `None` —— 单行粘贴交给 `TextEdit` 自己插，别抢；
- 光标所在行**不是列表项**也返回 `None` —— 段落里粘贴保持原样；
- 是列表项时，第一行原样，后面每个非空行按同型前缀补齐（有序列表**逐行递增**，任务项恒为未勾选 `- [ ] `），空行保持为空；
- 接线与回车同一条纪律：先算出结果，**再把那个 `Event::Paste` 从队列里摘掉**自己插，光标写回。

### 8.3 单测（6 条，`note_view` 36 → 42）

无序补前缀、段落不接管、单行不接管、有序逐行递增、任务项恒未勾选、空行保持空行。

### 8.4 实拍：短横在不在（同一判据的第二次使用）

夹具 `MW_CARD_ENTER`（两行清单），光标到第二项行尾，粘 `乙\n丙`：

| 场景 | 粘出的续行首簇 | 读法 |
| --- | --- | --- |
| `card-paste-list` | `(543,547) (553,568)` | 543-547 是 **5px 的 `-`**，553 起才是「丙」→ 前缀补上了 |
| `card-paste-plain`（对照，不进基线） | `(541,556)` | 一簇 15px 宽、**没有短横** → 段落里粘贴确实没被接管 |

`card-paste-plain` 用的是没有列表的 `MW_CARD_IME` 夹具，避免夹具自带的 `- 第二项` 混进判据
（第一版对照用的是有列表的夹具，量出来那条短横是夹具自己的，不作数，已重拍）。

### 8.5 边界

- 只处理**纯文本多行**这一种。富文本（HTML/RTF）剪贴板格式没做，egui 也不给；
- 段首编号（`1. `）之后接有序列表的连续性没做「重排」，只是逐行 +1；
- 「一次撤销」这条仍未专门验（与 §6.6 同一笔账）。

## 9. 一次撤销：带外改动也要能被 `Ctrl+Z` 一步撤回（`已实现`）

### 9.1 为什么这里会翻车

回车接管与列表粘贴都是「绕开 `TextEdit` 直接改缓冲区」。`TextEdit` 内置的 undoer 只认它自己
经手的那次编辑，带外改动对它来说是「天降文本」——按 `Ctrl+Z` 会退到一个更早的快照，
既不是改前、也不是改后。

### 9.2 先试错，再定方案（都记下来）

1. **第一版**：给 `TextEditState::undoer()` 塞一枚还原点 `add_undo((光标, 改前文本))`。
   结果是 `Ctrl+Z` **退过头**：文字回来了，但光标落在别处、标记揭示状态跟着变，整行正文右移 13px
   （实测两张图差 718 px，包围盒 `(539,219)-(612,277)`）。原因是 `add_undo` 只放点，
   egui 下一帧仍按自己的 `flux` / `stable_time` 规则再补一个点，撤销就多退一步。
2. **定案**：自己管**一步**。带外改动时把「改前文本 + 改前光标 + 改后文本」记进 `auto_undo`，
   `Ctrl+Z` 优先还原它；正文一旦被别处改过（`auto_undo.2 != draft_body`）就作废；还原一次即清空，
   再按一次不再来回跳。不接管时（`auto_undo` 为空）照旧把 `Ctrl+Z` 留给 `TextEdit`。

### 9.3 判据：撤销 == 没发生过

两张图、同一落点：`card-paste-none` 什么都不粘，`card-paste-undo` 粘两行再按一次 `Ctrl+Z`。

- 逐像素比较：**diff_px 0**（1800×1200 全图，最大差 0）；
- 两张基线**哈希相同**：`C32274AB09AD`（66115 B）。

这条不变量已经写进门里：两张都在 stage-b 矩阵中。撤销一旦坏掉，`card-paste-undo` 必然漂。

### 9.4 单测（1 条，`note_view` 42 → 43）

`store_after_edit_writes_caret_and_keeps_one_step_undo`：光标写到位、撤销槽记的是「改前」。
`egui::Context::default()` 不建窗口也能造，所以这条是纯函数级验证。

### 9.5 边界

- 只保**一步**。连续两次带外改动，只留最后一次的还原点（`docs/29` CER-17 要的就是「一次撤销」）；
- 撤销槽只在回车接管 / 列表粘贴后有效，用户接着打字就作废（丢弃而不是错位更重要）；
- `Ctrl+Shift+Z`（重做）没有为王；重做交给 `TextEdit` 自己的历史。

### 9.6 踩坑：PowerShell 脚本必须 UTF-8 **with BOM**

用 Node 的 `writeFileSync(..., "utf8")` 改 `scripts/x100-stage-b-gate.ps1` 会写成**无 BOM**，
`powershell.exe`（5.1）按 ANSI 读，中文注释变成乱码字节，解析器在半路报
`Unexpected token )`——报的行号还落在**没问题的那几行**上，很容易误判成数组写错。

处置：该脚本一律 UTF-8 + BOM + CRLF；复跑前用
`[System.Management.Automation.Language.Parser]::ParseFile(...)` 先过一遍解析。

## 10. 后半第二刀：即时转换 + 一次撤销（`已实现`）

> 状态口径：代码、单测、两张像素实拍、`MW_TRACE` 缓冲区区证据都在；
> **实机 IME 组合态仍未人工核对**（与 CER-17 共用那道门），所以不记 `已验证`。

### 10.1 「即时转换」在这套实现里到底缺什么

正文缓冲区存的就是 Markdown 源文，所以「敲下 `# ` 就变标题」**渲染层当场就做了**：
`# ` 是标题的源文，`markdown_job` 每帧按行首前缀决定字号与行高。
真正缺的是配套的**一次撤销**：`# ` 是两个字符，让 egui 自己撤销会先退那个空格，
留下一个光秃秃的 `#`——用户看到的是「撤了一半」。

### 10.2 实现

- `block_marker_len(line)`：认 `# ` / `## ` / `### ` / `#### ` / `> ` / `- ` / `* ` / `+ ` /
  `1. `（1–3 位数字）。只认**整行恰好只剩标记**的情况，`## 标题` 不算「刚转换」。
- `marker_undo_edit(text, caret)`：光标在该行行尾、整行只有标记时，返回「把这枚标记整段去掉」
  的文本与光标（行首）。
- `marker_undo_step(before, caret_before, after)`：只有「本帧比上一帧**多插了一格空格**，
  且这格空格让本行成了标记」才成立——粘贴、IME 上屏、一次插多字符都不算。
- 接线：`TextEdit` 之前拍下 `body_before` / `caret_before`，`TextEdit` 之后若
  `marker_undo_step` 成立，就把它并进已有的 `auto_undo` 槽（CER-17 的「一次撤销」同一条通道）。
  `Ctrl+Z` 走原路径：文本回到标记之前、光标回到行首。

### 10.3 证据

**缓冲区（`MW_TRACE` 逐次正文）**——脚本在第二段行尾回车，然后逐格敲 `- `、`1. `、`## `：

```
event card_body "第一段\n\n第二段\n- 列表项\n1. \n\n第三段\n"
event card_body "第一段\n\n第二段\n- 列表项\n1. 有序项\n\n第三段\n"
event card_body "第一段\n\n第二段\n- 列表项\n1. 有序项\n##\n\n第三段\n"
event card_body "第一段\n\n第二段\n- 列表项\n1. 有序项\n## \n\n第三段\n"
event card_body "第一段\n\n第二段\n- 列表项\n1. 有序项\n## 即时标题\n\n第三段\n"
```

撤销场景（同一动作 + 一次 `Ctrl+Z`）最后两行：

```
event card_body "第一段\n\n第二段\n## \n\n第三段\n"
→ Ctrl+Z →  "第一段\n\n第二段\n\n\n第三段\n"
```

**像素**：

| 场景 | 与「只回车」对照 | 结论 |
| --- | --- | --- |
| `card-instant` | 6 921 px（0.32%），外接框 `x[539..1725] y[26..529]` | 三行标记确实成块；顶部那点是保存芯片由「已保存」变「未保存」 |
| `card-instant-undo` | **0 px，逐字节相同**（`64ea1c60c621`） | 一次 `Ctrl+Z` 完全回到「标记之前」，没有残留 `#` |

两张基线各连跑两趟 `--tol 0` 零差异；已登记进 `scripts/x100-stage-b-gate.ps1`。

### 10.4 单测（5 条新增，`note_view` 43 → 48）

### 10.5 未做 / 风险

1. **归一化没做**：`* ` / `+ ` 目前原样留在缓冲里（续写时才归一成 `- `）；`1) ` 不认作有序标记。
   合同没要求，但若将来做「敲下就统一成 `- `」，必须照样走一步撤销。
2. **实机 IME 未核对**：组合态下空格属于输入法，`marker_undo_step` 只在 `Event::Text`
   落地后才成立，理论上不会抢；但这条与 CER-17 共用同一道 IME 门，没有真人核对前不记 `已验证`。
3. **`card-instant-undo` 与 `card-instant-enter` 的相等性**依赖「只回车」这一个中间态；
   若将来 Enter 行为改变（例如列表续写的间距调整），两张图要一起重拍。
4. **脚本新增 `\s` 转义**（`golden_input.rs`）：`text \s` 发一格空格。原有脚本没有反斜杠，
   不受影响；`\n` / `\t` 与 `paste` 保持同一套写法。
