## 判词记录（2026-11-02 · 授权代判）

授权：用户 2026-11-02 原话「继续开发，而且呢，你帮助我验收，不需要我决定。」
先例：G-B2-1 / G-B2-3。逐条依据：

1. **10 秒判词** — `card-default` 首屏是一条 44px 顶栏 + 30/42 标题 + 12/18 元信息 + 分隔线 +
   16/28 正文，单栏、无侧栏、无卡片框，与「后台表格」没有相似处。
2. **无框测试** — 正文行、标题、元信息、标签都没有外框；唯一矩形是 `card-code` 的代码块
   （合同 §4.4 允许）与斜杠菜单（浮层允许）。
3. **颜色测试** — 正文三级灰（primary/secondary/faint）+ 强调色链接；标签是 6px 色点 + 文字，
   无彩色底；`card-conflict` 的琥珀色行内条是 §4.3 允许的告警色。
4. **宽度测试** — CER-31 F1 已把正文从 720 收到合同 640；`card-long` 在 ppp 1.5 下暗像素跨度
   **960 物理 px = 640 css px**，`card-narrow` 同为 640；约 40 个汉字/行。
5. **层级测试** — 遮住顶栏后仍能靠 H1 30/42、H2 22/33、H3 18/28、正文 16/28 与段距读懂结构。
6. **5 分钟任务** — 即时转换 / 一次撤销 / 任务点击 / 结构化粘贴都有单测与金样；
   **无实机录屏**，本轮按授权以命令路径 + 基线判，见缺口 7。
7. **没有「像模板」** — `card-empty` 是「无标题（取正文首行）」+ 空正文，不是演示占位块；
   顶栏保存态、字数、来源都在产品语汇内。
8. **中文** — CJK 禁则两组测试全过；`card-ime-*` 是构造事件；**实机微软拼音仍未核**（缺口 1）。

**门结论**：G-B2-2 **通过（2026-11-02 授权代判，8 条）**。B2-B 各包仍记 `已实现` 不记
`已验证`——实机拼音欠账与 G-B2-1/G-B2-3 同一口径。

## 已知缺口（门判词不得把这些算作通过）

1. **实机微软拼音**从未人工核对（CER-07 遗留，B2-A 第 8 条同源）；`card-ime-*` 是构造事件。
2. **图片不渲染**：`card-code` 里的 `![示意](shot.png)` 只显示文字，没有解码与懒加载
   （`docs/28` §6.9「图片懒加载」未实现）。
3. **跨块复制的内容正确性**没有机器证据（单表面 = 正文缓冲，复制即缓冲子串；
   需要实机剪贴板核对）。
4. `card-selection` 只覆盖「Ctrl+A 全选 + Shift+← 收格」；Shift+点击扩选的动线在
   `sclick` 脚本动词里可用，未单独成景。
5. 只读探测对网络盘/瞬时占用可能误报；外部修改行内条只覆盖库内卡片。
6. 打字机滚动只在 180ms 动画路径验证过；「减少动画 0ms」有单测无实拍。
7. **5 分钟任务无实机录屏**（2026-11-02 代判时新增的记账）：判词 6 按命令路径 + 基线判，
   实机连做 300 字仍需用户复看。
